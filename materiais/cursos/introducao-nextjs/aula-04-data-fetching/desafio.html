Desafio · Aula 04 · entrega até 09/09, antes da aula 05

O dado sai do arquivo 🌐

A aula 03 deu memória às telas de vocês, e elas passaram a responder. Mas o que elas mostram ainda é um array escrito à mão dentro do projeto. Esta semana o Leque de Vagas passa a buscar o que mostra — e com isso ganha as três coisas que o Checkpoint 1 cobra: cache, revalidação e uma espera bem cuidada.

💼

O que muda de verdade nesta semana

Nenhuma tela nova. Nenhuma frente troca de dono. O que muda é de onde vem o dado que cada tela já mostra — e cada frente encontra pelo caminho uma parte diferente da aula de hoje.

Se você não leu o briefing do Leque de Vagas, leia antes: o Checkpoint 1, na aula 08, pede "vagas vindas de uma fonte externa, com cache e revalidação". É esta semana que essa frase começa a existir no código de vocês.

Quatro frentes, quatro pedaços da aula 👥
Frente 1 · Vaga Publica o JSON, escreve o lib/api.ts que a equipe inteira vai usar, e pré-gera as páginas de detalhe. fetch · generateStaticParams
Frente 2 · Empresa As empresas também saem do projeto, e cada página passa a ter o seu próprio título de aba. generateMetadata
Frente 3 · Pessoa e candidatura O que a tela faz quando a busca falha, e quando o id não existe. error.tsx · notFound()
Frente 4 · Busca e números Os números do catálogo em streaming, e a decisão de quão velho o dado pode ficar. Suspense · revalidate

A frente 1 tem, esta semana, um poder que não tinha. O lib/api.ts dela é o único arquivo do projeto que conhece a URL da fonte — as outras três frentes só chamam funções. Isso não é hierarquia: é o que vai permitir trocar o GitHub pela API do Spring Boot, mais para frente no semestre, mexendo em uma linha.

Antes de codar — a combinação de 15 minutos
⏱️

Nada começa antes de o JSON estar no ar

Na semana passada as quatro frentes podiam trabalhar em paralelo desde o primeiro minuto. Esta semana não. As frentes 2, 3 e 4 buscam de um endereço que só existe depois que a frente 1 der push — e um endereço combinado no grupo, mas errado, custa a mesma hora de depuração para as três.

Sentem juntos por quinze minutos, ainda em aula, e resolvam estas três coisas nesta ordem.

passo 1 · frente 1 O JSON no ar Move o array para dados/vagas.json, dá push e abre o botão Raw.
→
passo 2 · todo mundo A URL no grupo A URL crua, copiada da barra de endereço, colada no grupo. Cada pessoa abre e confere que vê JSON.
→
passo 3 · frente 1 O lib/api.ts As quatro funções, num commit só, mesmo que ainda incompletas. É o contrato da semana. 
// lib/api.ts — FRENTE 1 entrega este arquivo primeiro, num commit só.
// As outras três frentes só chamam estas funções. Ninguém mais escreve fetch.

const FONTE = "https://raw.githubusercontent.com/SUA-EQUIPE/leque-de-vagas/main/dados";

export async function buscarVaga(id: string): Promise<Vaga | undefined> {
  throw new Error("TODO frente 1");
}
export async function listarEmpresas(): Promise<Empresa[]> {

}
export async function buscarEmpresa(slug: string): Promise<Empresa | undefined> {
  throw new Error("TODO frente 1");
}

Repare no | undefined. Ele não está aí por capricho de tipagem: é o TypeScript obrigando cada tela a decidir, agora, o que fazer quando a vaga não existir. Essa decisão é a parte 3 do desafio.

Os dois erros que a equipe inteira vai cometer

1 · A URL errada. A do github.com/... devolve a página do GitHub, em HTML — e o .json() quebra com "Unexpected token '<'". A que serve começa com raw.githubusercontent.com. Abra no navegador antes de colar: você tem que ver o JSON cru, sem barra lateral e sem botão.

2 · O JSON que ainda é TypeScript. Vírgula sobrando no fim do array, aspas simples, chave sem aspas, comentário com //. O TypeScript aceitava tudo isso; JSON não aceita nada disso. Se o editor não pintar erro, cole o arquivo num validador de JSON antes do push — o erro que aparece depois, no terminal do colega, é bem menos claro.

As quatro partes
PARTE 1

Vaga

frente 1 · fetch e generateStaticParams

Tirar o dado de dentro do projeto e devolvê-lo pronto para as outras três frentes — com as doze páginas de detalhe já geradas no build.

  • dados/vagas.json na raiz do repositório, com as mesmas 12 vagas (no mínimo) do desafio 03. Nenhuma perda de dado: as descrições de 300 caracteres continuam lá.
  • data/vagas.ts e data/empresas.ts viram um lib/tipos.ts só, com apenas os tipos Vaga e Empresa — a frente 1 cria o arquivo com o Vaga, e a frente 2 acrescenta o Empresa no mesmo commit da combinação de 15 minutos. Nenhum array sobra em app/.
  • lib/api.ts com as quatro funções combinadas, cada fetch com next: { revalidate: 60, tags: [...] } e a conferência de resposta.ok.
  • app/vagas/[id]/page.tsx async, buscando pelo lib/api.ts. A /vagas não é sua: ela é da frente 4 desde a aula 03, e a parte 4 cuida dela. O que a frente 1 entrega ali é o lib/api.ts que ela chama.
  • generateStaticParams em app/vagas/[id]/page.tsx, gerando uma página por vaga.

Como você prova que fez: npm run build, e embaixo de /vagas/[id] aparecem as rotas geradas, cada uma com ●. A linha do /vagas/[id] em si sai sem símbolo: ela virou só o cabeçalho do grupo. E não espere ver as doze — o terminal imprime as três primeiras e resume o resto como [+9 more paths]. Cole essa parte na descrição do Pull Request — é o que a correção vai olhar primeiro.

PARTE 2

Empresa

frente 2 · generateMetadata

A mesma mudança do lado das empresas — e cada página passando a ter o seu próprio título de aba, que é o que aparece quando alguém manda o link no grupo.

  • dados/empresas.json publicado, com as mesmas empresas de antes. Os slug continuam sendo os mesmos que a frente 1 usa em empresaSlug.
  • data/empresas.ts deixa de existir: o array vai para o JSON acima, e o tipo Empresa vai para o lib/tipos.ts que a frente 1 criou — no mesmo commit da combinação de 15 minutos.
  • app/empresas/[slug]/page.tsx async, buscando com buscarEmpresa(slug).
  • A aba Vagas do AbasDaEmpresa continua sendo cliente e continua com useState — mas as vagas chegam por prop, filtradas no servidor por empresaSlug.
  • generateMetadata na página da empresa: título "{nome} · Leque de Vagas" e description a partir do sobre.
  • generateStaticParams por slug, e export const metadata fixo na listagem /empresas.

Como você prova que fez: abra duas empresas diferentes e olhe a aba do navegador — dois títulos diferentes. Print das duas abas no Pull Request.

PARTE 3

Pessoa e candidatura

frente 3 · erro e ausência

Responder às duas perguntas que só existem porque o dado agora vem de fora: e se a vaga não existir? e se a rede cair?

  • Em app/vagas/[id]/page.tsx: se buscarVaga(id) devolver undefined, chame notFound(). O not-found.tsx da aula 02 finalmente tem quem o chame.
  • app/vagas/[id]/error.tsx (cliente, com "use client"): mensagem em português de gente, sem stack trace, e um botão que chama reset().
  • Teste os dois de verdade: /vagas/999 para o primeiro; uma URL quebrada de propósito no lib/api.ts, por trinta segundos, para o segundo.
  • O FormularioDeCandidatura continua igual — tudo o que você fez na aula 03 fica. Ele só passa a receber o título da vaga vindo da busca.
  • loading.tsx em app/vagas/[id]/, com um esqueleto do tamanho da página real, e não um "Carregando…" de uma linha.

Como você prova que fez: dois vídeos curtos de tela, ou dois prints — /vagas/999 mostrando o not-found, e a tela de erro com o botão de tentar de novo funcionando.

A diferença que cai na prova: notFound() é para o que não existe — o endereço está errado, e recarregar não vai ajudar. O error.tsx é para o que falhou — a rede caiu, o GitHub estava fora, e tentar de novo pode muito bem funcionar. Trocar um pelo outro é dizer à pessoa a coisa errada sobre o que ela deve fazer agora.

PARTE 4

Busca e números

frente 4 · Suspense e revalidate

Fazer a listagem aparecer antes de o bloco mais lento ficar pronto — e escolher, com um número que você sabe defender, quão velho o dado pode ficar.

  • app/vagas/page.tsx é sua, como desde a aula 03 — e é ela que muda de forma esta semana: deixa de ser async, e quem busca passam a ser os filhos, cada um dentro do seu <Suspense>. A frente 1 só te entrega o lib/api.ts que eles chamam.
  • components/NumerosDoCatalogo.tsx: async, busca por conta própria e mostra "{vagas.length} vagas · {iniciantes} aceitam quem está começando". É o lab 4 da aula.
  • <Suspense> em volta dele, com um fallback da mesma altura do bloco real — e um segundo <Suspense> em volta da listagem, para um bloco não segurar o outro.
  • O MuralDeVagas continua cliente e continua com os filtros no useState — a aula 03 inteira fica de pé. O que muda é que as vagas chegam por prop, buscadas por um ListagemDeVagas async.
  • Escolha um revalidate para as vagas e escreva num comentário por que esse número. Sessenta segundos, dez minutos, uma hora: qualquer um serve, desde que você saiba dizer o motivo.
  • Uma linha no README: quanto tempo uma vaga nova leva, no pior caso, para aparecer no site publicado.

Como você prova que fez: um vídeo curto de tela com a página carregando — o título e a lista aparecem, o esqueleto fica um instante, e os números entram sem a página pular.

O que a equipe entrega junto
  • Nenhum import de array de dados sobrou dentro de app/ ou components/. Se sobrou um, a frente dele não terminou.
  • Um fetch só mora no projeto, e ele está no lib/api.ts. Página nenhuma conhece a URL.
  • npm run build passa sem erro, e a equipe sabe explicar o símbolo de cada rota da tabela.
  • Nenhum console.log e nenhum setTimeout de teste sobreviveu ao commit.
  • Está publicado na Vercel, e alguém abriu no celular para conferir.
  • Um Pull Request por frente, revisado por outra pessoa da equipe antes do merge — como no curso de GitHub.

Prazo e formato

Até 09/09, antes do início da aula 05. O que é entregue é o repositório da equipe, na branch principal, com o site publicado.

  1. Um Pull Request por frente, com a descrição dizendo o que mudou e o print que a sua parte pede.
  2. README atualizado: de onde vêm os dados, e quanto tempo uma vaga nova leva para aparecer.
  3. O link do site na Vercel no grupo da turma.

Isto não é exercício avulso. É o Checkpoint 1 sendo construído — ele é a soma dos desafios das aulas 03 a 07. Quem pula esta semana não sente falta agora: sente na aula 08, quando faltar a metade que devia estar pronta.
