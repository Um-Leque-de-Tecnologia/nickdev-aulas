// conceito · LP-205

O componente que busca antes de existir na tela

Server Component pode ser async. Ele espera a API, monta o HTML já preenchido e manda pronto. Não existe "estado de carregando" porque não existe o momento sem dado.

app/midia/[slug]/page.tsx
export default async function Ficha(
  { params }: { params: Promise<{ slug: string }> }
) {
  // no Next 16 params é Promise — o await não é enfeite
  const { slug } = await params;
  const midia = await buscarMidia(slug);

  return (
    <article>
      <h1>{midia.titulo}</h1>
      {midia.diretor && <p>Diretor: {midia.diretor}</p>}
    </article>
  );
}
1Sem useEffect, sem useState, sem spinner à mão. A busca acontece onde a chave mora: no servidor.
2O && ali não é estilo: campo ausente tem que sumir junto com o rótulo. "Diretor:" sozinho é pior que não mostrar nada.
3Filme antigo sem elenco, documentário sem diretor. Leia a documentação antes de escrever — quais campos podem vir vazios?
4Duração vem em minutos e aparece como 1h47, nunca "107". Formato é decisão de produto.

LP-205 é a prática deste slide inteiro: a ficha do filme com diretor, duração, elenco e classificação — e testada com um filme completo e com um filme faltando dado.

// notFound() · LP-204

Ficha vazia respondendo 200 é mentira

/midia/titulo-que-nao-existe abre uma ficha esqueleto e diz para o mundo inteiro que deu certo. Isso tem nome: soft 404.

app/midia/[slug]/page.tsx
import { notFound } from "next/navigation";

const midia = await buscarMidia(slug);
if (!midia) notFound();   // 404 de verdade
Network › /midia/nao-existe Status: 404 Not Found ← o único jeito de saber
1Buscador indexa lixo, monitoramento não acusa, e ninguém descobre o link interno quebrado. O 200 esconde o problema de todo mundo.
2Confira o status na aba Network. A tela pode estar bonita e o status errado — só o cabeçalho HTTP responde.
3O not-found.tsx merece mais que uma frase: ofereça busca e destaques. É uma pessoa perdida, não um erro de sistema.
4Cuidado: título existente com dado incompleto não pode virar 404 por engano. Ausência de campo não é ausência de título.

🤖 Conteúdo de entrevista: peça a diferença entre notFound(), not-found.tsx e um redirect para a home. As três "resolvem" o sintoma; só uma está certa — e o PR do LP-204 tem que argumentar por que redirecionar seria errado.

Três mídias, três fichas — e uma decisão de arquitetura

Hoje a ficha da série é idêntica à do filme, e por isso está errada: mostra "duração" de algo que não tem duração única. O podcast exibe "Diretor: —".

🎬 Filme · LP-205

Diretor, duração, elenco, classificação. Duração em minutos vira 1h47. Campo ausente some junto com o rótulo.

📺 Série · LP-206

Temporadas, total de episódios, status. Série de uma temporada no singular. Nenhum campo de filme sobra.

🤖 Descreva as três formas de mídia e peça sugestões de estrutura. Ouça, escolha uma, e escreva no PR por que ela e não as outras. A decisão é de arquitetura — e é sua.

Ninguém segue sem responder

Três perguntas. O resto da aula empilha em cima destas — se alguma travar, é agora.

1Seu componente busca dado com await. Onde essa requisição acontece — na sua máquina, no servidor ou no navegador de quem visita?

// o card mais grave da semana · LP-210

NEXT_PUBLIC_ não é estilo. É uma declaração.

Tudo que começa com esse prefixo é embutido no pacote que vai para o navegador. Você não está nomeando uma variável — está assinando um documento dizendo que aquele valor é público.

hoje
🌐
navegadorcarrega a chave junto com o catálogo
→
🔓
APIrecebe a chave direto de quem quiser

Qualquer pessoa com o site aberto tem a chave. Basta a aba Network.

com BFF
🌐

→
🛡️
seu Route Handlerguarda a chave, devolve só o necessário
→
🔒

BFF = Backend for Frontend. Um servidor seu, entre o navegador e a API de terceiro.

Verdade desconfortável: chave que já foi ao navegador está comprometida. Trocar o código não a desvaza. O LP-210 exige registrar isso no PR e avisar quem administra a API.

// Route Handler · LP-210 · LP-216

Hoje o código trata qualquer resposta ruim igual. Erro interno da API vira "o filme não existe", e a pessoa desiste de procurar um título que está lá.

// a ironia da semana · LP-212

Ausente, nulo e vazio são três coisas

O arquivo de tipos do LequePlay foi gerado por IA numa tarde e nunca conferido. O TypeScript garante uma segurança que não existe — e metade dos bugs desta semana nasce daí.

types/midia.ts
// o que a IA escreveu
type Midia = {
  titulo: string;
  poster: string;
  elenco: string[];
  nota: number;
};

// o que a API devolve de verdade
type Midia = {
  titulo: string;
  poster?: string | null;   // evidência: doc §4.2
  elenco?: string[];         // evidência: resposta real
  nota?: number | null;     // null = ainda não avaliado
};
1Ausente — a chave nem vem na resposta. Acessar dá undefined, e o erro aparece longe daqui.
2Nulo — a chave vem, o valor é null. Passa por uma checagem de existência e quebra no .length.
3Vazio — string vazia, lista vazia, zero. Não quebra nada: só exibe rótulo órfão ou uma nota 0,0 que é mentira.
4Onde a documentação não disser, teste contra a API real e registre. Documentação mente por omissão; a resposta de verdade não.
5Aceite duro: nenhum any novo para calar o compilador. Isso troca um problema visível por um invisível.

🤖 A ironia do card: ele conserta o que a IA escreveu. Use o Copilot para acelerar a varredura, mas cada campo opcional precisa de evidência — uma linha da documentação ou uma resposta real. A evidência vai no PR.

// resiliência · LP-201

Um item quebrado não derruba os outros

Um podcast entrou sem capa e a home inteira parou de abrir. Trinta pôsteres perfeitos morreram por causa de um campo nulo. A correção tem duas metades, e entregar só uma reprova no review.

metade 1 · honestidade de tipo

O campo é opcional, e o código sabe

poster?: string | null;

A ausência deixa de ser surpresa em tempo de execução e vira um caso que o compilador te obriga a tratar.

metade 2 · produto

Pôster ausente vira cartão nomeado

{midia.poster
  ? <Poster src={midia.poster} />
  : <CartaoNomeado titulo={midia.titulo} />}

Não é buraco cinza: é um cartão com o nome do título, e o texto alternativo descreve o que a pessoa está perdendo.

Aceite do LP-201: testado com três itens quebrados de formas diferentes — um sem o campo, um com null, um com string vazia. As três quebram diferente, e é por isso que são três testes.

// formatação · LP-213 · LP-214

O servidor formatou de um jeito. O navegador, de outro.

Armadilha específica do Next: os dois lados podem ter fuso e configuração regional diferentes. O HTML sai com um texto, o navegador pinta outro, e o React acusa incompatibilidade de hidratação.

lib/formato.ts
// determinístico: idioma e fuso fixados
export const data = (iso: string) =>
  new Intl.DateTimeFormat("pt-BR", {
    timeZone: "America/Sao_Paulo",
    day: "2-digit", month: "long", year: "numeric",
  }).format(new Date(iso));

export const nota = (n: number | null | undefined) =>
  n == null
    ? "ainda não avaliado"
    : n.toFixed(1).replace(".", ",");
1Caso mais visível: título lançado às 21h aparece como do dia seguinte em outro fuso. Escolha um fuso de referência e aplique em todo lugar.
2LP-213: sem avaliação não é 0,0. Zero é uma nota, e péssima. Ausência de informação é outra coisa — e merece convite para ser a primeira pessoa a avaliar.
3A correção óbvia é não dividir por zero. A boa é decidir o que "sem nota" significa.
4Formatação centralizada, não repetida. Cartão e ficha usando a mesma função é o que garante o mesmo texto nos dois. Duração vira 1h47, não "107 min".
5Aceite: nenhum aviso de hidratação no console e nenhuma data crua na interface.

🤖 Descreva o erro de hidratação e peça a causa — ele acerta o diagnóstico. Sobre fuso, confira com calma: é o assunto em que ele mais mistura conselhos incompatíveis entre si. No LP-213, use-o para o que ele faz bem: varrer o projeto atrás de outras divisões com denominador possivelmente zero.

// duplicação · LP-215

Cinco cópias, cinco verdades diferentes

O cartão do catálogo foi copiado para home, busca, destaques, perfil e página de gênero. Cinco arquivos quase iguais, com a mesma cadeia de if. A etiqueta já está errada em dois: série marcada como filme.

Sintoma

Etiqueta errada em duas telas. Alguém corrigiu em três arquivos e esqueceu dos outros dois.

Causa

Duplicação. Cinco cópias não são cinco componentes: são cinco chances de divergir.

Correção

Um componente só, usado nos cinco lugares — com as diferenças legítimas resolvidas de propósito.

1As diferenças são reais: destaque é maior, perfil mostra progresso. Isso não é ruído, é requisito.
2Três saídas possíveis: propriedades de variação, composição, ou dois componentes com base comum. Escolher é o trabalho do card.
3Cuidado com o exagero oposto: um componente com onze propriedades booleanas é pior que cinco cópias. Ele parece unificado e não é.
4Aceite: nenhuma cópia antiga sobrou. Unificar deixando os arquivos velhos no repositório é criar a sexta cópia.

🤖 Ele é bom em achar a duplicação e propor a unificação; erra na dose, sugerindo o componente universal de onze propriedades. Peça duas alternativas e escolha a mais simples — depois defenda a escolha no PR.

// o antídoto

A API tem três estados, e o segundo é uma armadilha

A documentação da API do LequePlay marca cada endpoint. Não é burocracia: a confusão da sprint passada nasceu de confiar na leitura de memória — a de quem lembrava, e a do modelo.

✅ existe

Está no ar hoje. Você pode chamar, testar e ver a resposta real. É daqui que sai a evidência do LP-212.

🕓 backlog

É especificação, não existe. Está escrito na documentação e responde 404. Endpoint documentado não é endpoint pronto.

❓ a confirmar

Ninguém garante. Antes de construir tela em cima, pergunte a quem mantém a API — e registre a resposta no PR.

1A IA lê a documentação inteira e não distingue os três estados. Ela sugere o endpoint 🕓 com a mesma confiança do ✅.
2O sintoma é sempre o mesmo: código plausível que responde 404 em execução. Não há erro de compilação para te salvar.
3Nunca prometa na tela o que a API não tem. Se o endpoint é 🕓, o card não é este — fale com quem prioriza.

Consumir a API de verdade é o antídoto contra a alucinação. Os dois eixos da aula — Next e IA — se encontram exatamente aqui: quem confere na fonte não é enganado nem pela própria memória nem pela do modelo.

Onde ela acerta, e onde ela erra caro

peça sem medo
  • Stack trace → causa raiz. Cole inteiro, sem cortar. LP-201 · LP-214
  • Varredura mecânica. "Ache toda divisão com denominador possivelmente zero." LP-213
  • Padrão de acessibilidade. ARIA, role, região anunciada. LP-202
  • Texto de interface. A mensagem de erro em português que não assusta. LP-203
  • Estrutura de código. O esqueleto do mapeamento de status, as tags OG. LP-209 · LP-211
confira sempre
  • Declara todo campo como obrigatório. É o bug que o LP-212 existe para consertar.
  • Inventa formato de dado. "Duração vem em segundos" — vem em minutos, e ninguém avisou.
  • Inventa endpoint 🕓. Sugere o que só existe na especificação, com voz de quem testou.
  • Mistura versões do Next. params sem await, getServerSideProps, error.tsx sem "use client".
  • Erra na dose da abstração. O componente universal de onze propriedades. LP-215
1Auditar campo por campo. Não "revisei o arquivo": percorreu cada campo perguntando ausente? nulo? vazio?
2Pedir evidência. Toda afirmação da IA vira uma pergunta: "onde está escrito isso?" Sem linha de documentação ou resposta real, não entra.
3Conferir na fonte. A fonte é a aba Network, o log do servidor, o node_modules — nunca o chat.

A IA escreve, você assina. O nome no PR é o seu, e a pergunta do review — "por que assim?" — é feita a você. O campo "o que a IA sugeriu e eu recusei" não é enfeite do template.
