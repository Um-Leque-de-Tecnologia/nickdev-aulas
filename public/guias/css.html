CSS, do seletor ao sistema

Começa no básico — como aplicar, seletores, box model — e vai até montar um sistema: tokens em custom properties, tema claro e escuro, camadas com @layer e container queries. No fim, o caminho do design pronto até o código.

Fundamentos

cssComo aplicar CSS

Três formas — mas o jeito profissional é o arquivo separado. A regra é sempre: seletor { propriedade: valor; }

/* 1. arquivo separado (recomendado) — no <head> do HTML: */
<link rel="stylesheet" href="style.css">

/* 2. no próprio HTML, dentro de <style> */
/* 3. inline (evite): <p style="color:red"> */

/* anatomia de uma regra: */
h1 {
  color: tomato;
  font-size: 40px;
}

cssSeletores

Como você escolhe quem vai receber o estilo.

p            /* toda tag <p> */
.destaque    /* tudo com class="destaque" */
#topo        /* o elemento com id="topo" */
nav a        /* todo <a> dentro de <nav> */
a:hover      /* link quando o mouse está em cima */
button:focus /* botão quando está selecionado */
Dica: use class (.nome) para a maioria das coisas — pode repetir em vários elementos. Use id (#nome) só para algo único na página.

}

cssBox model

Toda caixa tem 4 camadas, de dentro pra fora: content → padding → border → margin.

.card {
  width: 300px;
  padding: 20px;   /* espaço INTERNO */
  border: 2px solid #7B4FD0;
  border-radius: 12px; /* cantos arredondados */
  margin: 16px;    /* espaço EXTERNO */
  box-sizing: border-box; /* padding não estoura a largura */
}
resultado
Atalho de valores: padding: 10px 20px = 10 em cima/baixo, 20 nas laterais. Com 4 valores é no sentido horário: cima, direita, baixo, esquerda.

cssDisplay e posicionamento

display define como o elemento ocupa espaço. É a propriedade mais importante do CSS de layout.

display: blockocupa a linha inteira (div, p, h1). Empilha um embaixo do outro.
display: inlineocupa só o necessário, fica na mesma linha (span, a).
display: flexvira um container flexível — ver seção Flexbox.
display: gridvira uma grade — ver seção Grid.
display: nonesome da tela completamente.
.fixo-no-topo {
  position: sticky;  /* gruda ao rolar */
  top: 0;
  z-index: 10;      /* ordem de empilhamento */
}
Layout

Flexbox ou Grid

A dúvida mais recorrente do CSS, e ela tem resposta.

Flexbox — uma direção

Os itens ficam em linha ou em coluna, e o espaço se distribui entre eles. O conteúdo decide o tamanho.

Barra de navegação, grupo de botões, chips de filtro, o rodapé de um card.

Grid — duas direções

Existe alinhamento em linhas e colunas ao mesmo tempo. Você decide o tamanho, no container.

Galeria de cards, layout da página inteira, formulário em duas colunas.

Regra de bolso: o conteúdo decide → Flex. Você decide → Grid.

Não é escolher um time. O normal é a página em Grid e cada card, por dentro, em Flex. Eles foram feitos pra conviver.

cssFlexbox

O jeito moderno de alinhar itens em uma direção (linha ou coluna). Você aplica no container, e os filhos se organizam.

.container {
  display: flex;
  justify-content: space-between; /* eixo horizontal */
  align-items: center;         /* eixo vertical */
  gap: 16px;                    /* espaço entre itens */
}
resultado
flex-directionrow (linha, padrão) ou column (coluna).
justify-contentalinha no eixo principal: flex-start, center, space-between, space-around.
align-itemsalinha no eixo cruzado: center, flex-start, stretch.
gapespaço entre os itens.
flex-wrapwrap deixa quebrar linha quando não cabe.
Pratique jogando: flexboxfroggy.com ensina tudo isso movendo sapinhos. 🐸

cssGrid

Pra layouts em duas dimensões (linhas E colunas). Ótimo pra galerias e páginas inteiras.

.galeria {
  display: grid;
  grid-template-columns: 1fr 1fr 1fr; /* 3 colunas iguais */
  gap: 12px;
}
resultado
Pratique jogando: cssgridgarden.com — regue as cenouras com CSS Grid. 🥕

Grid na prática

A galeria que se vira sozinha

.lista-eventos {
  display: grid;
  gap: var(--esp-3);
  grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));
}

Uma linha, e nenhuma media query:

  • auto-fit — crie quantas colunas couberem
  • minmax(280px, 1fr) — cada coluna tem no mínimo 280px; o espaço que sobrar é dividido igualmente

Celular estreito: 1 coluna. Tablet: 2. Monitor: 4. Sem você listar nenhuma largura de aparelho.

auto-fit ou auto-fill? Com poucos itens, auto-fit faz eles esticarem pra ocupar a linha; auto-fill mantém colunas vazias e os itens no tamanho mínimo. Para galeria, quase sempre auto-fit.

Layout da página com áreas nomeadas

.pagina {
  display: grid;
  min-height: 100dvh;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "cabecalho"
    "conteudo"
    "rodape";
}

header { grid-area: cabecalho; }
main   { grid-area: conteudo; }
footer { grid-area: rodape; }

O 1fr no meio faz o rodapé grudar embaixo mesmo com pouco conteúdo — sem position: absolute, sem cálculo de altura.

Repare no 100dvh. O vh tradicional conta a barra de endereço do celular e gera aquele corte estranho. dvh acompanha a altura que realmente está visível.

Tamanho fluido: clamp e min

h1 {
  /*      mínimo      ideal (cresce)   máximo */
  font-size: clamp(1.75rem, 4vw + 1rem, 3.5rem);
}

.conteudo {
  width: min(100% - 2rem, 70ch);
  margin-inline: auto;
}
RecursoPra que serve
clamp(min, ideal, max)Valor que acompanha a tela mas nunca sai da faixa
min(a, b)O menor dos dois — largura com margem garantida
chLargura em caracteres. 60–75ch é a faixa legível
margin-inlineMargem horizontal, respeitando o sentido da escrita
Use rem, não px, em tipografia e media query. Quem aumentou a fonte padrão do navegador — por baixa visão, por exemplo — só é atendido se você usar unidade relativa. Com px, o ajuste da pessoa é simplesmente ignorado.
Propriedades lógicas. margin-inline, padding-block, inset substituem left/right/top/bottom e funcionam em qualquer direção de escrita. Custa o mesmo e já deixa o projeto pronto pra internacionalização.
Responsividade

cssResponsividade e media queries

Um só código que funciona bem no celular, no tablet e no monitor. É o que separa um site amador de um profissional — e é mais simples do que parece.

Pré-requisito nº 1: sem esta linha no <head>, nada de responsivo funciona no celular. Ela manda o navegador respeitar o tamanho real da tela: 
<meta name="viewport" content="width=device-width, initial-scale=1.0">

Unidades: fixas x flexíveis

Metade da responsividade é só parar de usar px pra tudo. Unidades relativas se ajustam sozinhas ao tamanho da tela e da fonte.

UnidadeO que éQuando usar
pxpixels fixos, não mudambordas, detalhes finos
%porcentagem do elemento pailarguras que acompanham o container
remrelativo à fonte base (1rem = 16px)tamanhos de fonte e espaçamentos — o queridinho
emrelativo à fonte do próprio elementopadding interno de botões
vw / vh1% da largura / altura da telaseções em tela cheia (100vh)
Truque profissional: width: min(600px, 90%) — o bloco tem no máximo 600px, mas nunca passa de 90% da tela. Responsivo numa linha só.

A sintaxe da media query

Uma media query é um "se a tela tiver tal tamanho, aplique estes estilos". Você coloca regras CSS normais lá dentro.

@media (min-width: 700px) {
  /* só vale quando a tela tem 700px OU MAIS */
  .menu { flex-direction: row; }
  .titulo { font-size: 48px; }
}

@media (max-width: 699px) {
  /* só vale quando a tela tem 699px OU MENOS */
  .esconder-no-celular { display: none; }
}
min-widthaplica de tal largura pra cima (abordagem mobile-first).
max-widthaplica de tal largura pra baixo.

Breakpoints comuns

"Breakpoint" é o tamanho onde o layout muda. Não existe regra fixa, mas estes são os pontos de virada mais usados:

até ~600px📱 celular — tudo empilhado, uma coluna
~600 a 900px📲 tablet — começa a caber lado a lado
~900px pra cima💻 desktop — layout completo, várias colunas

Mobile-first na prática

Escreva o estilo do celular primeiro (sem media query) e vá adicionando o que muda em telas maiores. É mais fácil e é como o mercado trabalha.

/* 1. base: celular — cards empilhados */
.cards {
  display: flex;
  flex-direction: column;
  gap: 12px;
}

/* 2. tela maior: coloca lado a lado */
@media (min-width: 700px) {
  .cards { flex-direction: row; }
}

Veja acontecer 👇

Clique nos tamanhos e observe o layout mudar. Em 700px a media query dispara e os blocos saem de empilhados pra lado a lado — sozinhos.

Bônus: grid que se vira sozinho

Esse padrão cria colunas que se ajustam sem nenhuma media query: cada card tem no mínimo 200px, e o grid encaixa quantos couberem por linha.

.galeria {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(200px, 1fr));
  gap: 16px;
}
E as imagens? Uma regra resolve 90% dos problemas: img { max-width: 100%; height: auto; } — a imagem nunca estoura a tela e mantém a proporção.

Container queries

O recurso mais importante desta aula pra quem vai escrever componente — e é por isso que ele aparece antes de Angular e Next.

O problema: media query pergunta o tamanho da janela. Mas um card não se importa com a janela. Ele se importa com o espaço que recebeu. O mesmo card pode estar numa barra lateral de 300px ou no meio da página com 900px — e a janela é a mesma nos dois casos.

/* 1. o pai declara que é um container mensurável */
.lista-eventos {
  container-type: inline-size;
  container-name: lista;
}

/* 2. o filho reage ao tamanho DO PAI, não da tela */
@container lista (min-width: 400px) {
  .card-evento {
    grid-template-columns: 120px 1fr;
  }
}
@media@container
MedeA janela do navegadorO elemento pai
Serve praLayout geral da páginaComponente reutilizável
O componente precisa saber onde está?SimNão
Por que isso muda tudo com framework. Um componente de card é escrito uma vez e usado em cinco lugares de larguras diferentes. Com media query você acaba criando variações (card--estreito, card--largo) e passando prop pra escolher. Com container query o card se resolve sozinho, onde quer que seja colocado.
Pegadinha: container-type: inline-size faz o elemento medir a si mesmo — e um elemento não pode depender do tamanho do próprio conteúdo pra isso. Se o container "sumir" ou colapsar, é quase sempre isso. Declare o container no pai do que você quer estilizar, nunca no próprio elemento.
Sistema

Custom properties como tokens

Um token é um valor de design com nome. Em vez de espalhar #7B4FD0 por quarenta lugares, você o declara uma vez.

:root {
  /* cor */
  --cor-fundo: #ffffff;
  --cor-superficie: #f4f4f5;
  --cor-texto: #18181b;
  --cor-marca: #7B4FD0;

  /* escala de espaço — nada de 13px, 17px, 22px soltos */
  --esp-1: .5rem;
  --esp-2: 1rem;
  --esp-3: 1.5rem;
  --esp-4: 2.5rem;

  /* forma */
  --raio: 12px;
  --borda: 1px solid rgb(0 0 0 / .1);
}

E o uso:

.card-evento {
  background: var(--cor-superficie);
  padding: var(--esp-3);
  border-radius: var(--raio);
}

Elas cascateiam — e isso é o truque

Diferente de variável de Sass, custom property é viva no navegador e herda. Você pode redefinir num pedaço da árvore:

.card-evento.destaque {
  --cor-superficie: #faf5ff;   /* só aqui dentro */
}
Valor padrão: var(--x, 1rem) usa 1rem se --x não existir. Ótimo pra escrever componente que funciona mesmo sem o tema carregado.
Nomeie pelo papel, não pela aparência. --cor-marca sobrevive ao redesign; --roxo vira mentira no dia em que a marca fica verde. Vale a mesma lógica de escolher <article> em vez de class="card-azul".

Tema claro e escuro

Com tokens no lugar, o tema custa poucas linhas — e nenhum componente precisa saber que ele existe.

/* 1. o padrão */
:root {
  color-scheme: light dark;
  --cor-fundo: #ffffff;
  --cor-texto: #18181b;
}

/* 2. quem prefere escuro no sistema */
@media (prefers-color-scheme: dark) {
  :root {
    --cor-fundo: #0d0b14;
    --cor-texto: #f3f0fa;
  }
}

/* 3. e a escolha manual vence os dois */
:root[data-tema="dark"] {
  --cor-fundo: #0d0b14;
  --cor-texto: #f3f0fa;
}
:root[data-tema="light"] {
  --cor-fundo: #ffffff;
  --cor-texto: #18181b;
}

Os componentes seguem usando var(--cor-fundo) e não mudam uma linha. Esse desacoplamento é o ponto — não o tema em si.

color-scheme: light dark não é enfeite. Ele faz o navegador adaptar o que você não controla: barra de rolagem, campos de formulário nativos, seletor de data. Sem ele, você tem um site escuro com um <input> branco brilhante.
Contraste continua valendo nos dois temas. Texto normal precisa de 4.5:1 contra o fundo. Uma combinação que passa no claro pode falhar no escuro — teste os dois. O DevTools mostra a razão de contraste quando você inspeciona uma cor.

@layer

A cena clássica: você escreve uma regra, ela não aplica, e a saída vira !important — que obriga o próximo !important, e em seis meses ninguém sabe mais quem manda em quê.

A causa é a especificidade: .pagina .lista .card a ganha de .card a, mesmo que a segunda seja mais recente e mais correta.

@layer resolve isso deixando você declarar a ordem de prioridade antes de escrever qualquer regra:

/* declare a ordem UMA vez, no topo. só isso já define tudo */
@layer reset, base, componentes, utilitarios;

@layer base {
  a { color: var(--cor-marca); }
}

@layer componentes {
  /* seletor mais fraco, mas vence: a camada é posterior */
  .card-evento a { color: var(--cor-texto); }
}

@layer utilitarios {
  .texto-suave { color: var(--cor-texto-2); }
}

Quem está numa camada posterior vence, independente da especificidade. A disputa deixa de ser uma corrida de seletor.

A regra que confunde: CSS fora de qualquer camada vence todas as camadas. Isso é proposital — deixa você sobrescrever uma biblioteca em camadas com um CSS avulso. Mas significa que misturar os dois estilos dá confusão: coloque tudo em camadas, ou nada.
Onde isso brilha: importar CSS de terceiro dentro de uma camada — @import url(lib.css) layer(vendor) — e pronto: o seu CSS ganha da biblioteca inteira sem um !important sequer.

:has() e aninhamento

:has() — o seletor de pai

Por vinte anos o CSS só descia na árvore. :has() permite estilizar um elemento pelo que existe dentro dele.

/* card que TEM selo de gratuito */
.card-evento:has(.selo-gratuito) {
  border-color: var(--cor-ok);
}

/* o campo cujo input está inválido — e que a pessoa já preencheu */
.campo:has(input:invalid:not(:placeholder-shown)) {
  border-color: var(--cor-erro);
}

/* lista sem nenhum card = estado vazio */
.lista-eventos:not(:has(.card-evento)) {
  display: grid;
  place-items: center;
  min-height: 40vh;
}

Cada um desses casos exigia JavaScript pra adicionar uma classe. Agora é CSS, e continua funcionando se o JavaScript falhar.

O truque do :not(:placeholder-shown). Sozinho, :invalid pinta o campo de vermelho antes de a pessoa digitar qualquer coisa, o que é hostil. Combinado assim, o erro só aparece depois que ela mexeu no campo.

Aninhamento nativo

Sem Sass, sem passo de build:

.card-evento {
  padding: var(--esp-3);
  border-radius: var(--raio);

  & h3 { margin-block-end: var(--esp-1); }

  &:hover { border-color: var(--cor-marca); }

  @media (width >= 48rem) {
    padding: var(--esp-4);
  }
}
Vá até 2 níveis, no máximo 3. Aninhar fundo gera seletores enormes e específicos demais — exatamente o problema que @layer veio resolver. Aninhamento é conveniência de escrita, não licença pra criar .a .b .c .d .e.
Repare em @media (width >= 48rem): a sintaxe de comparação, mais legível que min-width. E em margin-block-end, a versão lógica de margin-bottom.

O problema do escopo

Esta seção existe pra plantar uma pergunta que volta na aula 03 e na aula 10.

Em CSS puro, toda regra é global. Você escreve .card { padding: 1rem } pensando na listagem de eventos. Três meses depois, outra pessoa escreve .card pensando no perfil do organizador. Uma das duas telas quebra — e ninguém descobre até alguém reclamar.

Não é falta de cuidado: é uma característica da linguagem. As saídas historicamente foram:

AbordagemComo funcionaO custo
Convenção de nome (BEM).card-evento__titulo--destaqueFunciona, mas é manual e verboso
Estilo no componente (Angular)O framework reescreve os seletores pra valerem só aliPrecisa do framework
CSS Modules (Next)O build gera nomes únicos: .card_a3f9Precisa do passo de build
@scope (CSS nativo)Delimita onde as regras valem, sem ferramentaAinda chegando aos navegadores
Guarde esta seção. Na aula 03, quando o Angular isolar o CSS do componente automaticamente, e na aula 10, quando o Next fizer o mesmo por outro caminho, a pergunta vai ser: que problema isso resolve? É este. Quem entende o problema entende a solução em cinco minutos; quem não entende decora sintaxe.

No desafio de hoje vocês vão sentir isso na mão: três telas, um arquivo de CSS, e a necessidade de inventar uma convenção de nome pra não colidir.

Do design ao código

O olho de dev

Antes de escrever qualquer código, leia o design. Procure por:

  • Blocos — quais são as caixas grandes? (cada uma vira uma div)
  • Repetição — o que se repete? (vira um componente, tipo um card)
  • Alinhamento — está centralizado? à esquerda? em colunas?
  • Espaçamento — quanto de respiro entre os elementos?
  • Hierarquia — o que é título, o que é secundário? (tamanho e cor)
Truque: desenhe retângulos por cima do design (mentalmente ou no papel). Você acabou de descobrir sua estrutura HTML.

Design tokens

Designers definem uma paleta e tamanhos-padrão. No código, a gente guarda isso em variáveis CSS — muda num lugar, reflete em tudo.

:root {
  --rosa: #F24487;
  --roxo: #7B4FD0;
  --texto: #1B1830;
  --raio: 22px;
  --espaco: 16px;
}

/* usar em qualquer lugar: */
.card { background: var(--rosa); border-radius: var(--raio); }
Por que vale a pena: pra trocar o tema inteiro do site, você muda 5 variáveis em vez de caçar cor por cor.

Tipografia

Fonte e tamanhos criam a hierarquia. Pegue a fonte no Google Fonts e defina os tamanhos que viu no design.

<!-- no <head> -->
<link href="https://fonts.googleapis.com/css2?family=Poppins:wght@400;600;700" rel="stylesheet">

body { font-family: 'Poppins', sans-serif; }
h1 { font-size: 32px; font-weight: 700; }   /* título forte */
.legenda { font-size: 13px; color: #6B6580; } /* secundário */

Espaçamento

O que faz um layout parecer profissional é o respiro consistente. Três ferramentas:

  • padding — espaço dentro da caixa
  • margin — espaço fora da caixa
  • gap — espaço entre itens de um flex/grid
Dica de ouro: use múltiplos de um número (4 ou 8): 8px, 16px, 24px... Isso é o “grid de 8pt” que designers usam. Fica tudo alinhado sem esforço.

Imagens & assets

No Figma você exporta as imagens (PNG/SVG) e coloca na pasta do projeto.

<img src="foto.jpg" alt="Descrição da imagem">

img {
  width: 92px;
  height: 92px;
  border-radius: 50%;
  object-fit: cover;   /* recorta sem esticar */
}
  • SVG pra logos e ícones (não perde qualidade)
  • PNG/JPG pra fotos
  • object-fit: cover encaixa a foto no espaço sem distorcer
  • Sempre preencha o alt (acessibilidade!)

Componentização (sem framework)

"Componente" parece coisa de React — mas dá pra componentizar já no HTML/CSS/JS. Só que pela metade, e entender essa metade é o que faz o React fazer sentido depois.

Parte 1 — reaproveitar o estilo (dá pra hoje)

Uma classe CSS é um componente de estilo: escreve uma vez, usa em vários lugares.

.tag { background:#F3EEFC; color:var(--roxo); padding:6px 12px; border-radius:100px; }

<!-- o mesmo estilo, reaproveitado -->
<span class="tag">#dev</span>  <span class="tag">#design</span>

Parte 2 — a metade que falta: a estrutura

O estilo não repete, mas o HTML repete — você copia e cola <span class="tag"> pra cada tag. Essa dor é real, e é o que um framework resolve.

Deixe a turma sentir a repetição (copiar 6 cards na mão). É o melhor motivador pro React, onde a estrutura também é reaproveitada.

Parte 3 — o pulo do gato: componente = função que devolve HTML

Com o JavaScript da aula 2, dá pra reaproveitar a estrutura também: uma função cria o pedaço de HTML a partir de dados. Isso é um componente de verdade.

// os dados
const tags = ["#dev", "#design", "#café"];

// o COMPONENTE: uma função que devolve um elemento
function criarTag(texto) {
  const span = document.createElement("span");
  span.className = "tag";
  span.textContent = texto;
  return span;
}

// reaproveitando a estrutura (sem copiar e colar!)
tags.forEach(t => container.appendChild(criarTag(t)));
resultado
Ponte pro React: quando você vir function Tag() {} no React, vai reconhecer — é a mesma ideia, uma função que devolve um pedaço de tela.

Botão de curtir (estado + contador)

Do Figma pro CSS — o passo a passo

  • Fontes — nome, tamanho e peso aparecem no painel

Bootstrap — não reinvente a roda 🅱️

Depois de aprender a montar o layout na mão (o card), dá pra acelerar com uma biblioteca de CSS pronta. O Bootstrap traz navbar, grid, cards e botões já estilizados — você usa as classes em vez de escrever tudo.

1. Incluir (uma linha no <head>)

<link rel="stylesheet"
  href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css">

2. Grid responsivo pronto

Nada de media query na mão: row-cols-* define as colunas por tamanho de tela.

<div class="row row-cols-2 row-cols-md-4 row-cols-xl-6 g-3">
  <div class="col"> ...card... </div>
</div>

3. Card e botões prontos

<div class="card shadow-sm border-0">
  <div class="card-body">
    <h3 class="card-title h6">Título</h3>
    <button class="btn btn-sm btn-outline-secondary">Curtir</button>
  </div>
</div>

4. Dark mode nativo

O Bootstrap 5.3 já tem tema escuro. Só trocar o atributo no <html>:

document.documentElement.setAttribute("data-bs-theme", "dark");
E a componentização? Continua igual! O Bootstrap dá a aparência; a sua função criarCard() continua gerando os cards a partir dos dados. Biblioteca de estilo + componente por função = combo forte.
Quando usar? Bootstrap acelera muito, mas aprenda CSS primeiro (você já sabe 💜). Assim você entende o que a biblioteca faz e consegue customizar — em vez de ficar refém dela.

Erros comuns 🔧

Meu @container não faz nada

Duas causas: faltou container-type: inline-size no pai, ou você declarou o container no próprio elemento que está tentando estilizar. Ele mede o ancestral.

A regra certa não aplica e eu apelei pro !important

É especificidade. Em vez do !important, organize em @layer — ou reduza o seletor que está ganhando, que normalmente é longo demais.

O grid não quebra em coluna única no celular

Provavelmente o mínimo do minmax() é maior que a tela. minmax(280px, 1fr) numa tela de 320px com padding não cabe. Use minmax(min(280px, 100%), 1fr).

A página "pula" enquanto carrega

Imagem sem width e height. Declare os dois, mesmo usando CSS pra redimensionar.

Meu site escuro tem inputs brancos

Faltou color-scheme: light dark no :root. Os controles nativos não seguem as suas variáveis.

Zoom no celular quando toco num campo

O iOS dá zoom em campo com fonte menor que 16px. Use no mínimo 1rem nos inputs.

100vh corta o conteúdo no celular

A barra de endereço entra na conta. Use 100dvh.
