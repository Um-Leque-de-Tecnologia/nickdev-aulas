Java, do zero ao primeiro programa

O que significam aquelas siglas todas — JDK, JRE, JVM, bytecode — sem enrolação; por que orientação a objetos venceu o código estruturado; e o passo a passo, clique por clique, até ver o seu primeiro programa Java rodando.

Antes de tudo

O dicionário desta aula

Programação tem muita palavra estranha, e Java tem mais que a média. Aqui estão as desta aula, em português normal. Volte aqui sempre que esbarrar numa que você esqueceu — consultar dicionário não é trapaça, é o que todo mundo que programa faz o dia inteiro.

Escrever e rodar

PalavraO que é, em palavras simples
Terminal Uma janela onde você digita ordens pro computador em vez de clicar. Escreve uma linha, aperta Enter, ele responde. Também chamam de "prompt", "console" ou "linha de comando" — é tudo a mesma janela.
Código-fonte O texto que você escreve. É o arquivo .java. Uma pessoa lê e entende; o computador ainda não.
Compilar Traduzir o que você escreveu para algo que a máquina consegue executar — tudo de uma vez, antes de rodar. Quem faz isso em Java é o javac.
IDE Um editor de texto turbinado pra programar. Ele colore o código, avisa dos erros enquanto você digita e roda o programa com um clique. O nosso é o IntelliJ.
main A porta de entrada do programa. Quando você manda rodar, o Java procura esse método e começa por ele. Sem main, o programa não sabe por onde começar.

As siglas do Java

PalavraO que é, em palavras simples
Bytecode Uma língua intermediária. Não é mais o que você escreveu, e ainda não é o idioma do seu computador. Fica no arquivo .class.
JVM O tradutor que lê o bytecode e conversa com o seu computador. Existe uma versão dela pra Windows, outra pra Mac, outra pra Linux.
JRE A JVM mais um monte de coisa pronta que todo programa Java usa. É o pacote de quem só quer rodar programas.
JDK O JRE mais as ferramentas de construir — inclusive o tradutor javac. É o pacote de quem vai escrever programas. É este que você instala.

As palavras de orientação a objetos

PalavraO que é, em palavras simples
Classe A forma de bolo. Ela descreve como uma coisa é, mas não é a coisa. "Todo livro tem um título e pode ser emprestado" — isso é a classe Livro.
Objeto O bolo feito com aquela forma. Um livro de verdade, com título "Duna", que está emprestado. De uma forma você tira quantos bolos quiser.
Atributo Uma informação que o objeto guarda. O título do livro, se ele está emprestado. É um dado.
Método Uma ação que o objeto sabe fazer. Emprestar, devolver, mostrar o título. É um verbo.
Construtor A receita de como nascer. É o que roda no momento em que você cria um objeto, pra deixar ele já com as informações certas.
Tipo Que espécie de informação uma coisa guarda: texto (String), número inteiro (int), sim ou não (boolean). Em Java você é obrigada(o) a dizer isso; em Python, não.
Não decore nada disto. Ninguém aprende vocabulário técnico decorando lista — a gente aprende usando. Você vai ouvir cada uma dessas palavras centenas de vezes ao longo das 18 aulas, e daqui a um mês vai usar sem nem perceber.
Paradigmas

Paradigma estruturado × orientado a objetos

Comece pela agenda de telefone

Imagine que você vai anotar os contatos dos seus amigos. Existem duas maneiras.

Maneira 1: uma folha só com os nomes, outra folha só com os telefones, e uma terceira só com os aniversários. Funciona — desde que você lembre que o terceiro nome corresponde ao terceiro telefone. Se alguém apagar uma linha do meio, tudo desanda.

Maneira 2: um cartãozinho por pessoa, com nome, telefone e aniversário juntos. Perdeu um cartão? Perdeu só aquela pessoa. O resto continua certo.

Essas duas maneiras de arrumar as coisas existem também na hora de programar. Elas têm nome: cada jeito de organizar código é um paradigma.

  • A folha de nomes separada da folha de telefones é o paradigma estruturado
  • O cartãozinho com tudo junto é o paradigma orientado a objetos — o OO, assunto deste curso
Por que os exemplos a seguir estão em Python. A ideia de paradigma é a mesma em qualquer linguagem, e o Python se escreve com menos cerimônia — então dá pra enxergar a ideia sem tropeçar na escrita. Assim que ela estiver clara, a gente refaz o mesmo exemplo em Java e compara lado a lado.

Estruturado: dados de um lado, funções de outro

No paradigma estruturado você tem variáveis soltas e funções que recebem essas variáveis como parâmetro pra operar sobre elas. Dados e comportamento vivem separados.

# estilo estruturado: dados soltos + funções que mexem neles
nome = "Duna"
emprestado = False

def emprestar(titulo):
    # a função não sabe nada sobre `emprestado`
    print(titulo + " foi emprestado.")

emprestar(nome)
emprestado = True   # quem tem que lembrar disso é você, de fora

Orientado a objetos: dados e comportamento juntos

Em OO, cada entidade do mundo real (um livro, uma pessoa, um pedido) vira uma classe, que agrupa seus próprios dados (atributos) e ações (métodos). O objeto sabe cuidar de si mesmo.

# estilo orientado a objetos: dados + comportamento na mesma classe
class Livro:
    def __init__(self, nome):
        self.nome = nome
        self.emprestado = False

    def emprestar(self):
        self.emprestado = True   # o próprio objeto cuida do seu estado
        print(self.nome + " foi emprestado.")

duna = Livro("Duna")
duna.emprestar()
OO não é exclusividade do Java. O exemplo acima é Python e é orientado a objetos do mesmo jeito. A diferença é que em Python a classe é opcional — dá pra escrever o programa inteiro sem nenhuma. Em Java ela é obrigatória: até o main mora dentro de uma.

A mesma classe, agora em Java

Compare linha a linha com a versão em Python. A ideia é idêntica; muda a escrita.

// a mesma classe Livro, em Java
class Livro {
  String nome;                 // todo dado declara o tipo
  boolean emprestado = false;

  Livro(String nome) {         // o construtor tem o nome da classe
    this.nome = nome;           // `this` faz o papel do `self`
  }

  void emprestar() {
    emprestado = true;
    System.out.println(nome + " foi emprestado.");
  }
}

// usando o objeto
Livro duna = new Livro("Duna");
duna.emprestar();
Em PythonEm Java
Indentação delimita o bloco{ } delimitam o bloco, e cada linha fecha com ;
self, escrito como primeiro parâmetrothis, implícito
__init__Um método com o mesmo nome da classe (construtor)
Tipo descoberto ao rodarTipo declarado no código e conferido ao compilar
Classe é opcionalClasse é obrigatória — inclusive pro main
Por que isso importa: à medida que um sistema cresce, "dados soltos + funções que mexem em tudo" vira uma bagunça difícil de manter. Agrupar dados e comportamento em objetos é o que permite os quatro pilares que você vai ver nas próximas aulas: encapsulamento (aula 04), herança (aula 06), polimorfismo (aula 07) e abstração (já começando hoje, na ideia de classe).
O ecossistema

JDK, JRE e JVM

Três siglas que aparecem sempre juntas e confundem todo mundo no começo. A boa notícia: elas são uma dentro da outra, como bonecas russas.

Pense numa oficina de carros:

  • A JVM é o motor. É a peça que de fato faz o carro andar.
  • O JRE é o carro montado — motor, rodas, banco, volante. Dá pra dirigir, mas não dá pra construir outro carro.
  • O JDK é a oficina inteira: o carro, mais todas as ferramentas pra fabricar carros novos.

Você vai escrever programas, não só rodar os dos outros. Então você precisa da oficina: instale o JDK. Ele já vem com o carro e o motor dentro.

A mesma coisa, em tabela

SiglaDo que vem o nomeNa oficina éServe pra
JVMJava Virtual Machineo motor Ler o bytecode e fazer o computador executar. É a peça mais no fundo de todas.
JREJava Runtime Environmento carro montado Rodar programas Java que já estão prontos. Traz o motor mais um monte de coisa pronta que todo programa usa.
JDKJava Development Kita oficina inteira Escrever programas novos. Traz o carro inteiro mais as ferramentas — inclusive o tradutor javac.
Se você guardar uma frase só desta seção, guarde esta: instale o JDK. Os outros dois vêm dentro dele, e você nunca vai precisar instalar nenhum dos dois separado.

Bytecode e portabilidade

Comece por um livro traduzido

Você escreveu um livro em português e quer que ele seja lido no mundo inteiro. Traduzir pra cada idioma daria um trabalho enorme.

Então você faz diferente: traduz uma vez só para um idioma que todo tradutor do mundo conhece. Depois, em cada país, um tradutor local lê essa versão e conta a história na língua de lá.

É exatamente isso que o Java faz:

  • Você escreve em Java — o arquivo .java. É o seu livro em português.
  • O javac traduz uma vez para o bytecode — o arquivo .class. É o idioma que todo tradutor conhece.
  • A JVM é o tradutor local. Tem uma pra Windows, uma pra Mac, uma pra Linux. Cada uma lê o mesmo .class e fala com o computador dela.

Por isso o mesmo arquivo .class funciona em qualquer computador que tenha uma JVM instalada, sem você precisar mexer em nada. É o que o pessoal do Java chama de "write once, run anywhere" — "escreva uma vez, rode em qualquer lugar".

O caminho, num desenho

Aula.java  → (javac) →  Aula.class  → (JVM) →  executando
  o que você        o idioma           o computador
  escreveu          intermediário      fazendo a coisa

"E o Python não faz isso?"

Não — e é uma boa pergunta. No Python você digita python programa.py e pronto: ele lê o que você escreveu e vai executando na hora, toda vez que roda.

O Java tem essa parada a mais no meio. Parece trabalho desnecessário, mas ela paga duas coisas:

  • Erros aparecem antes. Na hora de traduzir, o javac confere um monte de coisa. Se você escreveu bobagem, ele avisa antes do programa rodar — e não na frente do usuário.
  • Roda em qualquer lugar. O mesmo .class funciona no Windows, no Mac e no Linux sem traduzir de novo.
Não existe linguagem melhor, existe troca. Python te dá velocidade pra escrever; Java te dá segurança pra crescer. Neste curso a gente usa Java justamente porque ele obriga a organizar as coisas — e organizar é o que você veio aprender.
Preparar o ambiente

Instalar o JDK 21

Vamos usar o JDK 21 (versão LTS — suporte de longo prazo) durante todo o curso. Baixe pela página oficial da Oracle, a mesma pros três sistemas:

🔗 oracle.com/java/technologies/downloads — role até JDK 21 e escolha a aba do seu sistema.

🪟 Windows

Aba Windows → x64 Installer (.exe) ou .msi. Execute e avance — o instalador já configura o PATH.

🍎 macOS

Aba macOS → ARM64 DMG (chip M1 em diante) ou x64 DMG (Intel). Abra e siga o instalador.

🐧 Linux

Aba Linux → .deb ou .rpm. Ou pelo gerenciador: sudo apt install openjdk-21-jdk.

Oracle JDK × OpenJDK. Os dois nomes aparecem por aí. É a mesma linguagem e a mesma versão — muda o distribuidor e a licença. Pra estudar, qualquer um serve.

Conferindo a instalação

Abra o terminal (Prompt de Comando, PowerShell ou Terminal) e rode:

$ java -version openjdk version "21.0.x" ... $ javac -version javac 21.0.x
Deu "comando não encontrado"? O JDK não está no PATH do sistema. Reinstale marcando a opção de adicionar ao PATH, ou configure a variável de ambiente manualmente (pesquise "adicionar JDK ao PATH" + seu sistema operacional).

Instalar o IntelliJ IDEA Community

O IntelliJ IDEA é a IDE (ambiente de desenvolvimento) mais usada pra Java no mercado. Vamos usar a versão Community — gratuita, open source, e suficiente pra tudo que faremos no curso.

Passo a passo

  1. Baixe o instalador em jetbrains.com/idea, escolhendo a edição Community.
  2. Instale normalmente (Windows/macOS/Linux têm instaladores próprios; no Linux também dá pra usar o JetBrains Toolbox).
  3. Abra o IntelliJ e crie um projeto: New Project → tipo Java → em JDK, selecione o 21 que você acabou de instalar (se não aparecer na lista, clique em Add JDK... e aponte pra pasta de instalação).
  4. Dê um nome ao projeto, ex.: orientacao-objetos-java, e confirme.

A estrutura do projeto

  • src/ — onde ficam seus arquivos .java (código-fonte)
  • out/ — onde a IDE guarda os .class compilados automaticamente
  • arquivo .iml — configuração interna do projeto pro IntelliJ
O botão ▶ verde: quando você clica em "Run" no IntelliJ, ele está fazendo por trás exatamente o que a gente vai fazer na mão daqui a pouco: chamando o javac e depois o java.
Primeiro programa

Hello, World!

Todo caminho em uma linguagem nova começa por aqui. Crie um arquivo chamado Ola.java dentro de src/:

public class Ola {
  public static void main(String[] args) {
    System.out.println("Olá, mundo Java!");
  }
}

São muitas palavras. Vamos por partes

Bate um susto na primeira vez: seis palavras estranhas pra escrever uma frase na tela. Cada linha faz uma coisa só:

A linhaO que ela faz
public class Ola Dá nome à forma de bolo. Em Java, todo código mora dentro de uma classe — não existe código solto. Cuidado: o nome aqui tem que ser igual ao nome do arquivo (Ola.java). Se não for, o Java reclama.
public static void main(...) A porta de entrada. Quando você manda rodar, o Java procura essa linha e começa por ela. Sem main, ele não sabe por onde começar.
System.out.println(...) Escreve uma linha na tela. É o equivalente ao print do Python. O nome comprido é o preço de ser Java.
Pode decorar essa casca sem culpa. Sério. Cada palavrinha dela tem um motivo, e cada motivo tem sua aula: public e static na aula 04, a ideia de classe na aula 03. Tentar entender tudo hoje só ia atrapalhar. Por enquanto: copie, rode, veja funcionar. O entendimento vem depois — e vem bem melhor depois de você já ter usado.

Compilar e rodar pelo terminal

Rodar pela IDE é ótimo no dia a dia, mas hoje a gente faz na mão pra entender o que realmente acontece — é exatamente isso que o desafio da semana vai pedir.

1. Compilar com javac

Primeiro você precisa levar o terminal até a pasta onde o arquivo está. Quem faz isso é o comando cd (de change directory, "mudar de pasta"):

$ cd caminho/da/pasta/onde/esta/o/arquivo

Chegou lá? Agora mande traduzir:

$ javac Ola.java

Se não der nenhum erro, o javac gerou um arquivo novo, Ola.class — o bytecode. Confira com ls (Linux/macOS) ou dir (Windows):

$ ls Ola.class Ola.java

2. Executar com java

Agora peça pra JVM rodar esse bytecode — sem a extensão .class:

$ java Ola Olá, mundo Java!
O fluxo completo: Ola.java (código-fonte, texto) → javac compila → Ola.class (bytecode) → java manda a JVM executar → saída no terminal. Isso é literalmente o mesmo fluxo do slide do bytecode, só que rodando na sua máquina.
