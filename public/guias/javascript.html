JavaScript, do console ao assíncrono

Do primeiro console.log até entender por que a tela não atualizou quando você mudou a lista. Começa do zero e vai até fetch, async/await e o laço de eventos.

Antes de tudo

Fundamentos

Console & variáveis

console.log() mostra qualquer valor no console — é como o JS "fala" com você.

console.log("Oi, mundo! 👋");

Variáveis: let e const

Variável é uma caixinha com etiqueta que guarda um valor.

let pontos = 0;      // pode mudar depois
pontos = 10;

const nome = "Nick";  // fixo, não muda
Regra prática: use const sempre. Só troque pra let quando o valor realmente precisar mudar.

Tipos de dado

  • String — texto, entre aspas: "Nicoly"
  • Number — números, sem aspas: 25, 3.14
  • Boolean — true ou false
  • Array — lista: [1, 2, 3]
  • Object — ficha: { nome: "Nick" }
typeof "oi";   // "string"
typeof 25;     // "number"
typeof true;   // "boolean"

Strings & template literals

Pra juntar texto com variáveis, use crase (`) e ${ }:

const nome = "Ana";
const idade = 20;

// jeito antigo
"Oi, " + nome + ", " + idade + " anos";

// jeito moderno (template literal) 👇
`Oi, ${nome}, ${idade} anos`;

Métodos úteis de string

nome.toUpperCase();   // "ANA"
nome.length;         // 3
nome.includes("A");  // true

Operadores

  • Aritméticos: + - * / % (resto)
  • Comparação: === (igual) !== (diferente) > < >= <=
  • Lógicos: && (E) || (OU) ! (NÃO)
10 % 2;        // 0  → resto da divisão (par!)
7 === 7;       // true
idade >= 18 && temCarteira;  // as duas precisam ser true
Cuidado: = guarda um valor. === compara. São coisas diferentes!

Condicionais

Fazem o código decidir o caminho: "se isso, faça aquilo".

const hora = 14;

if (hora < 12) {
  console.log("Bom dia ☀️");
} else if (hora < 18) {
  console.log("Boa tarde 🌤️");
} else {
  console.log("Boa noite 🌙");
}

Atalho: operador ternário

const status = idade >= 18 ? "maior" : "menor";

switch: quando são vários valores fixos

Ótimo pra comparar uma variável com várias opções exatas — mais limpo que muitos else if.

const dia = "sábado";

switch (dia) {
  case "sábado":
  case "domingo":
    console.log("Fim de semana! 🎉");
    break;
  default:
    console.log("Dia útil 💻");
}
Não esqueça o break! Sem ele, o JS continua executando os próximos case. O default é o "senão" — roda quando nenhum case bate.
Estruturas

Funções

Uma receita reutilizável: recebe parâmetros e pode retornar um resultado.

// declaração
function saudar(nome) {
  return `Oi, ${nome}!`;
}

// arrow function (versão curta e moderna)
const saudar = (nome) => `Oi, ${nome}!`;

saudar("Nick");  // "Oi, Nick!"
return devolve o resultado pra quem chamou. Sem return, a função faz algo mas não "entrega" valor.

Arrays

Lista ordenada de valores. O primeiro item tem índice 0.

const hobbies = ["café", "código", "música"];

hobbies[0];          // "café"
hobbies.length;      // 3
hobbies.push("games");  // adiciona no fim

Descobrir o que tem dentro

hobbies.length;            // 3   → quantos itens
hobbies.includes("café");   // true → esse item existe?
hobbies.indexOf("música");   // 2   → em qual posição está
hobbies.at(-1);             // "música" → o último item
hobbies.some(h => h.length > 5);   // true  → ALGUM item passa no teste?
hobbies.every(h => h.length > 2);  // true  → TODOS passam?

Adicionar e remover

hobbies.push("games");    // adiciona no FIM
hobbies.pop();            // remove o ÚLTIMO (e devolve ele)
hobbies.unshift("chá");   // adiciona no INÍCIO
hobbies.shift();          // remove o PRIMEIRO
Macete: push/pop mexem no fim; shift/unshift mexem no início.

Percorrer e transformar

Estes recebem uma função e rodam ela pra cada item. Os 3 últimos criam uma lista nova (não mexem na original).

// forEach → faz algo com cada item (não devolve nada)
hobbies.forEach(h => console.log(h));

// map → NOVA lista transformada, item por item
const maiusculas = hobbies.map(h => h.toUpperCase());  // ["CAFÉ", ...]

// filter → NOVA lista só com quem passa no teste
const curtos = hobbies.filter(h => h.length <= 4);  // ["café", "chá"]

// find → o PRIMEIRO item que bate (ou undefined)
const achado = hobbies.find(h => h.startsWith("c"));  // "café"

Resumir e organizar

// reduce → junta tudo num só valor (ex.: somar)
const numeros = [10, 20, 30];
const total = numeros.reduce((soma, n) => soma + n, 0);  // 60

hobbies.sort();          // ordena (alfabética por padrão)
hobbies.reverse();       // inverte a ordem
hobbies.slice(0, 2);     // PEDAÇO: ["café", "código"] (não altera o original)
hobbies.join(", ");      // vira texto: "café, código, música"

Bônus: item aleatório

const sorteado = hobbies[Math.floor(Math.random() * hobbies.length)];
Cuidado — muda ou não muda? push, pop, shift, unshift, sort, reverse e splice alteram o array original. Já map, filter, slice e join devolvem algo novo e deixam o original em paz.

Loops

Repetir uma ação sem copiar e colar.

// for clássico
for (let i = 0; i < 3; i++) {
  console.log(i);   // 0, 1, 2
}

// for...of (percorre uma lista)
for (const hobby of hobbies) {
  console.log(hobby);
}

Objetos

Agrupam dados relacionados em pares chave: valor.

const pessoa = {
  nome: "Nicoly",
  idade: 25,
  dev: true,
};

pessoa.nome;        // "Nicoly"
pessoa.idade = 26;   // alterar
pessoa.cidade = "SP"; // adicionar

Desestruturação e spread

A sintaxe que mais aparece em código de framework. Vale automatizar.

// tirar campos, com apelido e valor padrão
const { titulo, cidade = "Online", organizador: quem } = evento;

// pegar o resto
const { id, ...semId } = evento;

// em array, por posição
const [primeiro, segundo] = eventos;

// direto no parâmetro — o padrão de componente
function Card({ titulo, inicioEm }: Evento) { … }

Spread: copiar mudando

// objeto novo, com um campo diferente
const destacado = { ...evento, destaque: true };

// array novo, com um item a mais
const comNovo = [...eventos, novoEvento];

// juntar dois
const todos = [...gratuitos, ...pagos];
O spread é raso. { ...evento } copia o primeiro nível; objetos aninhados continuam compartilhados com o original. Se precisar de cópia profunda, use structuredClone(evento) — mas na maior parte dos casos, copiar só o nível que você vai mudar é o certo, e é mais rápido.

Métodos de array

MétodoDevolveUse quando
mapArray do mesmo tamanhoTransformar cada item

some / everyboolean"Algum?" / "Todos?"

// encadear é o normal
const proximosGratis = eventos
  .filter((e) => e.gratuito)
  .filter((e) => new Date(e.inicioEm) > new Date())
  .toSorted((a, b) => a.inicioEm.localeCompare(b.inicioEm));

// agrupar por categoria com reduce
const porCategoria = eventos.reduce<Record<string, Evento[]>>(
  (acc, e) => {
    (acc[e.categoria] ??= []).push(e);
    return acc;
  },
  {},
);
Se reduce ficar difícil de ler, use um laço for...of. Legibilidade ganha de elegância. reduce brilha em soma e agrupamento; fora disso, costuma atrapalhar.

Imutabilidade

O conceito mais importante desta aula para o resto do curso.

O problema, concretamente

const lista = ["a", "b"];
const mesma = lista;

lista.push("c");

lista === mesma;      // true — é o MESMO array
mesma.length;         // 3 — mudou sem ninguém pedir

Framework reativo detecta mudança comparando referências: "o valor de antes é o mesmo objeto de agora?" Se for, ele conclui que nada mudou e não redesenha a tela.

Muta — a tela não atualiza

lista.push(novo);
lista.sort();
lista.splice(0, 1);
evento.titulo = "x";

Cria novo — funciona

const l = [...lista, novo];
const l = lista.toSorted();
const l = lista.toSpliced(0, 1);
const e = { ...evento, titulo };

Os métodos que não mutam

Em vez deUse
sort()toSorted()
reverse()toReversed()
splice()toSpliced()
lista[0] = xlista.with(0, x)
push()[...lista, x]
Por que isso aparece hoje e não na aula de Angular. Porque quando o computed() não recalcular na aula 05, você vai ter duas hipóteses: "o Angular está com bug" ou "eu mutei". Sabendo disto, você vai direto na segunda — que é sempre a certa.
Cuidado com o encadeamento. lista.filter(...).sort() é seguro: o filter já criou um array novo, então o sort muta a cópia. Mas lista.sort() direto muta o original. Na dúvida, use sempre toSorted.
No navegador

DOM — controlando o HTML

O DOM é a sua página vista como uma árvore de objetos. Com JavaScript você seleciona um elemento e transforma ele: muda texto, cor, cria coisas novas, apaga... Os exemplos abaixo rodam de verdade — o resultado aparece logo embaixo de cada código.

1. Selecionar elementos

// por seletor de CSS (o mais usado)
const titulo = document.querySelector("h1");      // o primeiro <h1>
const botao  = document.querySelector("#enviar");  // id → #
const cards  = document.querySelectorAll(".card"); // TODOS com a classe → lista

// atalho clássico por id
const caixa = document.getElementById("caixa");
querySelector pega o primeiro que bate. querySelectorAll pega todos numa lista (dá pra usar forEach nela).

2. Ler e mudar conteúdo

titulo.textContent = "Mudei pelo JavaScript!";  // troca o texto
titulo.style.color = "#F24487";                // muda o estilo (CSS)
titulo.style.fontSize = "28px";
resultado
textContent troca só o texto. innerHTML aceita tags HTML (el.innerHTML = "<b>oi</b>") — mas cuidado ao usar com texto que veio do usuário.

3. Mudar classes e atributos

// classes CSS — a forma mais organizada de mudar visual
caixa.classList.add("ativo");      // adiciona
caixa.classList.remove("ativo");   // remove
caixa.classList.toggle("ativo");   // liga/desliga
caixa.classList.contains("ativo"); // tem essa classe? true/false

// atributos
link.setAttribute("href", "https://nickdeve.com");
img.src = "foto.jpg";
input.value;  // o que a pessoa digitou num <input>

4. Criar, inserir e remover elementos

// criar um elemento do zero
const item = document.createElement("li");
item.textContent = "Novo item";

// colocar dentro de outro (no fim)
lista.appendChild(item);

// apagar
item.remove();

Isso combinado com um loop é como se monta uma lista a partir de dados:

const frutas = ["🍎 Maçã", "🍌 Banana", "🍇 Uva"];

frutas.forEach(fruta => {
  const li = document.createElement("li");
  li.textContent = fruta;
  lista.appendChild(li);
});
resultado

5. Reagindo a você (prévia de eventos)

Quando o DOM encontra os eventos, a página fica viva. Estes dois demos são clicáveis / digitáveis — pode brincar:

// contador de curtidas
let curtidas = 0;
botao.addEventListener("click", () => {
  curtidas++;
  contador.textContent = curtidas + " ❤️";
});
resultado clica no botão 👆
// eco do que você digita (evento input)
campo.addEventListener("input", () => {
  saida.textContent = "Oi, " + campo.value + "! 👋";
});
resultado digite algo ⌨️
Resumo dos poderes: textContent/innerHTML (conteúdo) · style (visual direto) · classList (classes CSS) · value (inputs) · createElement/appendChild/remove (criar e apagar) · addEventListener (reagir).

Eventos

Fazem a página reagir: "quando acontecer X, execute Y".

botao.addEventListener("click", () => {
  console.log("Clicou! 🎉");
});

// ler o que o usuário digita, ao vivo
input.addEventListener("input", () => {
  console.log(input.value);
});

Eventos comuns: click, input, submit, mouseover, keydown.

Prática — juntando tudo

Um botão que troca o texto de um parágrafo ao ser clicado:

<!-- HTML -->
<button id="btn">Clique</button>
<p id="msg">Nada ainda...</p>

// JavaScript
const btn = document.querySelector("#btn");
const msg = document.querySelector("#msg");

btn.addEventListener("click", () => {
  msg.textContent = "Você clicou! ✨";
});

JavaScript moderno

Módulos ES

Um arquivo, um assunto. Cada módulo tem escopo próprio: o que você declara ali não vaza para o resto da página.

📄 dados/eventos.ts
export const eventos = [ … ];

export function porSlug(slug: string) {
  return eventos.find((e) => e.slug === slug);
}

// um "principal" por arquivo, se fizer sentido
export default eventos;
📄 main.ts
// nomeados: entre chaves, com o nome exato
import { eventos, porSlug } from "./dados/eventos.js";

// default: sem chaves, e o nome é escolha sua
import lista from "./dados/eventos.js";

// só o tipo — some no build
import type { Evento } from "./dados/tipos.js";

No HTML:

<script type="module" src="main.js"></script>
Sem type="module", o import não existe e o navegador dá erro de sintaxe. Módulo também já vem com defer embutido — ele espera o HTML terminar sozinho, então não precisa colocar o script no fim do <body>.
Por que a extensão .js no import de um arquivo .ts? Porque o import é resolvido em tempo de execução, quando o arquivo já virou .js. É estranho no começo e vira automático depois.

Escopo e closures

const não é imutável

const eventos = [];
eventos.push("a");      // ✓ permitido: o conteúdo mudou
eventos = [];             // ✗ erro: a ligação não pode mudar

const congela a ligação entre o nome e o valor, não o valor. Para um objeto, isso significa que você não pode trocá-lo por outro — mas pode mexer no de dentro à vontade. Guarde isso para a seção de imutabilidade.

Closure

function criarContador() {
  let total = 0;              // vive só aqui dentro
  return {
    incrementar: () => ++total,
    ler: () => total,
  };
}

const c = criarContador();
c.incrementar();
c.ler();                     // 1
// não existe jeito de mexer em "total" por fora
Closure não é curiosidade de entrevista. É o mecanismo de estado privado, e é literalmente como signal() funciona por dentro no Angular. Quando você chamar const total = signal(0) na aula 05, vai estar usando isto.

Arrow e o this

const obj = {
  nome: "Leque",
  normal() { return this.nome; },      // "Leque"  ✓
  seta: () => this.nome,                // undefined ✗
};

Função normal recebe um this que depende de como ela foi chamada. Arrow não tem this próprio — ela usa o de fora, decidido onde foi escrita.

Parece defeito, mas é justamente o que você quer em callback:

class ListaEventos {
  itens: Evento[] = [];

  async carregar() {
    const dados = await buscar();

    dados.forEach((e) => {
      this.itens.push(e);   // "this" ainda é a ListaEventos ✓
    });
  }
}
Regra prática: arrow em callback, método normal em objeto e classe. Você quase nunca vai precisar pensar nisso de novo.

?. e ??

// optional chaining: para e devolve undefined se algo não existir
const cidade = evento?.local?.cidade;
const primeiro = lista?.[0];
callback?.();                    // só chama se existir

// nullish: usa o padrão só quando é null ou undefined
const vagas = evento.vagas ?? "ilimitadas";
A diferença entre || e ?? é fonte de bug sutil. || troca qualquer valor falso — incluindo 0, "" e false:
evento.vagas = 0;

evento.vagas || "ilimitadas";   // "ilimitadas"  ✗ errado!
evento.vagas ?? "ilimitadas";   // 0             ✓ certo

Um evento com zero vagas restantes passa a exibir "ilimitadas". É o tipo de bug que sobrevive meses porque só aparece num caso de borda.

E ??=: (acc[chave] ??= []).push(x) quer dizer "se não existir, crie uma lista vazia; e me devolva ela". Aparece bastante em agrupamento.
Assíncrono

Promise

Um objeto que representa um valor que ainda não chegou. Ele está sempre num de três estados: pendente, resolvido ou rejeitado.

fetch("/dados/eventos.json")
  .then((resposta) => resposta.json())
  .then((eventos) => render(eventos))
  .catch((erro) => mostrarErro(erro))
  .finally(() => esconderCarregando());
Você precisa saber ler .then — ele está em código antigo, em documentação e em resposta de IA. Mas para escrever, a próxima seção é melhor em praticamente todos os casos.

async e await

async function carregarEventos(): Promise<Evento[]> {
  const resposta = await fetch("/dados/eventos.json");
  const eventos = await resposta.json();
  return eventos;
}
  • await = "espere chegar e me dê o valor, não o vale"
  • Só funciona dentro de função async — andam em par
  • Função async sempre devolve uma Promise, mesmo que você retorne um número
O erro de esquecer o await: em vez do valor, você fica com o objeto Promise. O sintoma é [object Promise] na tela, ou undefined ao acessar um campo. Com TypeScript, isso vira erro no editor — mais um motivo pra ligar o strict.
É a mesma dupla que aparece no Next.js lendo dados no servidor, na aula 11. A sintaxe não muda — muda o lugar onde ela roda.

fetch e tratamento de erro

A pegadinha que derruba todo mundo: o fetch só rejeita se a rede falhar. Um 404 ou um 500 chegam como resposta normal, resolvida. Se você não conferir, o .json() tenta interpretar uma página de erro como JSON e falha com uma mensagem incompreensível sobre token inesperado.
async function carregarEventos(): Promise<Evento[]> {
  const resposta = await fetch("/dados/eventos.json");

  // ⚠️ obrigatório
  if (!resposta.ok) {
    throw new Error(`Servidor respondeu ${resposta.status}`);
  }

  return resposta.json();
}

Onde tratar o erro

async function iniciar() {
  mostrarCarregando();
  try {
    const eventos = await carregarEventos();
    eventos.length ? render(eventos) : mostrarVazio();
  } catch (erro) {
    console.error(erro);
    mostrarErro("Não consegui carregar os eventos.");
  } finally {
    esconderCarregando();
  }
}
Quem busca lança; quem desenha decide o que mostrar. A função de dados não deveria mexer na tela — ela lança o erro e deixa quem chamou escolher a mensagem. Essa separação é a mesma que você vai usar com services no Angular.
Três estados, sempre. Toda tela que busca dados tem carregando, erro e vazio — além do caso feliz. Esquecer o vazio é o mais comum: uma busca sem resultado que mostra apenas uma área em branco parece site quebrado. Isso está na rubrica.

Vários pedidos

Em série — lento

const a = await buscar(1);
const b = await buscar(2);
// 300ms + 300ms

Em paralelo — rápido

const [a, b] = await Promise.all([
  buscar(1), buscar(2),
]);
// 300ms no total
MétodoComportamento
Promise.allFalha inteiro se um falhar
Promise.allSettledEspera todos e diz o que deu certo e o que não
Promise.raceDevolve o primeiro que terminar
Só use paralelo quando forem independentes. Se o segundo pedido precisa do resultado do primeiro, a fila é obrigatória — e tentar paralelizar aí só gera bug.

O laço de eventos

JavaScript tem uma fila de execução. Enquanto uma função roda, nada mais acontece: nem clique, nem rolagem, nem animação.

Não trava a tela

Esperar rede, timer, leitura de arquivo. Quem está esperando é o navegador, não o seu código — a fila fica livre.

Trava a tela

Laço de 10 milhões de voltas, ordenar 500 mil itens, JSON.parse de 40 MB. Aqui o seu código está ocupando a fila.

A conclusão que importa: await não deixa nada mais rápido. Ele só libera a vez enquanto a resposta não chega. Se a sua página travar, procure processamento pesado — não chamada de rede.
Ordem que surpreende: uma Promise já resolvida roda antes de um setTimeout(…, 0). São filas de prioridade diferentes. Não precisa decorar — só não se assuste quando acontecer.
Ferramentas

Node & npm

Calma: pro desafio de hoje você não precisa disto — tudo roda no navegador. Esta parte é um mapa do que vem nas próximas aulas, quando os projetos crescem.

Por que sair do navegador?

Até agora o JavaScript rodou dentro do navegador. O Node.js é um programa que roda JavaScript fora dele — no seu computador, direto no terminal. É o que permite usar ferramentas, servidores e projetos maiores (tipo o próprio site de vocês, feito em Next.js 👀).

1. Instalar o Node

Baixe a versão LTS em nodejs.org e instale (é só avançar). Depois, confira no terminal:

# mostra a versão instalada (se aparecer um número, deu certo)
node -v
npm -v

O npm (Node Package Manager) já vem junto com o Node. É ele que baixa e organiza os "pacotes" (códigos prontos de outras pessoas).

2. Começar um projeto

# cria o package.json (a "carteira de identidade" do projeto)
npm init -y

# instala um pacote (ex.: a biblioteca de datas)
npm install dayjs
  • package.json — lista o nome do projeto, os scripts e as dependências.
  • node_modules/ — pasta onde o npm guarda os pacotes baixados. Nunca se mexe nela na mão (e não sobe pro Git).
  • package-lock.json — trava as versões exatas, pra funcionar igual na máquina de todo mundo.

3. Rodar comandos (scripts)

No package.json você define atalhos na parte "scripts" e roda com npm run:

// dentro do package.json
"scripts": {
  "dev": "next dev"
}

# no terminal:
npm run dev
Você já viu isso! É exatamente assim que o site da NickDev roda: npm install pra baixar tudo e npm run dev pra ligar.

Erros comuns 🔧

Cannot use import statement outside a module

Faltou type="module" no <script>.

CORS / origem nula ao usar fetch

Você abriu o HTML com duplo clique (file://). Módulos e fetch exigem um servidor: use a extensão Live Server do VS Code ou npx serve.

Unexpected token '<' in JSON

O fetch recebeu HTML (uma página de 404) e tentou interpretar como JSON. Faltou if (!resposta.ok).

Apareceu [object Promise] na tela

Faltou await. E confira se a função tem async.

Mudei a lista e a tela não atualizou

Você mutou. push, sort, splice mantêm a mesma referência. Use [...lista, x] ou toSorted().

O valor 0 sumiu / virou o padrão

|| troca qualquer valor falso. Use ??.

this é undefined dentro do callback

Você usou function onde cabia arrow. Troque por () =>.
