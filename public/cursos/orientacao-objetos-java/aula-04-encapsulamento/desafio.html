Livro encapsulado 🔒

Pegue a classe Livro que você criou na aula 03 e feche ela por dentro: atributos privados, getters e setters que validam, o this resolvendo nomes repetidos, dois construtores (um chamando o outro) e um contador que sobrevive entre objetos.

🎯

O objetivo

Provar que você sabe transformar uma classe "aberta" numa classe encapsulada de verdade — sem perder nenhum comportamento, só ganhando proteção. São seis coisas:

  1. Todos os atributos de Livro viram private
  2. Um getter por atributo (get.../is...) e setters com validação
  3. Uso correto de this nos setters e no construtor
  4. Dois construtores, o menor chamando o maior com this(...)
  5. Um método sobrecarregado (mesmo nome, parâmetros diferentes)
  6. Um contador static de livros criados + uma constante static final
📖

Travou numa palavra?

Encapsulamento, getter, setter, this, sobrecarga, static, final — todo esse vocabulário está no guia de Java, na seção desta aula, em português simples e com exemplos.

Passo a passo
01

Feche os atributos

Troque todos os atributos de Livro (título, autor, preço, emprestado...) para private. Tente compilar seu código antigo — ele deve quebrar em todo lugar que acessava um atributo direto (ex.: livro.preco = 10). É esperado: é exatamente isso que vamos consertar nos próximos passos.

public class Livro {
  private String titulo;
  private String autor;
  private double preco;
  private boolean emprestado;
}
02

Getters e setters validados

Escreva um getter pra cada atributo. Nos setters, recuse valores inválidos lançando IllegalArgumentException — pelo menos em setPreco (não aceita negativo) e setTitulo (não aceita vazio):

public void setPreco(double preco) {
  if (preco < 0) {
    throw new IllegalArgumentException("Preço não pode ser negativo");
  }
  this.preco = preco;
}

Repare no this.preco: o parâmetro e o atributo têm o mesmo nome de propósito — é o cenário exato em que this deixa de ser opcional.

03

Dois construtores, um chamando o outro

Mantenha o construtor com os três parâmetros (título, autor, preço) e crie um segundo, só com título e autor, que chama o primeiro passando um preço padrão via this(...):

public Livro(String titulo, String autor, double preco) {
  this.titulo = titulo;
  this.autor = autor;
  setPreco(preco);   // reaproveita a validação
  this.emprestado = false;
  totalDeLivros++;
}

public Livro(String titulo, String autor) {
  this(titulo, autor, PRECO_MINIMO);   // tem que ser a 1ª linha
}

Por que reaproveitar com setPreco? Se você repetir a validação em cada construtor, algum dia alguém muda a regra num lugar e esquece do outro. Chamando o setter, a regra mora num lugar só.

04

Um método sobrecarregado

Escreva calcularDesconto(double percentual) e uma versão sem parâmetro que aplica um desconto padrão chamando a primeira:

public double calcularDesconto(double percentual) {
  return preco - (preco * percentual / 100);
}

public double calcularDesconto() {
  return calcularDesconto(10);  // 10% padrão
}
05

Contador static + constante final

Some um atributo static que conta quantos Livro já foram criados (incremente dentro dos construtores) e uma constante static final pro preço mínimo:

private static int totalDeLivros = 0;
public static final double PRECO_MINIMO = 0.0;

public static int getTotalDeLivros() {
  return totalDeLivros;
}
06

Teste tudo numa classe TesteLivro

Crie TesteLivro.java com main: instancie pelo menos dois livros (usando os dois construtores diferentes), chame o método sobrecarregado dos dois jeitos, imprima o total com Livro.getTotalDeLivros() e tente um setPreco(-10) dentro de um try/catch pra ver a exceção sendo barrada:

$ java TesteLivro Duna — R$ 89.9 — total de livros: 1 1984 — R$ 0.0 — total de livros: 2 Desconto padrão de Duna: R$ 80.91 Tentativa de preço negativo bloqueada: Preço não pode ser negativo

Ainda não é try/catch "de verdade": tratamento de exceções completo é assunto da aula 09. Por enquanto, um try { ... } catch (IllegalArgumentException e) { System.out.println(e.getMessage()); } simples já mostra que a validação está funcionando.

Requisitos mínimos
  • Todos os atributos de Livro são private
  • Um getter por atributo, e setters que validam (pelo menos preço e título)
  • this usado corretamente nos setters e no construtor
  • Dois construtores, o mais curto chamando o mais longo com this(...)
  • Um método sobrecarregado (dois calcularDesconto com parâmetros diferentes)
  • Um contador static de objetos criados + uma constante static final
  • TesteLivro.java com main demonstrando tudo isso rodando
Desafios extras (pra quem quer brilhar ✨)
  • Adicione validação também em setTitulo (não aceitar título vazio) e em setAutor
  • Crie um terceiro construtor sobrecarregado (ex.: recebendo também a quantidade de exemplares)
  • Adicione um método emprestar(int dias) sobrecarregado ao lado de emprestar() (sem parâmetro), guardando o prazo
  • Pesquise a diferença entre private e protected — qual dos dois você usaria se, na aula 06, criasse uma classe LivroDigital extends Livro?
