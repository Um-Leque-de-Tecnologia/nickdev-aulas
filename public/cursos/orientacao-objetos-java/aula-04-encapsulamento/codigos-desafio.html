✅ Solução comentada

1 · Atributos private

Primeiro passo: fechar tudo. Depois disso o código antigo que acessava livro.preco direto vai parar de compilar — é esperado.

private String titulo;
private String autor;
private double preco;
private boolean emprestado;

2 · Getters e setters validados ★

O ponto-chave do desafio: setters que recusam valores inválidos, e o this distinguindo o atributo do parâmetro de mesmo nome.

public String getTitulo() { return titulo; }
public String getAutor() { return autor; }
public double getPreco() { return preco; }
public boolean isEmprestado() { return emprestado; }

public void setTitulo(String titulo) {
  if (titulo == null || titulo.isBlank()) {
    throw new IllegalArgumentException("Título não pode ser vazio");
  }
  this.titulo = titulo;
}

public void setPreco(double preco) {
  if (preco < PRECO_MINIMO) {
    throw new IllegalArgumentException("Preço não pode ser negativo");
  }
  this.preco = preco;
}

Repare: sem this, a linha preco = preco dentro de setPreco falaria com o próprio parâmetro — o atributo nunca mudaria. this.preco deixa explícito "o atributo deste objeto".

3 · Construtores + this(...)

O construtor mais completo faz o trabalho de verdade — inclusive chamando os próprios setters, pra não duplicar a validação. O mais curto só repassa um valor padrão.

public Livro(String titulo, String autor, double preco) {
  setTitulo(titulo);
  this.autor = autor;
  setPreco(preco);
  this.emprestado = false;
  totalDeLivros++;
}

public Livro(String titulo, String autor) {
  this(titulo, autor, PRECO_MINIMO);
}
Regra do this(...): só pode aparecer na primeira linha do construtor, e um construtor não pode chamar this(...) mais de uma vez.

4 · Método sobrecarregado

Dois métodos com o mesmo nome, mas assinaturas diferentes (o número/tipo dos parâmetros muda). O Java escolhe qual chamar pelos argumentos que você passa — isso não tem nada a ver com o if.

public double calcularDesconto(double percentual) {
  return preco - (preco * percentual / 100);
}

public double calcularDesconto() {
  return calcularDesconto(10);
}

5 · static + final

totalDeLivros é uma única cópia, compartilhada por todos os objetos Livro — por isso ela mora fora de qualquer construtor, e o construtor só faz totalDeLivros++. PRECO_MINIMO é static (uma cópia, da classe) e final (nunca muda depois de definida).

private static int totalDeLivros = 0;
public static final double PRECO_MINIMO = 0.0;

public static int getTotalDeLivros() {
  return totalDeLivros;
}

Chama-se pela classe, sem precisar de nenhum objeto: Livro.getTotalDeLivros().

6 · Livro.java completo

public class Livro {
  private String titulo;
  private String autor;
  private double preco;
  private boolean emprestado;

  private static int totalDeLivros = 0;
  public static final double PRECO_MINIMO = 0.0;

  public Livro(String titulo, String autor, double preco) {
    setTitulo(titulo);
    this.autor = autor;
    setPreco(preco);
    this.emprestado = false;
    totalDeLivros++;
  }

  public Livro(String titulo, String autor) {
    this(titulo, autor, PRECO_MINIMO);
  }

  public String getTitulo() { return titulo; }
  public String getAutor() { return autor; }
  public double getPreco() { return preco; }
  public boolean isEmprestado() { return emprestado; }

  public void setTitulo(String titulo) {
    if (titulo == null || titulo.isBlank()) {
      throw new IllegalArgumentException("Título não pode ser vazio");
    }
    this.titulo = titulo;
  }

  public void setPreco(double preco) {
    if (preco < PRECO_MINIMO) {
      throw new IllegalArgumentException("Preço não pode ser negativo");
    }
    this.preco = preco;
  }

  public void emprestar() { emprestado = true; }
  public void devolver() { emprestado = false; }

  public double calcularDesconto(double percentual) {
    return preco - (preco * percentual / 100);
  }

  public double calcularDesconto() {
    return calcularDesconto(10);
  }

  public static int getTotalDeLivros() { return totalDeLivros; }
}

7 · TesteLivro.java

Uma classe separada, só com main, pra provar que tudo funciona de fora:

public class TesteLivro {
  public static void main(String[] args) {
    Livro duna = new Livro("Duna", "Herbert", 89.90);
    Livro orwell = new Livro("1984", "Orwell");  // construtor sobrecarregado

    System.out.println(duna.getTitulo() + " — R$ " + duna.getPreco() + " — total de livros: " + Livro.getTotalDeLivros());
    System.out.println(orwell.getTitulo() + " — R$ " + orwell.getPreco() + " — total de livros: " + Livro.getTotalDeLivros());

    System.out.println("Desconto padrão de Duna: R$ " + duna.calcularDesconto());
    System.out.println("Desconto de 25% de Duna: R$ " + duna.calcularDesconto(25));

    try {
      duna.setPreco(-10);
    } catch (IllegalArgumentException e) {
      System.out.println("Tentativa de preço negativo bloqueada: " + e.getMessage());
    }
  }
}

8 · Erros comuns

error: preco has private access in Livro

Algum código de fora (inclusive um teste antigo) ainda tenta acessar livro.preco direto. Troque pelo getter/setter correspondente.

error: constructor Livro in class Livro cannot be applied to given types

Você chamou new Livro(...) com uma combinação de parâmetros que não bate com nenhum dos construtores sobrecarregados. Confira quantos e quais argumentos cada um espera.

error: call to this must be first statement in constructor

this(...) só pode ser a primeira linha do construtor — nem um comentário antes tudo bem, mas nenhuma outra instrução.

error: cannot assign a value to final variable PRECO_MINIMO

Alguma linha tentou reatribuir a constante depois de criada. Constantes final recebem valor uma vez só.
