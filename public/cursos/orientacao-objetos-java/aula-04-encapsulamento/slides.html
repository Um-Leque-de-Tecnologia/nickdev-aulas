// lembrando da aula 03

O Livro que vocês construíram

Uma classe com atributos e um construtor — abstração e instanciação já funcionando:

public class Livro { String titulo; String autor; double preco; boolean emprestado; Livro(String titulo, String autor, double preco) { titulo = titulo; // hmm... autor = autor; preco = preco; emprestado = false; } }

Repare no comentário — já tem um bug escondido aí. A gente conserta ele daqui a pouco com this.

o problema de hoje · atributos abertos

Todo mundo pode mexer em tudo

Como titulo, autor, preco e emprestado não têm nenhuma proteção, qualquer código de fora acessa e altera direto:

Livro duna = new Livro("Duna", "Herbert", 89.90); duna.preco = -50; // preço negativo?! nada impede duna.emprestado = true; // "emprestado" sem passar pelo método emprestar() duna.titulo = ""; // título vazio também passa

O objeto não tem como se defender. Qualquer parte do sistema pode deixá-lo num estado que não devia existir.

a solução · encapsulamento

Esconder por dentro, controlar por fora

Painel elétrico do carro

Ninguém deveria enfiar a mão nos fios direto. É perigoso e fácil de quebrar algo.

Volante, pedal, botão

Você usa controles que o carro expõe. Por trás, ele decide como executar aquilo com segurança.

Encapsulamento é isso em código: os atributos ficam escondidos (private) e o objeto expõe só os "controles" — métodos — que garantem que o estado interno nunca fica inválido.

modificadores de acesso · quem pode ver o quê

public, private, protected

private

Só a própria classe enxerga. É o padrão pra atributos.

protected

A classe e suas subclasses (herança — aula 06). Por enquanto, guarde o nome.

public

Qualquer código enxerga. É o padrão pra métodos que formam o "controle remoto" da classe.

Regra prática desta aula: atributos privados, métodos públicos.

passo 1 · fechando os atributos

Livro com atributos private

public class Livro { private String titulo; private String autor; private double preco; private boolean emprestado; // ... construtor e métodos aqui }
Livro duna = new Livro("Duna", "Herbert", 89.90); duna.preco = -50; // erro de compilação: preco has private access

Ótimo — agora ninguém de fora acessa direto. Só que também ninguém consegue ler o título ou o preço. Precisamos abrir uma porta controlada.

passo 2 · abrindo uma porta pra leitura

Getters: método pra ler

Um método público que devolve o valor de um atributo privado. Convenção: get + nome do atributo (ou is pra boolean):

public String getTitulo() { return titulo; } public double getPreco() { return preco; } public boolean isEmprestado() { return emprestado; }

Uso: duna.getTitulo() — lê o valor sem nunca tocar direto no atributo.

passo 3 · abrindo uma porta pra escrita, com regra

Setters: método pra escrever

Convenção: set + nome do atributo. A vantagem sobre um atributo público: dá pra validar antes de aceitar o valor.

public void setPreco(double preco) { if (preco < 0) { throw new IllegalArgumentException("Preço não pode ser negativo"); } // this.preco: o da esquerda; preco: o parâmetro. já já a gente explica. this.preco = preco; }

Agora duna.setPreco(-50) não corrompe o objeto — ele reclama antes.

a palavra-chave · this

Resolvendo o nome duplicado

No setter, o parâmetro se chama preco — igualzinho ao atributo. Sem ajuda, o Java entende os dois como a mesma variável, o parâmetro, e o atributo nunca é atualizado:

Sem this

void setPreco(double preco) {
  preco = preco; // fala consigo mesmo,
}                // o atributo não muda

Com this

void setPreco(double preco) {
  this.preco = preco; // atributo
}                      // = parâmetro

this é uma referência ao próprio objeto que está executando o método. this.preco é sempre o atributo; preco sozinho, dentro do método, é o parâmetro.

voltando ao slide 2 · o bug do construtor

Consertando com this

Livro(String titulo, String autor, double preco) { this.titulo = titulo; // this.titulo (atributo) = titulo (parâmetro) this.autor = autor; setPreco(preco); // reaproveita a validação do setter! this.emprestado = false; }

Chamar setPreco(preco) dentro do construtor, em vez de atribuir direto, garante que a mesma regra vale tanto na criação quanto em qualquer troca de preço depois.

construtores · a receita de como nascer

O construtor padrão

Se você não escrever nenhum construtor, o Java cria um vazio, sem parâmetros, de graça:

public class Livro { private String titulo; // nenhum construtor escrito... } // ...então isto compila, usando o construtor padrão implícito: Livro l = new Livro();

Assim que você escreve qualquer construtor próprio, o padrão implícito desaparece — se ainda quiser um sem parâmetros, precisa escrevê-lo você mesma(o).

sobrecarga de construtores · vários jeitos de nascer

Dois construtores, mesma classe

Às vezes você ainda não sabe o preço na hora de cadastrar. Em vez de obrigar todo mundo a passar 0.0 na mão, oferecemos um segundo construtor:

Livro(String titulo, String autor, double preco) { this.titulo = titulo; this.autor = autor; setPreco(preco); this.emprestado = false; } // sobrecarga: mesmo nome (Livro), lista de parâmetros diferente Livro(String titulo, String autor) { this(titulo, autor, 0.0); // this(...) chama o outro construtor }

Sobrecarga (overload) = mesmo nome de método/construtor, mas parâmetros diferentes (quantidade ou tipo). O Java escolhe qual usar pela lista de argumentos que você passa.

// this(...) em detalhe

Um construtor pode chamar outro

this(titulo, autor, 0.0) tem que ser a primeira linha do construtor. Evita repetir a mesma lógica de inicialização em dois lugares.

sobrecarga de métodos · a mesma ideia, em métodos comuns

calcularDesconto de dois jeitos

public double calcularDesconto(double percentual) { return preco - (preco * percentual / 100); } // sobrecarga: sem parâmetro, usa um desconto padrão public double calcularDesconto() { return calcularDesconto(10); // 10% padrão }

duna.calcularDesconto() e duna.calcularDesconto(25) chamam métodos diferentes — o Java decide qual pelos parâmetros.

membros static · pertence à classe, não ao objeto

Um contador compartilhado

Todo atributo comum é por objeto — cada Livro tem seu próprio titulo. Um atributo static existe uma vez só, compartilhado por todos os objetos da classe:

private static int totalDeLivros = 0; // uma cópia só, da classe Livro(String titulo, String autor, double preco) { // ... totalDeLivros++; // todo Livro criado soma no mesmo contador } public static int getTotalDeLivros() { return totalDeLivros; }

Método static também: chama-se pela classe, sem precisar de objeto — Livro.getTotalDeLivros().

// lembra da aula 01?

Por isso o main é static

A JVM chama main antes de qualquer objeto existir. Sem static, precisaria de um objeto pra chamar o método — e não existe nenhum ainda.

constantes · final

Valor que nunca muda

final numa variável trava o valor depois da primeira atribuição. Combinado com static, vira uma constante da classe — convenção: nome todo em maiúsculas:

public static final double PRECO_MINIMO = 0.0; public void setPreco(double preco) { if (preco < PRECO_MINIMO) { throw new IllegalArgumentException("Preço não pode ser negativo"); } this.preco = preco; } PRECO_MINIMO = 5.0; // erro de compilação: cannot assign a value to final variable

Uma constante nomeada é mais clara que um número solto no meio do código (o famoso "número mágico") — e o compilador impede qualquer tentativa de mudá-la depois.

recap · o Livro encapsulado, por inteiro

Tudo junto

public class Livro { private String titulo; private String autor; private double preco; private boolean emprestado; private static int totalDeLivros = 0; public static final double PRECO_MINIMO = 0.0; public Livro(String titulo, String autor, double preco) { this.titulo = titulo; this.autor = autor; setPreco(preco); this.emprestado = false; totalDeLivros++; } public Livro(String titulo, String autor) { this(titulo, autor, PRECO_MINIMO); } public String getTitulo() { return titulo; } public double getPreco() { return preco; } public boolean isEmprestado() { return emprestado; } public void setPreco(double preco) { if (preco < PRECO_MINIMO) throw new IllegalArgumentException("Preço não pode ser negativo"); this.preco = preco; } public void emprestar() { emprestado = true; } public void devolver() { emprestado = false; } public static int getTotalDeLivros() { return totalDeLivros; } }
desafio · sua vez

Encapsule a sua classe

  • Atributos private, getters e setters com validação
  • Dois construtores, um chamando o outro com this(...)
  • Um método sobrecarregado
  • Um contador static + uma constante final

Por quê?

Encapsulamento é a base dos outros três pilares de OO — sem ele, herança e polimorfismo (aulas 06 e 07) ficam bem mais frágeis.
