Lembra da pergunta do primeiro dia?

"Como você organizaria o código de um sistema de biblioteca?" A gente respondeu com uma metáfora — o cartãozinho com nome, telefone e aniversário juntos — e mostrou um Livro em Python e em Java. Mas você nunca escreveu um objeto de verdade com a sua própria mão.

Hoje muda isso. E olha só: vamos resolver essa mesma pergunta da biblioteca — só que agora de verdade, no desafio do fim da aula.

o conceito central · classe × objeto

Uma forma de bolo não é um bolo

Classe

O molde. Descreve o que todo livro tem (título, autor, ano) e o que todo livro faz (ser emprestado, ser devolvido). Não é um livro específico — é a receita de "como é um livro".

Objeto

Um livro de verdade, feito a partir daquele molde. "Duna", de Frank Herbert, publicado em 1965, disponível. De uma classe só, você tira quantos objetos quiser.

É a mesma ideia da aula 01, só que agora você vai escrever a classe e criar os objetos — não só ler o exemplo pronto.

sintaxe · o molde vazio

Criando a classe Livro

class Livro { // por enquanto, vazia }

Isso já compila. É um molde sem nada dentro — ainda não descreve nenhuma informação nem nenhuma ação. Vamos preencher, uma peça de cada vez.

dentro da classe · atributos

Atributos: o que um Livro tem

Atributos são variáveis que moram dentro da classe. Cada objeto criado a partir dela vai ter o seu próprio valor pra cada uma:

class Livro { String titulo; String autor; int anoPublicacao; boolean disponivel; }

Repare: é exatamente a mesma sintaxe de declarar uma variável (tipo nome;) que você já usa desde a aula 02 — só que agora ela mora dentro da classe, não solta dentro de um main.

dentro da classe · métodos

Métodos: o que um Livro faz

Métodos são ações que o objeto sabe executar — geralmente usando os próprios atributos dele:

class Livro { String titulo; String autor; int anoPublicacao; boolean disponivel; void mostrarFicha() { System.out.println(titulo + " — " + autor + " (" + anoPublicacao + ")"); } }

Dentro do método, titulo, autor e anoPublicacao não precisam de nenhum prefixo — o método já sabe que está falando dos atributos do próprio objeto que o chamou.

criando objetos · a palavra-chave new

Do molde ao livro de verdade

Livro duna = new Livro();

Livro

O tipo da variável — que classe de objeto ela vai guardar.

duna

O nome que você escolheu pra essa variável.

new Livro()

A ordem "cria um Livro agora". É esse new que efetivamente fabrica o objeto na memória.

Isso se chama instanciar a classe — criar uma instância (um objeto) dela. Sem new, nenhum objeto é criado — só existe o molde.

usando o objeto · o ponto (.)

Preenchendo e chamando

Livro duna = new Livro(); duna.titulo = "Duna"; duna.autor = "Frank Herbert"; duna.anoPublicacao = 1965; duna.disponivel = true; duna.mostrarFicha(); // Duna — Frank Herbert (1965)

O ponto (.) é o operador de acesso: objeto.atributo pra ler/escrever um dado, objeto.metodo() pra executar uma ação.

// o que a variável guarda, de verdade

A variável não é o objeto

Diferente de um int, a variável duna não guarda o objeto Livro dentro dela. Ela guarda uma referência — o "caminho" até onde o objeto mora na memória.

Um int é uma caixa com o valor dentro. Uma referência é mais como o endereço escrito num papel — ela aponta pra onde o valor está, sem ser o valor.

cuidado com isso · duas variáveis, um objeto só

Copiar a referência não copia o objeto

Livro duna = new Livro(); duna.titulo = "Duna"; Livro copia = duna; // NÃO cria outro livro copia.titulo = "Outro nome"; System.out.println(duna.titulo); // "Outro nome" — mudou os dois!

copia = duna copiou a referência, não o livro. As duas variáveis apontam pro mesmíssimo objeto — mexer por uma mexe pela outra também.

referências · quando não aponta pra nada

O valor null

Livro proximo; // declarada, mas sem new System.out.println(proximo); // null

Enquanto um int sem valor não existe em Java (o compilador não deixa usar), uma referência sem new assume um valor especial: null — "não aponta pra objeto nenhum".

null só existe pra tipos de referência (classes, como Livro e String). Um int, double ou boolean nunca pode ser null.

cuidado com isso · o erro mais famoso do Java

NullPointerException

Livro proximo = null; proximo.mostrarFicha(); // 💥 explode em tempo de execução
$ java Teste
Exception in thread "main" java.lang.NullPointerException

Chamar um método em cima de null é pedir pro Java falar com um objeto que não existe. Sempre que usar uma referência que pode não ter sido preenchida, pergunte: isso pode estar null aqui?

comunicação entre objetos · parâmetros

Métodos que recebem informação

class Livro { // ...atributos... void emprestarPara(String nomeDoLeitor) { disponivel = false; System.out.println(titulo + " foi emprestado para " + nomeDoLeitor); } } duna.emprestarPara("Nicoly"); // "Nicoly" é o argumento

nomeDoLeitor é o parâmetro — a variável que existe só durante a execução do método, recebendo o valor de fora. "Nicoly", no momento da chamada, é o argumento.

comunicação entre objetos · retorno

void × devolver um valor

boolean emprestar() { if (disponivel) { disponivel = false; return true; } return false; } boolean deuCerto = duna.emprestar(); // guarda o retorno

void quer dizer "esse método não devolve nada". Quando ele devolve algo, o tipo antes do nome do método (aqui, boolean) precisa bater com o que vem depois de return.

// uma classe pode conhecer outra

A classe Leitor

class Leitor { String nome; Livro livroAtual; // referência — começa null }

Um atributo não precisa ser um tipo primitivo ou String — pode ser outro objeto seu, como Livro. É assim que classes começam a se conectar formando um domínio.

live code · Livro e Leitor conversando

Um objeto como parâmetro

class Leitor { String nome; Livro livroAtual; boolean pegarEmprestado(Livro livro) { if (livro.disponivel) { livro.disponivel = false; livroAtual = livro; return true; } return false; } void devolverLivro() { if (livroAtual != null) { livroAtual.disponivel = true; livroAtual = null; } } }

Repare o parâmetro Livro livro: um método pode receber um objeto inteiro como argumento, não só números e textos. E devolverLivro() confere != null antes de mexer — exatamente pra evitar a explosão do slide 14.

modelagem · um primeiro diagrama de classes

Duas classes, num desenho

┌─────────────────────────┐ ┌─────────────────────────┐ │ Livro │ │ Leitor │ ├─────────────────────────┤ ├─────────────────────────┤ │ titulo: String │ │ nome: String │ │ autor: String │ │ livroAtual: Livro │ │ anoPublicacao: int │ └─────────────────────────┘ │ disponivel: boolean │ │ ├─────────────────────────┤ │ conhece um Livro │ emprestar(): boolean │◄─────────────────────┘ │ devolver(): void │ │ mostrarFicha(): void │ └─────────────────────────┘

Nada de UML chique por enquanto: só caixas com nome, atributos e métodos, e uma linha mostrando quem conhece quem. Isso já é um diagrama de classes de verdade.

modelagem · um método simples pra achar as classes

Substantivo, verbo, característica

Substantivos → classes

"Um leitor pega um livro emprestado" → duas classes candidatas: Leitor e Livro.

Verbos → métodos

"Pega emprestado", "devolve" → viram pegarEmprestado(), devolver().

Características → atributos

Nome do leitor, título do livro, se está disponível → viram os atributos de cada classe.

Não existe fórmula mágica nem resposta única — modelagem é sobre fazer escolhas razoáveis e conseguir explicar por quê. Isso vai ficar mais afiado a cada aula.
