Classes e objetos

A diferença entre classe e objeto, o que são atributos e métodos, como criar objetos com new, o que de fato uma variável guarda (referências), o que é null, e como um objeto conversa com outro através de parâmetros e retorno. Fecha com um primeiro diagrama de classes.

📖 Perdida(o) numa palavra? Comece pelo dicionário desta aula — todo termo técnico traduzido pra português normal.

O dicionário desta aula

Hoje o vocabulário de orientação a objetos deixa de ser só teoria e vira coisa que você escreve. Volte aqui sempre que precisar — consultar dicionário não é trapaça, é o que todo mundo que programa faz o dia inteiro.

Classe × objeto

A pergunta que ficou em aberto

Na aula 01 a gente perguntou: "como você organizaria o código de um sistema de biblioteca?" — e respondeu com uma metáfora: um cartãozinho por pessoa, com nome, telefone e aniversário juntos, em vez de três listas separadas. Você viu um Livro em Python e depois em Java, mas só como leitura. Hoje você escreve o seu.

Uma forma de bolo não é um bolo

Pense numa forma de fazer bolo em formato de coração. A forma descreve o formato que todo bolo feito nela vai ter — mas a forma em si não é um bolo, não dá pra comer ela. Cada vez que você usa a forma com massa de verdade, sai um bolo de verdade, comestível, que existe fisicamente.

  • A classe é a forma: descreve o que todo objeto daquele tipo vai ter (atributos) e fazer (métodos).
  • O objeto é o bolo: uma coisa concreta, com valores reais em cada atributo, existindo na memória do programa enquanto ele roda.

De uma classe só, você tira quantos objetos quiser — assim como de uma forma só você assa vários bolos. Cada um deles é independente: mudar o título de um Livro não muda o título de outro.

Uma classe, muitos objetos: a classe Livro existe uma vez só no seu código-fonte. Mas em tempo de execução, o seu programa pode ter cinco, cem, mil objetos Livro diferentes ao mesmo tempo — cada um com seu próprio título, autor e situação de empréstimo.

Onde vive uma classe em Java

Uma classe começa vazia — um molde sem nada dentro ainda:

class Livro {
  // por enquanto, vazia
}

Isso já compila. É só um tipo novo que o Java passa a conhecer, sem nenhuma informação nem comportamento definidos ainda. As próximas duas seções preenchem essa classe.

Atributos

Atributos são variáveis que moram dentro da classe, fora de qualquer método. Cada objeto criado a partir da classe tem o seu próprio valor pra cada atributo — é o que faz um Livro ser diferente do outro.

class Livro {
  String titulo;
  String autor;
  int anoPublicacao;
  boolean disponivel;
}

A sintaxe é a mesma de declarar uma variável comum (tipo nome;), que você já usa desde a aula 02. A única diferença de posição: ela mora dentro da classe, não solta dentro de um main.

Sem valor inicial, tudo bem. Atributos declarados sem = valor recebem um valor padrão automaticamente: 0 para números, false para boolean, e null para tipos como String. Isso é diferente de uma variável local (dentro de um método), que o Java obriga você a inicializar antes de usar.

Métodos

Métodos são as ações que um objeto sabe executar — normalmente lendo ou alterando os próprios atributos dele.

class Livro {
  String titulo;
  String autor;
  int anoPublicacao;
  boolean disponivel;

  void mostrarFicha() {
    System.out.println(titulo + " — " + autor + " (" + anoPublicacao + ")");
  }
}

Dentro do método, titulo, autor e anoPublicacao não precisam de nenhum prefixo — o método já sabe que está lendo os atributos do objeto que o chamou. Isso só funciona porque o método vive dentro da mesma classe que declara esses atributos.

Atributo × variável local. Um atributo é declarado direto na classe e existe enquanto o objeto existir. Uma variável local é declarada dentro de um método (ou dentro do main) e só existe enquanto aquele método está rodando — depois, ela some.

Instanciação com new

Ter a classe pronta não cria nenhum objeto — é só o molde. Pra fabricar um objeto de verdade, você usa a palavra-chave new:

Livro duna = new Livro();
ParteO que é
Livro (1ª vez)O tipo da variável — que classe de objeto ela vai guardar.
dunaO nome que você escolheu pra essa variável.
new Livro()A ordem "crie um Livro agora". É esse new que de fato fabrica o objeto na memória.

Esse ato de criar um objeto a partir de uma classe se chama instanciar a classe — e o objeto resultante é chamado de instância. "Uma instância de Livro" e "um objeto Livro" significam a mesma coisa.

Preenchendo e usando

Com o objeto criado, você acessa atributos e chama métodos usando o operador ponto (.):

Livro duna = new Livro();

duna.titulo = "Duna";
duna.autor = "Frank Herbert";
duna.anoPublicacao = 1965;
duna.disponivel = true;

duna.mostrarFicha(); // Duna — Frank Herbert (1965)

objeto.atributo lê ou escreve um dado; objeto.metodo() executa uma ação. Repare que só existe um Livro aqui — quer mais um, é só chamar new de novo, guardando numa variável diferente.

Sem construtor, de propósito. A classe Livro da aula 01 tinha um construtor (Livro(String nome) { ... }), que deixava criar o objeto já com o título pronto: new Livro("Duna"). Hoje a gente não usa construtor ainda — criamos com new Livro() vazio e preenchemos atributo por atributo, na mão. Construtor de verdade, com toda a lógica de "nascer já pronto", é conteúdo da aula 04, junto com encapsulamento.

Referências e null

A variável não é o objeto

Isso é o pulo do gato de hoje. Diferente de um int — que guarda o número dentro da própria variável — uma variável de tipo classe, como Livro duna, guarda uma referência: o "caminho" até onde o objeto realmente mora, na memória.

Livro duna ─────► objeto Livro { titulo: "Duna", autor: "Frank Herbert", ... } (a variável) (os dados de verdade vivem aqui)

Pense num int como uma caixa com o valor dentro dela. Uma referência é mais como um endereço escrito num papel — ela aponta pra onde o valor está, sem ser o valor.

Cuidado com isso: copiar a referência não copia o objeto

Livro duna = new Livro();
duna.titulo = "Duna";

Livro copia = duna; // NÃO cria outro livro
copia.titulo = "Outro nome";

System.out.println(duna.titulo); // "Outro nome" — mudou os dois!
duna
copia
↘  ↙
Livro titulo: "Outro nome"

copia = duna não cria um segundo livro — copia só o endereço. As duas variáveis apontam pro mesmíssimo objeto na memória, então mexer usando uma delas afeta o que a outra "vê" também. Esse comportamento chama-se aliasing (duas variáveis, um "apelido" cada, pro mesmo objeto).

Isso é diferente de um int. Se fosse int a = 5; int b = a; b = 10;, a continuaria 5 — porque int copia o valor. Com objetos, copia = duna copia a referência, não o objeto. É uma das maiores fontes de confusão de quem está começando em OO — vale reler esse trecho quantas vezes precisar.

null: quando a referência não aponta pra nada

Uma variável de tipo classe, declarada sem new, não fica com "lixo" nem dá erro de compilação — ela recebe um valor especial: null, que significa "esta referência não aponta pra objeto nenhum".

Livro proximo; // declarada, mas sem new
System.out.println(proximo); // null
null só existe pra referências. Tipos primitivos (int, double, boolean, char) nunca podem ser null — eles sempre têm um valor padrão numérico ou lógico. Só tipos de classe (String, Livro, qualquer classe sua) podem.

NullPointerException: o erro mais famoso do Java

Chamar um método ou acessar um atributo em cima de uma referência null é pedir pro Java conversar com um objeto que não existe. O programa compila normalmente — o erro só aparece quando essa linha roda:

Livro proximo = null;
proximo.mostrarFicha(); // 💥 explode aqui
$ java Teste Exception in thread "main" java.lang.NullPointerException
O hábito que evita isso: antes de usar uma referência que pode não ter sido preenchida, confira com if (variavel != null). É exatamente o que a classe Leitor faz mais adiante, no método devolverLivro() — conferir antes de mexer.

Parâmetros e retorno

Parâmetros: métodos que recebem informação

Um método pode declarar parâmetros — variáveis que só existem durante a execução dele, recebendo valores de fora:

class Livro {
  // ...atributos...

  void emprestarPara(String nomeDoLeitor) {
    disponivel = false;
    System.out.println(titulo + " foi emprestado para " + nomeDoLeitor);
  }
}

duna.emprestarPara("Nicoly");

nomeDoLeitor é o parâmetro, declarado entre os parênteses junto com seu tipo. "Nicoly", no momento em que o método é chamado, é o argumento — o valor real que preenche aquele parâmetro. Um método pode ter zero, um ou vários parâmetros, separados por vírgula.

Parâmetros também podem ser objetos

Um parâmetro não precisa ser um tipo primitivo ou String — pode ser qualquer classe sua:

boolean pegarEmprestado(Livro livro) {
  if (livro.disponivel) {
    livro.disponivel = false;
    return true;
  }
  return false;
}

Aqui, livro é uma referência pro mesmo objeto que existe fora do método — não uma cópia. Alterar livro.disponivel lá dentro muda o objeto original de verdade, do lado de fora também.

Retorno: void × devolver um valor

Todo método declara, antes do nome, o que ele devolve pra quem chamou. void quer dizer "nada":

void devolver() {          // não devolve nada
  disponivel = true;
}

boolean emprestar() {      // devolve um boolean
  if (disponivel) {
    disponivel = false;
    return true;
  }
  return false;
}

boolean deuCerto = duna.emprestar(); // guarda o retorno numa variável

Quando o método devolve algo, o tipo declarado antes do nome (boolean, no exemplo) precisa bater com o que vem depois de return. O Java confere isso ao compilar — se prometeu boolean e você tentar devolver um String, é erro de compilação.

return também encerra o método na hora. Assim que uma linha return executa, o método termina ali — mesmo que existam linhas depois dela. Em emprestar() acima, se disponivel for true, o segundo return false; nunca chega a rodar.

Duas classes conversando: Livro e Leitor

Um atributo também pode ser outro objeto seu, não só um tipo primitivo ou String. É assim que classes começam a se conectar:

class Leitor {
  String nome;
  Livro livroAtual; // referência — começa null

  boolean pegarEmprestado(Livro livro) {
    if (livro.disponivel) {
      livro.disponivel = false;
      livroAtual = livro;
      return true;
    }
    return false;
  }

  void devolverLivro() {
    if (livroAtual != null) {
      livroAtual.disponivel = true;
      livroAtual = null;
    }
  }
}

Juntando tudo, num main:

Livro duna = new Livro();
duna.titulo = "Duna";
duna.disponivel = true;

Leitor nicoly = new Leitor();
nicoly.nome = "Nicoly";

nicoly.pegarEmprestado(duna);
System.out.println(duna.disponivel); // false

nicoly.devolverLivro();
System.out.println(duna.disponivel); // true

Repare que devolverLivro() confere livroAtual != null antes de mexer nele — sem essa checagem, chamar devolverLivro() num Leitor que nunca pegou nada emprestado explodiria em NullPointerException.

Modelando um domínio simples

Modelar é decidir quais classes vão existir num sistema, o que cada uma sabe (atributos) e o que cada uma faz (métodos), antes — ou enquanto — você escreve o código. Um jeito simples de começar:

Substantivos → classes

"Um leitor pega um livro emprestado" tem dois substantivos concretos: candidatos fortes a virarem classes.

Verbos → métodos

"Pega emprestado", "devolve" viram pegarEmprestado(), devolver() — ações que um objeto sabe fazer.

Características → atributos

Nome do leitor, título do livro, se está disponível — os "detalhes" de cada substantivo viram atributos.

Não existe fórmula perfeita nem resposta única — duas pessoas podem modelar o mesmo domínio de jeitos diferentes, e as duas podem estar certas. O que importa é conseguir explicar a escolha. Esse instinto fica mais afiado a cada aula, principalmente a partir da aula 05, com relacionamentos entre objetos.

Um primeiro diagrama de classes

Um diagrama de classes é só um desenho que mostra as classes, seus atributos e métodos, e como elas se conectam. Nada de notação UML chique por enquanto — só caixas e linhas, legíveis por qualquer pessoa:

┌─────────────────────────┐ ┌─────────────────────────┐ │ Livro │ │ Leitor │ ├─────────────────────────┤ ├─────────────────────────┤ │ titulo: String │ │ nome: String │ │ autor: String │ │ livroAtual: Livro │ │ anoPublicacao: int │ └─────────────────────────┘ │ disponivel: boolean │ │ ├─────────────────────────┤ │ conhece um Livro │ emprestar(): boolean │◄─────────────────────┘ │ devolver(): void │ │ mostrarFicha(): void │ └─────────────────────────┘

A convenção que usamos aqui: a caixa tem três partes (nome da classe, atributos, métodos), e uma linha entre duas caixas mostra que uma classe conhece a outra — no exemplo, todo Leitor pode conhecer um Livro através do atributo livroAtual.

Por que desenhar antes de codar? Um diagrama, mesmo simples e feito à mão no papel, é muito mais barato de mudar do que código já escrito. Errar no papel custa uma borracha; errar direto no código custa refatoração. O desafio de hoje pede o seu primeiro diagrama — pode ser desenhado à mão e fotografado.
