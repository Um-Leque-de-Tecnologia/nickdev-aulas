Desafio · Aula 03

Livro & Leitor ganham vida 📚

Lembra da pergunta da aula 01 — "como você organizaria o código de um sistema de biblioteca?" Chegou a hora de responder de verdade: modele e implemente as classes Livro e Leitor, crie objetos com new e faça os dois conversarem através de parâmetros e retorno.

🎯

O objetivo

Sair da teoria e escrever seu primeiro par de classes de verdade. São cinco coisas:

  1. Desenhar um diagrama de classes simples, antes de codar
  2. Escrever a classe Livro, com atributos e métodos
  3. Escrever a classe Leitor, que conhece um Livro
  4. Implementar métodos com parâmetro (um objeto) e retorno
  5. Escrever um main que cria e usa os objetos, e mostra tudo no terminal
📖

Travou numa palavra?

Instância, referência, null, parâmetro, retorno — se alguma dessas aparecer aqui e você não lembrar o que é, o guia da aula tem um dicionário com todas elas em português simples.

Passo a passo
01

Desenhe o diagrama primeiro

Antes de abrir a IDE, desenhe (no papel, no caderno, ou num app tipo Excalidraw) duas caixas: Livro e Leitor. Em cada uma, liste os atributos e os métodos que você imagina que a classe vai ter. Puxe uma linha entre as duas mostrando que Leitor conhece um Livro.

┌─────────────────┐ ┌─────────────────┐ │ Livro │ │ Leitor │ ├─────────────────┤ ├─────────────────┤ │ titulo │ │ nome │ │ autor │ │ livroAtual: Livro │ │ anoPublicacao │ └─────────────────┘ │ disponivel │ │ ├─────────────────┤ │ conhece um Livro │ emprestar() │◄─────────────────┘ │ devolver() │ │ mostrarFicha() │ └─────────────────┘

Pode ser bem simples. O objetivo aqui não é ficar bonito, é pensar antes de codar. Uma foto do desenho no papel resolve — o guia da aula tem esse mesmo diagrama, se quiser conferir.

02

Crie a classe Livro

Crie o arquivo Livro.java com os atributos e pelo menos dois métodos: um que não devolve nada (void) e um que devolve um valor:

class Livro {
  String titulo;
  String autor;
  int anoPublicacao;
  boolean disponivel;

  void mostrarFicha() {
    // TODO: imprimir titulo, autor e anoPublicacao
  }

  boolean emprestar() {
    // TODO: se disponivel, marcar como emprestado e devolver true
    // TODO: senão, devolver false
    return false;
  }

  void devolver() {
    // TODO: marcar disponivel = true
  }
}

Sem construtor, de propósito. Ainda não vimos construtor (isso é aula 04). Os objetos vão ser criados com new Livro() vazio, e os atributos preenchidos direto, um a um.

03

Crie a classe Leitor

Crie o arquivo Leitor.java. O atributo livroAtual é do tipo Livro — uma referência que começa null, porque no início ninguém pegou nada emprestado:

class Leitor {
  String nome;
  Livro livroAtual; // null até pegar algo emprestado

  boolean pegarEmprestado(Livro livro) {
    // TODO: se livro.disponivel, chamar livro.emprestar(),
    // guardar em livroAtual e devolver true; senão, false
    return false;
  }

  void devolverLivro() {
    // TODO: se livroAtual != null, chamar livroAtual.devolver()
    // e voltar livroAtual pra null
  }
}

O detalhe que mais derruba gente nova: devolverLivro() precisa conferir livroAtual != null antes de tentar usar. Chamar um método em cima de null é NullPointerException na certa.

04

Escreva o main

Crie uma terceira classe, TesteBiblioteca.java, só com o main. Nela, crie pelo menos 2 objetos Livro e 1 objeto Leitor, preencha os atributos, e exercite os métodos — inclusive um caso em que o empréstimo falha (livro já emprestado) e um em que a devolução acontece em cima de um Leitor sem nada emprestado (pra provar que o != null segura a explosão):

public class TesteBiblioteca {
  public static void main(String[] args) {
    Livro duna = new Livro();
    duna.titulo = "Duna";
    duna.autor = "Frank Herbert";
    duna.anoPublicacao = 1965;
    duna.disponivel = true;

    Leitor nicoly = new Leitor();
    nicoly.nome = "Nicoly";

    // TODO: nicoly pega duna emprestado, mostre se deu certo
    // TODO: crie um segundo Leitor tentando pegar duna também — e mostre que falha
    // TODO: nicoly devolve duna
    // TODO: nicoly tenta devolver de novo, sem ter nada emprestado
  }
}
05

Compile, rode e publique

Compile as três classes e rode TesteBiblioteca pelo terminal:

$ javac Livro.java Leitor.java TesteBiblioteca.java $ java TesteBiblioteca

Publique no mesmo repositório GitHub das aulas anteriores, numa pasta aula-03 — junto com uma foto ou arquivo do diagrama do passo 01.

Requisitos mínimos
  • Diagrama de classes simples (papel ou digital) com Livro e Leitor, atributos e métodos
  • Classe Livro com os quatro atributos e pelo menos 2 métodos, um deles com retorno
  • Classe Leitor com atributo livroAtual do tipo Livro (referência, começa null)
  • Método pegarEmprestado(Livro livro) recebendo um objeto como parâmetro
  • Método devolverLivro() conferindo != null antes de usar livroAtual
  • Nenhum construtor — objetos criados com new vazio, atributos preenchidos direto
  • Classe TesteBiblioteca com main, criando e usando pelo menos 2 Livro e 2 Leitor
  • Compilado com javac e executado com java, pelo terminal
  • Publicado no repositório GitHub da turma, numa pasta aula-03
Desafios extras (pra quem quer brilhar ✨)
  • Crie uma terceira classe Biblioteca, com um array de Livro e um método buscarPorTitulo(String titulo) que devolve o Livro encontrado — ou null, se nenhum bater
  • Adicione um método listarDisponiveis() na Biblioteca, percorrendo o array com for
  • Troque o Leitor por um domínio próprio (ex.: ContaBancaria e Cliente, ou Personagem e Inventario) — desde que mantenha os mesmos conceitos: referência, null, parâmetro, retorno
  • No diagrama, adicione a terceira classe e a linha de conexão dela com Livro
