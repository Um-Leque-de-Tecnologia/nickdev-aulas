Livro & Leitor funcionando 📚✅

O diagrama de classes sugerido, as três classes completas (Livro, Leitor e TesteBiblioteca) e a saída real de rodar tudo pelo terminal — mais um bônus com a classe extra Biblioteca, pra quem foi atrás dos desafios extras.

O diagrama do passo 01
┌─────────────────────────┐ ┌─────────────────────────┐ │ Livro │ │ Leitor │ ├─────────────────────────┤ ├─────────────────────────┤ │ titulo: String │ │ nome: String │ │ autor: String │ │ livroAtual: Livro │ │ anoPublicacao: int │ └─────────────────────────┘ │ disponivel: boolean │ │ ├─────────────────────────┤ │ conhece um Livro │ emprestar(): boolean │◄─────────────────────┘ │ devolver(): void │ │ mostrarFicha(): void │ └─────────────────────────┘

No seu desafio, esse diagrama pode ter sido feito à mão e fotografado — o que importa é ele existir antes do código, não a ferramenta usada pra desenhar.

Código & saída
01 · Livro.java
Livro.java
class Livro {
  String titulo;
  String autor;
  int anoPublicacao;
  boolean disponivel;

  void mostrarFicha() {
    System.out.println(titulo + " — " + autor + " (" + anoPublicacao + ") · "
        + (disponivel ? "disponível" : "emprestado"));
  }

  boolean emprestar() {
    if (disponivel) {
      disponivel = false;
      return true;
    }
    return false;
  }

  void devolver() {
    disponivel = true;
  }
}
o que ele resolve
Quatro atributos simples. emprestar() devolve boolean — true se conseguiu, false se já estava emprestado. Quem decide se pode emprestar é o próprio Livro, não quem chama o método.
02 · Leitor.java
Leitor.java
class Leitor {
  String nome;
  Livro livroAtual;

  boolean pegarEmprestado(Livro livro) {
    boolean conseguiu = livro.emprestar();
    if (conseguiu) {
      livroAtual = livro;
    }
    return conseguiu;
  }

  void devolverLivro() {
    if (livroAtual != null) {
      livroAtual.devolver();
      livroAtual = null;
    } else {
      System.out.println(nome + " não tem nenhum livro emprestado.");
    }
  }
}
o que ele resolve
livro chega como parâmetro — uma referência pro mesmo objeto de fora, não uma cópia. E devolverLivro() confere != null antes de mexer — sem isso, chamar duas vezes seguidas explodiria em NullPointerException.
03 · TesteBiblioteca.java (main)
TesteBiblioteca.java
public class TesteBiblioteca {
  public static void main(String[] args) {
    Livro duna = new Livro();
    duna.titulo = "Duna";
    duna.autor = "Frank Herbert";
    duna.anoPublicacao = 1965;
    duna.disponivel = true;

    Leitor nicoly = new Leitor();
    nicoly.nome = "Nicoly";

    Leitor outro = new Leitor();
    outro.nome = "Marcos";

    System.out.println(nicoly.nome + " tentando pegar Duna: " + nicoly.pegarEmprestado(duna));
    System.out.println(outro.nome + " tentando pegar Duna também: " + outro.pegarEmprestado(duna));

    duna.mostrarFicha();

    nicoly.devolverLivro();
    duna.mostrarFicha();

    outro.devolverLivro();
  }
}
terminal
$ javac Livro.java Leitor.java TesteBiblioteca.java $ java TesteBiblioteca Nicoly tentando pegar Duna: true Marcos tentando pegar Duna também: false Duna — Frank Herbert (1965) · emprestado Duna — Frank Herbert (1965) · disponível Marcos não tem nenhum livro emprestado.
Bônus · indo além com a classe Biblioteca ✨

Um dos desafios extras: uma terceira classe guardando vários livros num array, com um método que devolve null quando não encontra nada — a referência e o null da aula 03, agora resolvendo um problema real.

Biblioteca.java
class Biblioteca {
  Livro[] acervo;

  Livro buscarPorTitulo(String titulo) {
    for (int i = 0; i < acervo.length; i++) {
      if (acervo[i].titulo.equals(titulo)) {
        return acervo[i];
      }
    }
    return null; // não achou nenhum com esse título
  }
}
usando
Biblioteca biblioteca = new Biblioteca();
biblioteca.acervo = new Livro[] { duna, hobbit };

Livro encontrado = biblioteca.buscarPorTitulo("Duna");
if (encontrado != null) {
  encontrado.mostrarFicha();
} else {
  System.out.println("Não achei esse livro.");
}
Por que devolver null aqui faz sentido: nem todo método precisa sempre conseguir devolver algo. buscarPorTitulo devolve o Livro quando acha, e null quando não acha — e quem chama o método é obrigado, na prática, a conferir antes de usar o resultado. É o mesmo cuidado do devolverLivro(), só que do lado de quem chama.
Por que essa solução funciona

Diagrama antes do código

Duas caixas, atributos e métodos, uma linha de conexão — pensado no papel antes de abrir a IDE.

Sem construtor, de propósito

Todo objeto nasce com new Classe() vazio, atributos preenchidos direto. Construtor é aula 04.

Objeto como parâmetro

pegarEmprestado(Livro livro) recebe a referência pro objeto de fora, não uma cópia.

null tratado de verdade

devolverLivro() confere != null antes de mexer — nenhuma NullPointerException escondida.

Retorno com propósito

emprestar() e pegarEmprestado() devolvem boolean: quem chamou sabe se deu certo, sem precisar adivinhar.

Uma responsabilidade por classe

Livro cuida do próprio estado; Leitor decide o que fazer com o resultado. Cada um no seu quadrado.

Checklist batido
  • Diagrama de classes simples, feito antes do código
  • Classe Livro com 4 atributos e 3 métodos, um deles com retorno
  • Classe Leitor com atributo livroAtual do tipo Livro (referência, começa null)
  • Método pegarEmprestado(Livro livro) recebendo um objeto como parâmetro
  • Método devolverLivro() conferindo != null antes de usar
  • Nenhum construtor usado — só new vazio e atributos preenchidos direto
  • TesteBiblioteca com main, criando e usando 2 Livro e 2 Leitor
  • Compilado com javac e executado com java, pelo terminal
