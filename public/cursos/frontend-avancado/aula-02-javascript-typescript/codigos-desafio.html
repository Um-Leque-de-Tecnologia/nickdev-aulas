src/tipos.ts ⭐
// União literal: só estes três valores são aceitos.
// Com "string" solto, escrever "presencial" minúsculo passaria batido.
export type Formato = "Presencial" | "Online" | "Híbrido";
export type Nivel = "Iniciante" | "Intermediário" | "Avançado";

export type Evento = {
  id: string;
  slug: string;
  titulo: string;
  resumo: string;
  descricao: string;
  organizador: string;
  organizadorSlug: string;
  categoria: string;
  formato: Formato;

  // "?" = o campo PODE NÃO VIR. Evento online não tem cidade.
  cidade?: string;

  inicioEm: string;      // ISO: "2026-09-12T19:00"
  duracaoMin: number;
  gratuito: boolean;

  // "| null" = o campo VEM SEMPRE, e null significa algo:
  // aqui, "vagas ilimitadas". Não é a mesma coisa que "?".
  vagas: number | null;

  nivel: Nivel;
};

// Preparando o formulário da aula 08: o id vem do servidor.
export type NovoEvento = Omit<Evento, "id">;
💡

? e | null não são sinônimos

cidade? quer dizer "pode não existir" — ausência. vagas: number | null quer dizer "existe sempre, e null carrega significado" — no caso, ilimitado. Confundir os dois faz você tratar "sem informação" e "ilimitado" como a mesma coisa, e a tela mente pra pessoa.

src/api.ts ⭐
import type { Evento } from "./tipos.js";

export async function carregarEventos(): Promise<Evento[]> {
  const resposta = await fetch("dados/eventos.json");

  // ⚠️ O ponto mais importante deste arquivo.
  // fetch SÓ rejeita se a rede falhar. Um 404 ou 500 chega aqui
  // como resposta "normal" — e o .json() abaixo tentaria
  // interpretar uma página de erro como JSON.
  if (!resposta.ok) {
    throw new Error(`Servidor respondeu ${resposta.status}`);
  }

  return resposta.json();
}

// Quem busca LANÇA. Quem desenha decide o que mostrar.
// Repare que este arquivo não toca em nada da tela — e é isso
// que vai permitir reaproveitá-lo quase inteiro no Angular.

src/filtros.ts ⭐

O arquivo que ensina imutabilidade na prática. Na aula 05, isto vira um computed() de três linhas.

import type { Evento, Formato } from "./tipos.js";

export type Filtros = {
  busca: string;
  formato: Formato | "todos";
  soGratuitos: boolean;
};

export const FILTROS_VAZIOS: Filtros = {
  busca: "",
  formato: "todos",
  soGratuitos: false,
};

// DERIVA uma lista nova. A original nunca é tocada —
// por isso limpar o filtro traz tudo de volta, de graça.
export function aplicarFiltros(
  eventos: readonly Evento[],   // readonly: o compilador PROÍBE mutar aqui dentro
  f: Filtros,
): Evento[] {
  const busca = f.busca.trim().toLowerCase();

  return eventos
    .filter((e) => !f.soGratuitos || e.gratuito)
    .filter((e) => f.formato === "todos" || e.formato === f.formato)
    .filter((e) =>
      busca === "" ||
      e.titulo.toLowerCase().includes(busca) ||
      e.organizador.toLowerCase().includes(busca)
    )
    // toSorted, não sort: sort MUTA o array
    .toSorted((a, b) => a.inicioEm.localeCompare(b.inicioEm));
}
🔒

O readonly Evento[] é o detalhe que vale ouro

Ele faz o compilador recusar qualquer push, sort ou splice dentro desta função. Você não precisa lembrar da regra de imutabilidade — a ferramenta lembra por você. Tente escrever eventos.push(x) aí dentro e veja o erro aparecer.

src/render.ts
import type { Evento } from "./tipos.js";

// ⚠️ Segurança: título com "<" ou "&" quebraria o innerHTML.
// Com dados de verdade (aula 08, formulário aberto), vira
// brecha pra injetar script. Escape SEMPRE o que vem dos dados.
function escapar(texto: string): string {
  const div = document.createElement("div");
  div.textContent = texto;
  return div.innerHTML;
}

function formatarData(iso: string): string {
  return new Date(iso).toLocaleDateString("pt-BR", {
    day: "numeric", month: "long", hour: "2-digit", minute: "2-digit",
  });
}

// A MESMA marcação semântica da entrega 0. Não perca isso:
// article, h3 com link dentro, time com datetime.
export function cardHtml(e: Evento): string {
  const local = e.cidade ?? "Online";   // ?? e não ||

  return `
    <li>
      <article class="card-evento">
        <div class="card-evento__corpo">
          <h3>
            <a href="evento.html?slug=${encodeURIComponent(e.slug)}">
              ${escapar(e.titulo)}
            </a>
          </h3>
          <p>${escapar(e.resumo)}</p>
          <p class="card-evento__meta">
            <time datetime="${e.inicioEm}">${formatarData(e.inicioEm)}</time>
            · ${escapar(local)} · ${e.formato}
          </p>
          ${e.gratuito ? '<p class="selo-gratuito">Gratuito</p>' : ""}
        </div>
      </article>
    </li>
  `;
}

export function listaHtml(eventos: readonly Evento[]): string {
  return eventos.map(cardHtml).join("");
}
🛡️

Por que escapar() vale nota

Hoje os dados são de vocês, então "não tem risco". Mas na aula 08 esse mesmo card vai exibir evento cadastrado por qualquer pessoa pelo formulário. Quem escreveu escapar() agora não vai ter que caçar a falha depois. E repare: o Angular e o React fazem isso automaticamente — mais uma coisa que você só valoriza tendo feito na mão.

src/eventos-page.ts · os quatro estados
import { carregarEventos } from "./api.js";
import { aplicarFiltros, FILTROS_VAZIOS, type Filtros } from "./filtros.js";
import { listaHtml } from "./render.js";
import type { Evento } from "./tipos.js";

const lista = document.getElementById("lista");
const aviso = document.getElementById("aviso");
if (!lista || !aviso) throw new Error("Elementos não encontrados no HTML");

// O "estado" da página. Duas coisas: os dados originais
// (que nunca mudam) e os filtros atuais.
let todos: readonly Evento[] = [];
let filtros: Filtros = { ...FILTROS_VAZIOS };

// Uma função só que redesenha a partir do estado.
// É exatamente o que o framework vai fazer sozinho depois.
function redesenhar(): void {
  const visiveis = aplicarFiltros(todos, filtros);

  // ESTADO 3: vazio — o mais esquecido, e o mais visível
  if (visiveis.length === 0) {
    lista.innerHTML = "";
    aviso.textContent = "Nenhum evento encontrado. Tente limpar os filtros.";
    return;
  }

  // ESTADO 4: com dados
  aviso.textContent = `${visiveis.length} evento(s) encontrado(s)`;
  lista.innerHTML = listaHtml(visiveis);
}

async function iniciar(): Promise<void> {
  // ESTADO 1: carregando
  aviso.textContent = "Carregando eventos…";

  try {
    todos = await carregarEventos();
    redesenhar();
  } catch (erro) {
    // ESTADO 2: erro — mensagem na TELA, não só no console
    console.error(erro);
    lista.innerHTML = "";
    aviso.textContent = "Não consegui carregar os eventos. Recarregue a página.";
  }
}

// Cada mudança de filtro devolve um objeto NOVO (spread),
// nunca "filtros.busca = ...". Mesma disciplina da lista.
document.getElementById("q")?.addEventListener("input", (ev) => {
  const alvo = ev.target as HTMLInputElement;
  filtros = { ...filtros, busca: alvo.value };
  redesenhar();
});

iniciar();
🎯

O padrão que se repete o curso inteiro

estado → derivação → tela. Você muda o estado, chama uma função que redesenha a partir dele, e nunca mexe na tela direto. É o modelo mental de todo framework reativo — a diferença é que lá o redesenhar() é automático, e só a parte que mudou é atualizada.

Quando o computed() aparecer na aula 05, você vai reconhecer o aplicarFiltros. E quando o template atualizar sozinho, vai reconhecer o redesenhar que você não precisou mais escrever.

src/evento-page.ts · o detalhe pelo slug
import { carregarEventos } from "./api.js";

async function iniciar(): Promise<void> {
  // lê ?slug=... da URL
  const slug = new URLSearchParams(location.search).get("slug");

  if (!slug) {
    mostrarNaoEncontrado();
    return;
  }

  const eventos = await carregarEventos();

  // find devolve Evento | undefined — e isso é BOM:
  // o TypeScript te obriga a tratar o "não achei".
  const evento = eventos.find((e) => e.slug === slug);

  if (!evento) {
    mostrarNaoEncontrado();
    return;
  }

  // ✨ daqui pra baixo o TS SABE que é Evento. Sem "!", sem cast.
  document.title = `${evento.titulo} · Leque de Eventos`;
  render(evento);
}
💡

Isto vira notFound() mais tarde

Esse if (!evento) é a versão manual do que o Angular faz com guard e o Next faz com notFound(). A lógica é idêntica — o que muda é quem cuida do roteamento.

src/tema.ts · fechando o gancho da aula 01
type Tema = "light" | "dark";

function temaSalvo(): Tema | null {
  const v = localStorage.getItem("tema");
  // narrowing: só aceita os dois valores válidos
  return v === "light" || v === "dark" ? v : null;
}

function aplicar(tema: Tema): void {
  // o JS só troca um atributo. Toda a repintura é do CSS,
  // que já usava var(--cor-*) desde a entrega 0.
  document.documentElement.dataset.tema = tema;
  localStorage.setItem("tema", tema);
}

// Na carga: só aplica se a PESSOA escolheu.
// Sem escolha, o CSS segue o prefers-color-scheme do sistema.
const salvo = temaSalvo();
if (salvo) aplicar(salvo);

document.getElementById("btn-tema")?.addEventListener("click", () => {
  const atual = document.documentElement.dataset.tema;
  aplicar(atual === "dark" ? "light" : "dark");
});
✨

Repare no que não mudou

Nenhuma linha de CSS. O tokens.css da entrega 0 já tinha :root[data-tema="dark"] preparado. O JavaScript só troca um atributo e some. É o desacoplamento da aula 01 pagando dividendo — e é a mesma razão pela qual o tema vai continuar funcionando no Angular e no Next sem reescrita.
