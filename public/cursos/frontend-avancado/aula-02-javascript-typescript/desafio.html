O protótipo ganha vida ⚙️

Os mesmos arquivos da semana passada — agora movidos a dados. Os eventos saem do HTML escrito à mão e passam a ser renderizados a partir de uma lista tipada, com busca, filtros e tratamento de erro. Ainda sem framework.

🎯

O objetivo

Fazer na mão tudo que o Angular vai fazer sozinho a partir da aula 04: renderizar uma lista, refletir filtro na tela, tratar carregando, vazio e erro. Quem faz isso a sério não decora sintaxe de framework depois — reconhece o que ele está automatizando.

⚠️

Antes de instalar: a versão do TypeScript

Use typescript@6.0.3. A versão 7 é mais recente e mais rápida, mas o Angular 22 não funciona com ela — e vocês vão migrar este projeto pro Angular na aula 03. Começar já na faixa certa evita retrabalho.

👥

Entrega de equipe

Mesma equipe, mesmo repositório da entrega 0. Dá pra dividir: quem faz os tipos e os dados, quem faz a renderização, quem faz busca e filtros, quem faz os estados de tela e o tema.

Passo a passo
01

Ligar o TypeScript

$ npm init -y $ npm install -D typescript@6.0.3

E o tsconfig.json:

{
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "outDir": "js",
    "rootDir": "src"
  },
  "include": ["src"]
}

Você escreve em src/*.ts e o compilador gera js/*.js, que é o que o HTML carrega. Para compilar continuamente:

$ npx tsc --watch

strict: true não é negociável nesta entrega. Sem ele o TypeScript aceita null em tudo e você perde a única coisa que ele veio fazer. Se aparecerem 30 erros ao ligar, isso é a ferramenta funcionando — não um problema.

02

Os tipos ⭐

Em src/tipos.ts, descreva o formato de um evento — os campos são os do briefing.

export type Formato = "Presencial" | "Online" | "Híbrido";
export type Nivel = "Iniciante" | "Intermediário" | "Avançado";

export type Evento = {
  id: string;
  slug: string;
  titulo: string;
  // … o resto dos campos do briefing
  cidade?: string;        // online não tem
  vagas: number | null;  // null = ilimitado
};

Use união literal, não string. formato: Formato faz o editor oferecer os três valores e recusar "presencial" em minúscula. Um string solto aceita qualquer coisa e o erro só aparece na tela.

Justifique no README por que cidade usa ? e vagas usa | null. Não é a mesma coisa, e a diferença importa.

03

Os dados saem do HTML

Mova os 8 eventos para dados/eventos.json — um arquivo JSON de verdade, servido junto com o site.

E apague os cards escritos à mão do HTML. A listagem vira só o contêiner vazio:

<ul class="lista-eventos" id="lista"></ul>

Por que JSON e não um .ts com a lista dentro. Porque assim vocês precisam usar fetch, tratar erro e lidar com espera — que é metade do conteúdo da aula. E porque na aula 07 esse mesmo arquivo vira uma chamada de API de verdade, sem mudar nada em volta.

04

Buscar com fetch, tratando o erro ⭐

export async function carregarEventos(): Promise<Evento[]> {
  const resposta = await fetch("dados/eventos.json");

  // obrigatório: fetch NÃO rejeita em 404 nem em 500
  if (!resposta.ok) {
    throw new Error(`Servidor respondeu ${resposta.status}`);
  }

  return resposta.json();
}

Teste o caminho do erro de verdade. Renomeie o JSON, recarregue, e confira que aparece a mensagem de erro — não uma tela em branco nem um erro só no console. Print disso vai pro README.

Precisa de servidor. Abrir o HTML com duplo clique (file://) bloqueia módulos e fetch. Use a extensão Live Server do VS Code, ou npx serve.

05

Renderizar a lista

Uma função que recebe a lista e devolve o HTML dos cards — a mesma marcação semântica da entrega 0.

function cardHtml(evento: Evento): string {
  return `
    <li>
      <article class="card-evento">
        <h3><a href="evento.html?slug=${evento.slug}">${evento.titulo}</a></h3>
        <time datetime="${evento.inicioEm}">${formatarData(evento.inicioEm)}</time>
      </article>
    </li>
  `;
}
  • Não perca a semântica: <article>, <h3>, <time datetime>
  • Formate a data com toLocaleDateString("pt-BR")
  • O detalhe passa a ler o slug da URL: evento.html?slug=…

Escape o que vem dos dados. Se o título tiver < ou &, jogar direto em innerHTML quebra a página — e, com dados reais, vira falha de segurança. Escreva uma função escapar() e use nos campos de texto. Vale ponto no critério de qualidade.

06

Os três estados da tela ⭐

Toda tela que busca dados tem quatro situações, e três costumam ser esquecidas:

EstadoO que aparece
CarregandoUm esqueleto ou "Carregando eventos…"
ErroMensagem clara e um botão "tentar de novo"
Vazio"Nenhum evento encontrado" — e o que fazer
Com dadosA lista

O vazio é o mais esquecido e o mais visível. Uma busca sem resultado que mostra área em branco parece site quebrado. E ele acontece toda vez que alguém filtra demais.

Para ver o carregando, sua rede local é rápida demais. Use o DevTools → Network → throttling "Slow 3G", ou segure de propósito com um await de 1 segundo enquanto testa.

07

Busca e filtros — imutáveis ⭐

Este é o coração do desafio. O formulário da entrega 0 finalmente funciona.

  • Busca por título ou organizador, sem diferenciar maiúscula
  • Filtro por formato (Presencial / Online / Híbrido)
  • Filtro por "somente gratuitos"
  • Os filtros se combinam
// guarde os critérios num objeto só
type Filtros = { busca: string; formato: Formato | "todos"; soGratuitos: boolean };

// e derive a lista visível a partir da original — sem alterá-la
function aplicar(eventos: Evento[], f: Filtros): Evento[] {
  return eventos
    .filter((e) => !f.soGratuitos || e.gratuito)
    .filter((e) => f.formato === "todos" || e.formato === f.formato)
    .filter((e) => e.titulo.toLowerCase().includes(f.busca.toLowerCase()));
}

A regra inegociável: a lista original nunca é alterada. Nada de push, splice ou sort nela. Toda filtragem deriva uma lista nova. Se você mutar, limpar o filtro não traz os eventos de volta — e esse é exatamente o bug que imutabilidade previne.

Reflita o filtro na URL (?formato=online) se quiser ir além. Aí o link fica compartilhável — e na aula 11, no Next, isso vira searchParams quase de graça.

08

O tema que lembra

Fechando o gancho da aula 01: o botão de tema agora guarda a escolha.

const salvo = localStorage.getItem("tema");
if (salvo === "dark" || salvo === "light") {
  document.documentElement.dataset.tema = salvo;
}

Ao clicar, alterne o data-tema e salve. O CSS da entrega 0 já está pronto pra isso — não mude uma linha dele.

Repare no que aconteceu: o JavaScript só troca um atributo. Toda a repintura é do CSS, que já usava var(--cor-*). Isso é o desacoplamento da aula 01 pagando dividendo.

Respeite quem não escolheu. Sem nada salvo, mantenha o prefers-color-scheme do sistema. Só sobrescreva quando a pessoa tiver clicado.

09

Compile, teste e publique

$ npx tsc --noEmit ✓ sem erros
  • tsc passando sem nenhum erro e sem nenhum any
  • Todos os estados testados: carregando, erro, vazio, com dados
  • A navegação por teclado da entrega 0 continua funcionando

A acessibilidade não pode regredir. É o deslize mais comum quando o JavaScript entra: o card renderizado perde o <article>, ou o foco some ao filtrar. Refaça o teste do teclado depois de tudo pronto.

Publicar: commite a pasta js/ gerada, já que o GitHub Pages não compila TypeScript. Diga isso no README pra ficar claro que foi decisão, não descuido.

O que NÃO pode 🚫
  • any. Se travar, use unknown e faça o narrowing
  • typescript@7 — o Angular 22 não aceita, e a aula 03 é semana que vem
  • Mutar a lista original com push, sort ou splice
  • fetch sem conferir resposta.ok
  • Framework ou biblioteca — ainda não
  • Perder a semântica ou a acessibilidade da entrega 0
  • innerHTML com dado não escapado
  • ! pra calar o strict
