O protótipo linha por linha

O desafio resolvido, comentado. Tente antes de espiar. O que importa aqui não é a sintaxe — é por que cada tag foi escolhida e por que o CSS está organizado assim.

🧭

Seis arquivos, e nenhuma linha de JavaScript

Repare enquanto lê: tudo que parece precisar de script — o destaque do card gratuito, o estado vazio, o tema escuro — está resolvido em CSS. Essa é a régua da aula.

Como os CSS entram na página

A ordem das camadas é declarada antes de qualquer regra. Uma vez só, e ela vale pro documento inteiro.

<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />
  <title>Eventos · Leque de Eventos</title>

  <!-- a ordem de prioridade da cascata, declarada UMA vez -->
  <style>@layer reset, base, componentes, utilitarios;</style>

  <link rel="stylesheet" href="css/tokens.css" />
  <link rel="stylesheet" href="css/base.css" />
  <link rel="stylesheet" href="css/componentes.css" />
</head>
💡

Por que declarar as camadas no <head>

Porque a ordem em que você declara define a prioridade — não a ordem em que os arquivos carregam. Declarando ali, você garante que componentes vence base mesmo que o navegador baixe os arquivos fora de ordem.

css/tokens.css ⭐

O arquivo mais importante do desafio. Toda decisão visual mora aqui — e em nenhum outro lugar.

@layer base {
  :root {
    /* faz o NAVEGADOR adaptar scrollbar, inputs e seletor de data.
       sem isto, site escuro com input branco brilhante. */
    color-scheme: light dark;

    /* --- cor: nomeada pelo PAPEL, não pela cor --- */
    --cor-fundo:      #ffffff;
    --cor-superficie: #f4f4f5;
    --cor-texto:      #18181b;
    --cor-texto-2:    #52525b;
    --cor-marca:      #6d28d9;
    --cor-ok:         #15803d;
    --cor-linha:      rgb(0 0 0 / .12);

    /* --- espaço: uma escala, sem valor mágico --- */
    --esp-1: .5rem;
    --esp-2: 1rem;
    --esp-3: 1.5rem;
    --esp-4: 2.5rem;

    /* --- forma --- */
    --raio:  12px;
    --borda: 1px solid var(--cor-linha);

    /* --- medida de leitura --- */
    --largura-texto: 70ch;
  }

  /* quem prefere escuro no sistema */
  @media (prefers-color-scheme: dark) {
    :root {
      --cor-fundo:      #0d0b14;
      --cor-superficie: #161122;
      --cor-texto:      #f3f0fa;
      --cor-texto-2:    #b4aec6;
      --cor-marca:      #a98ce0;
      --cor-ok:         #5fd08a;
      --cor-linha:      rgb(255 255 255 / .12);
    }
  }

  /* a escolha manual vence as duas de cima (extra do desafio) */
  :root[data-tema="dark"]  { --cor-fundo: #0d0b14; --cor-texto: #f3f0fa; }
  :root[data-tema="light"] { --cor-fundo: #ffffff; --cor-texto: #18181b; }
}
🎨

Repare no que mudou entre os temas

A marca fica mais clara no escuro (#6d28d9 → #a98ce0). Um roxo que passa no contraste sobre branco não passa sobre quase-preto. Trocar só o fundo e manter as outras cores é o erro mais comum de tema escuro — e ele reprova no critério de acessibilidade.

css/base.css
@layer reset {
  *, *::before, *::after { box-sizing: border-box; }
  * { margin: 0; }

  /* respeita quem pediu menos movimento no sistema */
  @media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
      animation-duration: .01ms !important;
      transition-duration: .01ms !important;
    }
  }
}

@layer base {
  html { scroll-behavior: smooth; }

  body {
    background: var(--cor-fundo);
    color: var(--cor-texto);
    font-family: system-ui, sans-serif;
    line-height: 1.6;

    /* rodapé sempre embaixo, sem position nem cálculo de altura */
    display: grid;
    grid-template-rows: auto 1fr auto;
    min-height: 100dvh;   /* dvh, não vh: a barra do celular conta */
  }

  /* tipografia fluida: nunca menor que 1.75rem, nunca maior que 3rem */
  h1 { font-size: clamp(1.75rem, 4vw + 1rem, 3rem); line-height: 1.1; }
  h2 { font-size: clamp(1.35rem, 2vw + .8rem, 2rem); }
  h3 { font-size: 1.125rem; }

  p { max-width: var(--largura-texto); }

  /* imagem nunca estoura o container */
  img { max-width: 100%; height: auto; display: block; }

  /* ⭐ o foco: aparece pra quem usa teclado, some no clique de mouse.
     NUNCA escreva outline: none sem colocar um substituto. */
  :focus-visible {
    outline: 2px solid var(--cor-marca);
    outline-offset: 2px;
    border-radius: 4px;
  }
}
⚠️

Os dois !important do reset são a exceção da regra

O desafio pede zero !important — e este é o único caso aceito, porque prefers-reduced-motion precisa vencer qualquer animação que alguém escreva depois. É uma questão de saúde: movimento pode causar enjoo e crise em quem tem sensibilidade vestibular. Fora daqui, nenhum.

Por que o link está no <h3>

Porque quem usa leitor de tela navega por títulos e por links. Com o link dentro do título, a mesma coisa aparece nas duas listas — e o texto do link é descritivo ("React Recife · Meetup #42"), não "clique aqui" nem "saiba mais". Uma lista de links que só diz "saiba mais" dez vezes é inútil.

css/componentes.css · a listagem
@layer componentes {

  /* ⭐ uma linha no lugar de três media queries */
  .lista-eventos {
    display: grid;
    gap: var(--esp-3);
    list-style: none;   /* tira a bolinha, mantém a semântica de lista */
    padding: 0;

    /* o min() interno evita rolagem horizontal em telas de 320px:
       sem ele, 280px + padding estoura e aparece barra lateral. */
    grid-template-columns: repeat(auto-fit, minmax(min(280px, 100%), 1fr));

    /* ⭐ declara que os FILHOS podem medir este elemento */
    container-type: inline-size;
    container-name: lista;
  }

  .card-evento {
    background: var(--cor-superficie);
    border: var(--borda);
    border-radius: var(--raio);
    overflow: hidden;
    height: 100%;   /* cards da mesma linha ficam da mesma altura */

    & h3 a { color: inherit; }

    &:hover { border-color: var(--cor-marca); }
  }

  .card-evento__corpo {
    padding: var(--esp-3);
    display: flex;            /* uma direção → flex */
    flex-direction: column;
    gap: var(--esp-1);
  }

  /* ⭐ quando o CARD tiver 420px — não a tela.
     o mesmo card fica empilhado na lateral estreita e lado a lado no meio. */
  @container lista (min-width: 420px) {
    .card-evento {
      display: grid;
      grid-template-columns: 140px 1fr;
    }
    .card-evento__capa { height: 100%; object-fit: cover; }
  }
}
💡

O que provar no README

Coloque a mesma <ul class="lista-eventos"> em dois lugares: no meio largo da home e dentro de uma barra lateral estreita. O card fica lado a lado num e empilhado no outro — sem uma linha de HTML diferente e sem prop nenhuma. É isso que media query não consegue fazer, e é o argumento inteiro de container query.

O :has() e o estado vazio
@layer componentes {

  /* ⭐ estiliza o PAI pelo que existe dentro dele.
     antes de :has(), isto exigia JavaScript adicionando uma classe. */
  .card-evento:has(.selo-gratuito) {
    border-color: var(--cor-ok);
  }

  .selo-gratuito {
    align-self: start;
    font-size: .8rem;
    padding: .15rem .6rem;
    border-radius: 999px;
    border: 1px solid var(--cor-ok);
    color: var(--cor-ok);
  }

  /* lista que NÃO tem card nenhum = estado vazio, só com CSS */
  .lista-eventos:not(:has(.card-evento)) {
    display: grid;
    place-items: center;
    min-height: 30vh;
  }
  .lista-eventos:not(:has(.card-evento))::after {
    content: "Nenhum evento encontrado.";
    color: var(--cor-texto-2);
  }
}

⌨️

Por que left: -9999px e não display: none

Porque display: none e visibility: hidden removem o elemento da ordem de foco — ele nunca receberia o Tab, e o link deixaria de existir pra quem mais precisa dele. Tirar da área visível mantendo no fluxo é o truque padrão.

Extra · alternar tema sem JavaScript

Um checkbox escondido, um :has() no <html>, e pronto.

<!-- no topo do body -->
<input class="so-leitor" type="checkbox" id="tema" />
<label class="btn-tema" for="tema">Alternar tema</label>
/* o html que TEM um #tema marcado usa a paleta escura */
html:has(#tema:checked) {
  --cor-fundo:      #0d0b14;
  --cor-superficie: #161122;
  --cor-texto:      #f3f0fa;
  --cor-marca:      #a98ce0;
}
✨

Por que isso funciona

:has() permite estilizar um ancestral pelo estado de um descendente — e nada impede que esse ancestral seja o <html>. Como toda a interface usa var(--cor-fundo), trocar as variáveis na raiz repinta o site inteiro. Nenhum componente sabe que existe um botão de tema.

A limitação honesta: a escolha não sobrevive a um recarregamento, porque não há onde guardar. Isso pede JavaScript — e é exatamente o que vocês vão fazer na aula 02.
