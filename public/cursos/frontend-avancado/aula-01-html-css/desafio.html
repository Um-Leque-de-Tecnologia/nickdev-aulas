O protótipo estático 🧱

Três telas do Leque de Eventos em HTML e CSS puros. Sem framework, sem biblioteca, sem uma linha de JavaScript. É a base visual e estrutural que vocês vão portar duas vezes — primeiro pro Angular, depois pro Next.

🎯

O objetivo

Provar que vocês conseguem escrever HTML que funciona sem enxergar a tela e CSS que é sistema, não remendo. Nas próximas 15 aulas o framework vai cuidar de muita coisa — mas nenhum deles escreve semântica nem acessibilidade por você.

🚫

Por que sem JavaScript

Porque é a única aula do curso em que dá pra focar 100% na estrutura e no estilo. Filtro, busca e interação chegam na aula 02. Se você resolver algo com JavaScript hoje, está resolvendo o problema errado — e quase sempre existe uma saída em CSS que você ainda não conhece.

👥

Entrega de equipe

Equipe de 3 a 4 pessoas, repositório público. As três telas são bem separadas — dá pra dividir uma por pessoa e integrar no fim. Todo mundo precisa ter commit, e eu olho isso.

Passo a passo
01

O catálogo de eventos

Antes do HTML, decidam o conteúdo. Escrevam 8 eventos plausíveis — eles vão aparecer em todas as entregas do curso, então vale caprichar.

Cada evento precisa dos campos do briefing: título, resumo, descrição, organizador, categoria, formato, cidade, data/hora, duração, gratuito ou pago, vagas e nível.

  • Pelo menos 3 categorias diferentes
  • Pelo menos um de cada formato: presencial, online e híbrido
  • Pelo menos 2 do mesmo organizador — isso importa na aula 06
  • Uma mistura de gratuitos e pagos

Nada de "Evento 1" e lorem ipsum. Catálogo genérico torna impossível avaliar se as telas funcionam — texto real tem tamanhos irregulares, e é justamente aí que o layout quebra.

02

A estrutura de arquivos

leque-de-eventos-estatico/
├── index.html            a home
├── eventos.html          a listagem
├── evento.html           o detalhe de UM evento
├── css/
│   ├── tokens.css        custom properties e tema
│   ├── base.css          reset e elementos
│   └── componentes.css   card, cabeçalho, filtros…
└── README.md

Três arquivos de CSS, não um. Vocês vão importar os três em cada página com @layer. Essa separação é o embrião do que o framework vai fazer sozinho depois — e é o que torna a discussão de escopo concreta.

03

HTML semântico ⭐

Este passo vale mais que os outros. As três páginas precisam ter:

  • Link "pular para o conteúdo" como primeiro elemento focável
  • <header> com <h1> e <nav aria-label>
  • Exatamente um <main>
  • Hierarquia de títulos sem pular níveis
  • A listagem como <ul>, cada card em <article>
  • Datas em <time datetime="…">
  • <footer>
<li>
  <article class="card-evento">
    <h3><a href="evento.html">React Recife · Meetup #42</a></h3>
    <p>Uma noite sobre Signals e o futuro da reatividade.</p>
    <time datetime="2026-09-12T19:00">12 de setembro, 19h</time>
  </article>
</li>

O teste de <section>: ela tem um título dentro? Se não tem, use <div>. Section decorativa não ajuda ninguém e ainda suja a árvore de acessibilidade.

04

Tokens e tema ⭐

Em css/tokens.css: a paleta, a escala de espaçamento, o raio de borda — e os dois temas.

:root {
  color-scheme: light dark;

  --cor-fundo: #ffffff;
  --cor-texto: #18181b;
  --cor-marca: #7B4FD0;

  --esp-1: .5rem;
  --esp-2: 1rem;
  --esp-3: 1.5rem;
  --raio: 12px;
}

@media (prefers-color-scheme: dark) {
  :root { --cor-fundo: #0d0b14; --cor-texto: #f3f0fa; }
}
  • Nenhuma cor literal fora de tokens.css. Nada de #fff perdido no componente
  • Nenhum espaçamento mágico: use a escala. Sem 13px, 17px, 22px
  • Os dois temas com contraste conferido — texto normal a 4.5:1

Nomeie pelo papel, não pela cor. --cor-marca sobrevive ao redesign; --roxo vira mentira quando a marca mudar.

05

Layout com Grid e Flex

A listagem precisa se adaptar sem media query de largura de aparelho:

.lista-eventos {
  display: grid;
  gap: var(--esp-3);
  grid-template-columns: repeat(auto-fit, minmax(min(280px, 100%), 1fr));
  list-style: none;
  padding: 0;
}

E a página inteira com o rodapé sempre embaixo:

body {
  display: grid;
  grid-template-rows: auto 1fr auto;
  min-height: 100dvh;
}

Repare no min(280px, 100%). Sem isso, numa tela de 320px o mínimo de 280px mais o padding estoura e aparece rolagem horizontal. É o bug mais comum desta entrega.

06

Pelo menos um @container ⭐

O card de evento precisa se comportar diferente conforme o espaço que recebe — não conforme o tamanho da tela.

.lista-eventos { container-type: inline-size; }

@container (min-width: 420px) {
  .card-evento {
    display: grid;
    grid-template-columns: 120px 1fr;
    gap: var(--esp-2);
  }
}

Na home, coloque a mesma lista dentro de um container estreito (uma barra lateral, por exemplo) e mostre no README que o card se comporta diferente sem mudar uma linha do HTML.

Se não funcionar: o container-type vai no pai do elemento que você quer estilizar, nunca nele mesmo.

07

@layer e um :has()

Organizem a cascata declarando as camadas no topo:

@layer reset, base, componentes, utilitarios;

E usem :has() pelo menos uma vez de forma útil — por exemplo, destacar o card de evento gratuito:

.card-evento:has(.selo-gratuito) {
  border-color: var(--cor-ok);
}

Meta explícita: o projeto inteiro precisa ter zero !important. Se você sentiu vontade de usar um, é sinal de que a organização em camadas resolve melhor. Conte no README o momento em que isso quase aconteceu.

08

O teste do teclado ⭐

Antes de entregar, solte o mouse e percorra as três telas inteiras com Tab, Shift+Tab e Enter.

  • Chega em todo link e botão?
  • O foco é sempre visível?
  • A ordem faz sentido?
  • O "pular para o conteúdo" aparece no primeiro Tab?
:focus-visible {
  outline: 2px solid var(--cor-marca);
  outline-offset: 2px;
}

Grave um vídeo curto (30s) navegando só por teclado e coloque o link no README. É a forma mais rápida de eu conferir — e de vocês perceberem o que quebrou.

09

Publique

São arquivos estáticos: GitHub Pages resolve, sem build.

  1. Repositório público, com os arquivos na raiz
  2. Settings → Pages → Deploy from branch → main / root
  3. Cole o link no README e mande no grupo

Confira no celular de verdade, não só no modo responsivo do navegador. O emulador não reproduz o zoom em campo de formulário nem o comportamento da barra de endereço.

O README
  1. Link do site publicado
  2. A tabela de tokens: quais vocês criaram e o critério de nomes
  3. Onde vocês usaram @container e por que ali
  4. Onde usaram :has() e o que ele evitou
  5. O momento em que quase usaram !important — e como resolveram
  6. O vídeo da navegação por teclado
  7. Quem fez o quê
Requisitos mínimos
  • Três telas: home, listagem e detalhe, ligadas por links
  • 8 eventos plausíveis, com todos os campos do briefing
  • Link "pular para o conteúdo" funcionando
  • Um <main>, um <h1> por página, títulos sem pular nível
  • Listagem em <ul>, cards em <article>, datas em <time datetime>
  • Toda imagem com alt adequado e width/height
  • Tokens em custom properties, sem cor literal fora de tokens.css
  • Tema claro e escuro, com color-scheme declarado
  • Grid com auto-fit e pelo menos um @container
  • @layer organizando a cascata, e zero !important
  • Pelo menos um :has() com propósito real
  • Navegável só por teclado, com :focus-visible visível
  • Sem rolagem horizontal em 360px de largura
  • Publicado, com link no README
Extras, pra quem quiser ir além ✨
  • Botão de alternar tema — sem JavaScript, usando :has() e um checkbox escondido
  • Estado vazio da listagem só com CSS: .lista:not(:has(.card-evento))
  • Formulário de busca completo e acessível (sem funcionar ainda — a aula 02 liga)
  • prefers-reduced-motion respeitado em toda transição
  • Rodar o Lighthouse e colar a pontuação de acessibilidade no README
  • Nota no README sobre onde vocês tiveram medo de colisão de nome de classe — é exatamente o assunto da aula 03
O que NÃO pode 🚫
  • JavaScript. Nenhuma linha, nem pra menu, nem pra tema
  • Bootstrap, Tailwind ou qualquer biblioteca de componentes
  • outline: none sem substituto visível
  • !important
  • <div onclick> no lugar de <button>, ou <a href="#"> que não navega
  • Placeholder no lugar de <label>
  • Escolher nível de título pelo tamanho da fonte
  • Repositório privado

  2. Abra em 360px e confira que não há rolagem horizontal
