Ambiente, projeto e deploy ▲

Sua missão: ambiente montado, projeto Next.js rodando, duas rotas escritas por você e tudo publicado na Vercel. Curto de propósito — o objetivo é que ninguém chegue na aula 2 travado em instalação.

🎯

O objetivo

Provar duas coisas: que o seu computador está pronto pro semestre inteiro, e que você entendeu a ideia da aula — um componente é uma peça escrita uma vez e usada em vários lugares. Por isso um dos passos é justamente criar a sua primeira peça.

🚀

Por que colocar no ar já na aula 1

Porque "na minha máquina funciona" deixa de ser desculpa quando existe um link que qualquer pessoa abre. E porque ver o próprio site no celular muda como você se sente sobre o que acabou de escrever — vale mais do que qualquer nota.

📖

Travou numa palavra?

Terminal, build, deploy, repositório, importar — se alguma dessas aparecer aqui e você não lembrar o que é, o guia da aula tem um dicionário com todas elas em português simples. Consultar não é trapaça: é o que todo mundo que programa faz o dia inteiro.

Passo a passo
01

Confira o Node e o npm

$ node -v v22.19.0 # precisa ser 20.9 ou maior $ npm -v 10.8.2 # ja vem junto com o Node

Guarde os dois prints. Eles entram no README — e me ajudam a diagnosticar rápido se algo der errado com você.

02

Crie o projeto

$ npx create-next-app@latest meu-primeiro-next

Respostas: TypeScript Yes · ESLint Yes · Tailwind No · App Router Yes · Turbopack Yes · alias @/* Yes.

Tailwind fica pra aula 08. Até lá o estilo é CSS comum no globals.css — que você já sabe escrever. Quem responder Yes aqui vai ficar com um projeto diferente do da turma.

Confira a versão que aparece ao subir: precisa ser Next.js 16.3 ou mais recente. Se vier 15 ou menos, o npx pegou uma versão guardada de antes — rode com @latest explícito.

03

Crie um componente de verdade ⭐

Este passo vale mais que os outros: é o conceito da aula virando experiência. Você vai escrever uma peça e usá-la em duas páginas.

Crie a pasta components/ na raiz do projeto, e dentro dela o arquivo Cabecalho.tsx:

// components/Cabecalho.tsx
export default function Cabecalho() {
  return (
    <header className="cabecalho">
      <h1>Nome do seu projeto</h1>
    </header>
  );
}

Agora use ele no app/layout.tsx:

import Cabecalho from "@/components/Cabecalho";

// ...dentro do <body>, antes do {children}:
<Cabecalho />

E o estilo, em app/globals.css — CSS comum, do jeito que você já escreve:

.cabecalho {
  display: flex;
  gap: 16px;
  padding: 16px;
  border-bottom: 1px solid #27272a;
}

Registre no README, com suas palavras, o que é um componente e por que escrever o cabeçalho uma vez só é melhor do que copiar em cada página. Essa frase é o que eu vou ler primeiro na correção — e ela tem que ser sua, não do ChatGPT.

04

Duas rotas e navegação

  • Personalize a home (app/page.tsx) com o nome do seu projeto
  • Crie app/sobre/page.tsx contando quem é você e o que espera do semestre
  • Ligue as duas com <Link> do next/link
import Link from "next/link";

<Link href="/sobre">Sobre mim</Link>

Use <Link>, não <a>. Troque um pelo outro e repare: com <a> a tela pisca a cada clique; com <Link> não. Anote a diferença — a aula 2 explica o porquê.

05

Rode o build antes de subir

$ npm run build

É exatamente o comando que a Vercel executa. Se passar aqui, passa lá.

Repare na lista de rotas que o build imprime — todas as páginas que você criou devem aparecer ali. Se faltar alguma, o arquivo não está com o nome page.tsx ou está na pasta errada.

06

Publique na Vercel

  1. Suba num repositório público no GitHub
  2. vercel.com → Add New… → Project → importe
  3. Não mexa em configuração nenhuma → Deploy
  4. Cole o link no README e mande no grupo
07

Marco do projeto: forme a equipe

Este passo é da equipe, não individual.

  • Equipe de 3 a 4 pessoas, definida
  • Um repositório da equipe, com todo mundo como colaborador
  • Um README.md com os nomes de todo mundo

O tema já está definido: a turma inteira constrói o Leque de Vagas — um site de vagas de tecnologia pra quem está em transição de carreira. Vocês não precisam decidir nada sobre isso hoje. O briefing completo, com as telas e o que entra em cada checkpoint, vem na aula 02.

Requisitos mínimos
  • Node 20.9+ e npm funcionando, com os prints no README
  • Projeto em Next.js 16.3+, criado com create-next-app
  • Rota /sobre escrita por você, ligada à home por <Link>
  • Um componente Cabecalho em arquivo próprio, usado no layout
  • No README: o que é um componente, com suas palavras
  • npm run build passando sem erro
  • Publicado na Vercel, com o link no README
  • Equipe formada, com repositório e ideia de tema
Extras, pra quem quiser ir além ✨
  • Um segundo componente — Rodape — também no layout
  • Uma terceira rota, /contato, ligada às outras pelo cabeçalho
  • Configure metadata no layout e veja o título mudar na aba
  • Mude alguma coisa no site, mande pro GitHub, e veja a Vercel atualizar sozinha em um minuto
  • Personalize o CSS do globals.css com as suas cores
O que NÃO pode 🚫
  • Deixar o package-lock.json de fora do repositório — ele precisa ser enviado junto
  • Pages Router — o curso inteiro é App Router
  • <a href> para navegação interna
  • Subir node_modules ou .next (o .gitignore gerado já cuida — confira se veio)
  • Repositório privado: ele é parte do seu portfólio
