antes de começar · sejamos honestos

De onde a gente parte

Você já sabe

  • Escrever HTML: <header>, <ul>, <a>
  • Estilizar com CSS
  • JavaScript básico: variável, função, array

Você não precisa saber

  • React — a gente aprende aqui, do zero
  • Next.js — idem
  • TypeScript, banco de dados, servidor

Ninguém aqui precisa ter feito React antes. Se você sabe fazer uma página HTML, você tem o que precisa pra aula de hoje.

o problema · e você já viveu isso

Repare no que se repete

📄 index.html
<header> <h1>Minha Loja</h1> <nav> <a href="index.html">Início</a> <a href="sobre.html">Sobre</a> </nav> </header> <main>Bem-vindo!</main>
📄 sobre.html
/* exatamente o mesmo cabeçalho */ <header> <h1>Minha Loja</h1> <nav> <a href="index.html">Início</a> <a href="sobre.html">Sobre</a> </nav> </header> <main>Quem somos</main>

Copiar e colar o cabeçalho funciona. Com duas páginas. O problema aparece na décima.

Agora adicione um item no menu

O cabeçalho é uma coisa só. Mas está escrito em doze lugares. Esse é o problema que o resto da aula resolve.

Essa peça tem nome: componente. Um pedaço de interface com nome próprio, escrito uma vez e reaproveitado. É a palavra mais importante do semestre.

como se escreve um componente

Uma função que devolve HTML

function Cabecalho() { return ( <header> <h1>Minha Loja</h1> <nav> <a href="/">Início</a> <a href="/sobre">Sobre</a> </nav> </header> ); }
  • É uma função JavaScript comum — a mesma que você já escreve
  • Só que ela devolve HTML, e o nome começa com letra maiúscula
  • Esse HTML dentro do JavaScript tem nome: JSX

Usar fica assim: <Cabecalho />. Igualzinho a uma tag HTML — só que quem inventou a tag foi você.

os nomes · duas coisas, dois papéis

O que é React, o que é Next

React

A biblioteca que permite escrever interface em componentes — exatamente o que a gente acabou de ver. Ela sozinha não sabe o que é uma página, nem um endereço.

Next.js

A ferramenta construída em volta do React. Ela traz o que falta pra virar um site de verdade: endereços, organização de pastas, e publicar no ar.

React é o motor. Next.js é o carro montado em volta do motor — com direção, portas e placa.

Você vai usar os dois o semestre inteiro sem precisar separar na cabeça. Só é bom saber de quem é cada nome quando for pesquisar no Google.

antes de digitar · três palavras novas

O que é aquela tela preta

O terminal

Uma janela onde você digita ordens pro computador, em vez de clicar. Escreve uma linha, aperta Enter, ele responde. Só isso.

Node

O programa que faz o JavaScript rodar fora do navegador. Até hoje o seu JS só vivia dentro do Chrome. Agora vai rodar direto na máquina.

Pacote

Um pedaço de programa que outra pessoa já escreveu e deixou de graça pra você usar. Ninguém faz tudo do zero.

Vai parecer estranho nos primeiros dias. Daqui a um mês você abre o terminal sem pensar — como quem abre o WhatsApp.

setup · o combinado técnico

O ambiente do semestre

Node 20.9+

Precisa ser essa versão ou mais nova. O Next 16 não funciona com versão velha.

npm

O entregador dos pacotes: você diz o que precisa, ele baixa da internet. Já vem com o Node.

VS Code + Git

O editor onde você escreve, e o programa que guarda o histórico das suas mudanças. Conta no GitHub é obrigatória — a entrega é por lá.

💻 confira antes de continuar
$ node -v v20.11.0 ← precisa ser 20.9 ou maior $ npm -v 10.8.2 ← já vem junto com o Node

o que veio na caixa

A estrutura de pastas

meu-primeiro-next/ ├── app/ ← é aqui que você trabalha │ ├── layout.tsx a moldura de todas as páginas │ ├── page.tsx a página inicial │ └── globals.css estilos gerais ├── public/ imagens e arquivos soltos ├── package.json a lista de compras do projeto └── node_modules/ as compras entregues (não mexa)

app/

A pasta que importa. Praticamente tudo que você fizer no semestre acontece dentro dela.

node_modules/

É onde os pacotes baixados ficam. Milhares de arquivos que você não escreveu. Não abra, não edite, não suba pro GitHub — se sumir, um npm install traz tudo de volta.

live code · a dívida do começo da aula

layout.tsx: o cabeçalho, uma vez só

📄 app/layout.tsx
export default function RootLayout({ children }) { return ( <html lang="pt-BR"> <body> <header>Minha Loja</header> {/* ← escrito UMA vez */} {children} {/* ← cada página entra aqui */} <footer>© 2026</footer> {/* ← e o rodapé também */} </body> </html> ); }

Lembra das 12 páginas com o mesmo cabeçalho copiado? Acabou. Mudou o menu aqui, mudou no site inteiro. Esse é o pagamento da promessa do começo da aula.

live code · o seu primeiro componente

page.tsx: o conteúdo

📄 app/page.tsx
export default function Home() { return ( <main> <h1>Bem-vindo à Minha Loja</h1> <p>Esse é o meu primeiro projeto Next.js.</p> </main> ); }

Uma função com nome. Que devolve HTML. Você acabou de escrever um componente — o mesmo conceito do slide de trás.

o conceito · guarde esta tabela

O endereço é a pasta

Você não configura endereço em lugar nenhum. Você cria a pasta — e o endereço passa a existir.

Você cria o arquivoO endereço vira
app/page.tsx/
app/sobre/page.tsx/sobre
app/contato/page.tsx/contato
app/blog/posts/page.tsx/blog/posts

O arquivo tem que se chamar page.tsx, exatamente assim. sobre.tsx solto dentro de app/ não vira endereço nenhum — é o erro mais comum da semana 1.

importante · antes de confiar

Compare com o que a gente fez

Bateu com a aula?

Ótimo — agora você tem duas fontes dizendo a mesma coisa, e entendeu de dois jeitos diferentes. Isso fixa.

Veio diferente?

Muito material de Next na internet é de versões antigas, e a IA aprendeu com esse material. Se falar em pages/ ou getServerSideProps, é resposta velha — me pergunte.

Usar IA neste curso é liberado e incentivado. A regra é uma só: você precisa entender o que ela te deu. Código que você não sabe explicar não conta como seu — nem aqui, nem no primeiro emprego.

deploy · antes de escrever a segunda linha

No ar hoje, não no fim

Suba o código pro GitHub

Um repositório novo, público, com o projeto que você acabou de criar.

Conecte na Vercel

Login com GitHub, "Import Project", escolhe o repositório. Não precisa configurar nada.

Ela faz o build sozinha

Build = empacotar o projeto no formato final, pronto pra ser servido. É o que o npm run dev não faz.

Recebe um link

Termina em .vercel.app. Abre no celular. Manda pra sua mãe.

A partir de agora, todo git push atualiza o site sozinho. Você nunca mais vai "publicar" manualmente nesta disciplina.

projeto do semestre · o que a gente vai construir

Leque de Vagas

Um site onde pessoas em transição de carreira encontram vagas de tecnologia. É o projeto que vai crescer nas 18 aulas seguintes — o mesmo pra turma toda.

Você não escolhe o tema

E isso é de propósito: a gente gasta o semestre inteiro aprendendo Next, não decidindo o que fazer.

Cada aula, uma peça

Hoje é a página no ar. Depois vêm listagem, busca, login, banco de dados, deploy.

Mesmo projeto, seu código

Todo mundo constrói o mesmo produto — mas cada equipe escreve o seu, do seu jeito.

A vantagem de todo mundo no mesmo projeto: quando alguém trava, a dúvida serve pra turma inteira. E eu consigo mostrar a solução no telão sem ter que entender 8 temas diferentes.

projeto do semestre · agora

Formação das equipes

  • 3 a 4 pessoas. Menos que isso sobrecarrega; mais que isso alguém some.
  • Criem um repositório da equipe no GitHub, com todo mundo dentro, ainda hoje.
  • Nome sugerido: leque-de-vagas-equipe-X
  • O briefing completo — telas, funcionalidades e o que entra em cada checkpoint — vem na aula 02.

Hoje o entregável do time é só o repositório criado, com todo mundo com acesso. O código vem na semana que vem.
