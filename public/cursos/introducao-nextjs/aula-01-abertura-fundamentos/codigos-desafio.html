O projeto linha por linha

O desafio resolvido, comentado. Use como referência quando travar — mas tente antes. O que importa aqui não é a sintaxe: é entender por que o cabeçalho existe em um lugar só.

🧭

Poucos arquivos, e só

A aula 1 inteira cabe em cinco arquivos. Cada um vai ganhar camadas nas próximas 18 aulas — mas a espinha é esta.

A estrutura
meu-primeiro-next/
├── app/
│   ├── layout.tsx          ← a moldura de todas as páginas
│   ├── page.tsx            ← rota /
│   ├── sobre/page.tsx      ← rota /sobre
│   └── globals.css         ← o CSS do projeto
├── components/
│   └── Cabecalho.tsx       ← a peça reutilizável ⭐
├── public/
├── next.config.ts
└── package.json
app/layout.tsx
import type { Metadata } from "next";
import Cabecalho from "@/components/Cabecalho";
import "./globals.css";

// vira <title> e <meta name="description"> sozinho
export const metadata: Metadata = {
  title: "Meu primeiro Next",
  description: "Projeto da aula 01 de Introdução ao Next.js",
};

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    // lang="pt-BR" importa: o leitor de tela usa pra escolher a voz
    <html lang="pt-BR">
      <body>
        /* a peça, escrita uma vez e usada aqui */
        <Cabecalho />

        <main className="conteudo">{children}</main>
      </body>
    </html>
  );
}
💡

Por que o cabeçalho fica no layout

Porque o layout envolve todas as páginas. Escrito ali uma vez, o cabeçalho aparece em /, em /sobre e em qualquer rota que você criar depois. Se ele estivesse dentro de cada page.tsx, você estaria de volta ao problema das doze páginas com o menu copiado.

components/Cabecalho.tsx ⭐

O componente do desafio. Um arquivo, uma função, um nome com maiúscula.

import Link from "next/link";

// Uma função que devolve HTML. Isso é um componente.
// O "export default" é o que permite importar em outro arquivo.
export default function Cabecalho() {
  return (
    <header className="cabecalho">
      <Link href="/">Início</Link>
      <Link href="/sobre">Sobre</Link>
    </header>
  );
}
💡

Repare em três coisas

1. Cabecalho começa com maiúscula — é assim que o Next diferencia a sua peça de uma tag do HTML. 2. É className, não class. 3. Tudo está dentro de um elemento (<header>) — uma função só consegue devolver uma coisa.

app/globals.css

CSS comum, do jeito que você já sabe. Nada de novo aqui — só as classes que os componentes usam.

/* o que vale pro site inteiro */
body {
  margin: 0;
  min-height: 100vh;
  background: #09090b;
  color: #fafafa;
  font-family: system-ui, sans-serif;
}

/* a classe usada em <header className="cabecalho"> */
.cabecalho {
  display: flex;
  gap: 16px;
  padding: 16px;
  border-bottom: 1px solid #27272a;
}

.conteudo {
  max-width: 640px;
  margin: 0 auto;
  padding: 32px;
}

.rodape {
  padding: 16px;
  border-top: 1px solid #27272a;
  color: #a1a1aa;
}

Por que CSS puro por enquanto

Você já sabe CSS — então ele não custa nada de aprendizado agora, e dá pra focar no que é novo de verdade: o componente. Na aula 08 a gente entra no Tailwind e você vai entender o que ele resolve, tendo sentido a diferença. Até lá, CSS comum no globals.css.

app/page.tsx
// Isto também é um componente — a diferença é que ele está
// num arquivo chamado page.tsx, e por isso vira uma página.
export default function Home() {
  return (
    <section>
      <h1>Meu primeiro Next</h1>
      <p>
        O cabeçalho acima não está escrito neste arquivo — ele vem
        do layout, e aparece em todas as páginas.
      </p>
    </section>
  );
}
app/sobre/page.tsx

A pasta criou a rota. Só isso — nenhum arquivo de configuração.

import type { Metadata } from "next";

// metadata da página sobrescreve a do layout
export const metadata: Metadata = {
  title: "Sobre mim · Meu primeiro Next",
};

export default function Sobre() {
  return (
    <section>
      <h1>Sobre mim</h1>
      <p>
        Quem eu sou e o que espero deste semestre.
      </p>
    </section>
  );
}
Extra · o segundo componente

Se você fez o extra: components/Rodape.tsx. Mesma receita do cabeçalho — e é exatamente esse "mesma receita" que é o ponto.

export default function Rodape() {
  return (
    <footer className="rodape">
      © 2026 — feito na aula 01
    </footer>
  );
}
🎯

O padrão que se repete

Criar um componente é sempre isto: um arquivo, uma função com nome maiúsculo, export default, e HTML no return. Nas próximas 18 aulas você vai fazer isso centenas de vezes — só que as peças vão ficando mais espertas.

O que o build revela

Rode npm run build e confira: todas as páginas que você criou têm que aparecer nesta lista.

$ npm run build Route (app) ┌ / ├ /_not-found ├ /sobre └ /contato
🔎

Faltou alguma rota?

Se você criou /contato e ele não aparece aqui, é quase sempre uma destas duas: o arquivo não se chama exatamente page.tsx, ou não está dentro de uma pasta com o nome da rota. O build é o jeito mais rápido de conferir isso.

Se der errado
# 404 na rota que você criou → o arquivo precisa se chamar page.tsx, dentro da pasta. app/sobre.tsx não vira rota. # Port 3000 is already in use → npm run dev -p 3001, ou pare a execução anterior # o estilo do componente nao aplica → voce escreveu class= em vez de className= No JSX o atributo tem outro nome. # Adjacent JSX elements must be wrapped → voce devolveu 2 elementos soltos. Envolva tudo em um so: <main>, <div> ou <>...</> # build passa local e falha na Vercel → quase sempre maiúscula em import. Windows ignora, Linux não.
