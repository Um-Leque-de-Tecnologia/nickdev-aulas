Aula 01 · guia de conteúdo

Fundamentos e setup

A ideia que organiza o curso inteiro — o componente, uma peça de interface escrita uma vez e usada em muitos lugares — e o passo a passo pra deixar o ambiente pronto e o primeiro deploy no ar.

🎯 O que esta aula assume. Só isto: HTML, CSS e JavaScript básico (variável, função, array). Você não precisa saber React — a gente começa do zero aqui. Tudo que for de React ou de Next é ensinado ao longo do caminho. Se HTML ou JS estiverem enferrujados, fale nesta semana: recuperar agora é muito mais fácil do que na aula 5.

O problema: HTML que se repete

Antes de falar de Next.js, vale entender que dor ele resolve. E é uma dor que você provavelmente já sentiu.

Imagine um site em HTML puro, com duas páginas. O cabeçalho é o mesmo nas duas:

<!-- index.html -->
<header>
  <h1>Minha Loja</h1>
  <nav>
    <a href="index.html">Início</a>
    <a href="sobre.html">Sobre</a>
  </nav>
</header>
<main>Bem-vindo!</main>

<!-- sobre.html — o MESMO cabeçalho, copiado -->
<header>
  <h1>Minha Loja</h1>
  <nav>
    <a href="index.html">Início</a>
    <a href="sobre.html">Sobre</a>
  </nav>
</header>
<main>Quem somos</main>

Copiar e colar funciona bem — com duas páginas. O problema aparece na décima.

A conta que não fecha

Agora o cliente pede pra adicionar "Contato" no menu. Seu site tem 12 páginas. Então:

  • Você abre 12 arquivos
  • Faz a mesma edição 12 vezes
  • Esquece uma — e o site fica inconsistente sem ninguém perceber

Repare no absurdo: o cabeçalho é uma coisa só, conceitualmente. Mas está escrito em doze lugares diferentes. É esse descompasso que todo o resto desta aula existe pra resolver.

Componente: a peça reutilizável

E se o cabeçalho fosse uma peça? Escrita uma vez, com um nome próprio, e usada em quantas páginas você quiser. Mudou a peça, mudou em todas de uma vez.

Essa peça tem nome: componente.

Guarde esta definição. Um componente é um pedaço de interface com nome próprio, escrito uma vez e reaproveitado onde precisar. É a palavra mais importante do semestre inteiro — tudo que vem depois é variação disso.

A analogia do LEGO

Você não esculpe um castelo de LEGO de um bloco só. Você monta peças pequenas — uma parede, uma janela, uma torre — e depois combina. Se a janela precisar mudar, você muda o molde da janela, não cada castelo.

Uma página em Next.js é isso: um monte de peças combinadas. Cabeçalho, lista de produtos, rodapé. Cada uma escrita separadamente, cada uma com seu nome.

JSX: HTML dentro do JavaScript

Na prática, um componente é uma função JavaScript comum — a mesma que você já sabe escrever. Com duas diferenças: o nome começa com letra maiúscula, e ela devolve HTML.

function Cabecalho() {
  return (
    <header>
      <h1>Minha Loja</h1>
      <nav>
        <a href="/">Início</a>
        <a href="/sobre">Sobre</a>
      </nav>
    </header>
  );
}

Esse HTML escrito dentro do JavaScript tem nome: JSX. Não é uma string, não está entre aspas — é escrito direto, e o Next entende.

Como se usa

Depois de criado, o componente vira uma tag:

<Cabecalho />

Igualzinho a uma tag HTML — só que quem inventou a tag foi você. É por isso que o nome precisa começar com maiúscula: é assim que o Next diferencia <header> (tag do HTML) de <Cabecalho /> (peça sua).

Três detalhes que pegam no começo

No HTML você escreveNo JSX viraPor quê
class="botao"className="botao"class já é palavra reservada do JavaScript
<br><br />toda tag precisa fechar, sem exceção
vários elementos soltostudo dentro de um elementoa função só consegue devolver uma coisa
O erro mais comum da primeira semana. Escrever class em vez de className. O estilo simplesmente não aplica e nenhum erro aparece. Quando o CSS "não funcionar sem motivo", confira isso primeiro.

React e Next: quem faz o quê

Dois nomes vão aparecer o semestre inteiro. Vale saber de quem é cada um — principalmente na hora de pesquisar no Google.

NomeO que éO que traz
React A biblioteca que permite escrever interface em componentes Componente, JSX, e a forma de combinar as peças
Next.js A ferramenta construída em volta do React Endereços, organização de pastas, e publicar no ar

React sozinho não sabe o que é uma página, nem o que é um endereço como /sobre. Ele sabe montar peças de interface — e só. Next.js é o que transforma essas peças num site de verdade.

A analogia. React é o motor. Next.js é o carro montado em volta do motor: direção, portas, placa. Você dirige o carro sem precisar pensar no motor separadamente — mas quando o erro é do motor, ajuda saber que ele tem outro nome.

Na prática, você vai escrever componentes (React) dentro da estrutura de pastas do Next. Sem precisar separar as duas coisas na cabeça.

Node 20.9+

O Next.js 16 exige Node 20.9 ou mais novo. Confira:

$ node -v v22.19.0

Se aparecer menos que isso, ou "comando não encontrado", instale a versão LTS em nodejs.org e reabra o terminal.

Trabalha com vários projetos? Vale usar um gerenciador de versões — nvm (macOS/Linux) ou fnm (multiplataforma, mais rápido). Eles deixam cada projeto na sua versão de Node sem conflito.

pnpm

Este curso usa pnpm em vez de npm. O Node moderno já traz o Corepack, que instala pra você:

$ corepack enable pnpm $ pnpm -v 10.x

Por que pnpm

Aspectonpmpnpm

Instalação—bem mais rápida a partir da segunda vez

Na prática, o que muda pra você: quase nada. npm install vira pnpm install, npm run dev vira pnpm dev. Com cinco projetos Next na máquina, a economia de disco passa de 1 GB — o que, como a gente vai ver, não é detalhe.

A regra do App Router

Pasta = rota. Arquivo page.tsx = a página. Não existe arquivo de configuração de rotas.

Você criaURL que nasce
app/page.tsx/
app/sobre/page.tsx/sobre
app/contato/page.tsx/contato
app/blog/posts/page.tsx/blog/posts
Pegadinha nº 1: criar app/sobre.tsx em vez de app/sobre/page.tsx. Sem o arquivo chamado exatamente page.tsx dentro da pasta, a rota não existe — e você toma 404 sem nenhum erro no terminal.

Os outros nomes reservados — layout, loading, error, not-found, template — são o assunto da aula 2.

layout e page

Aqui a promessa do começo do guia é paga. Lembra do cabeçalho copiado em doze arquivos? O layout.tsx é onde ele passa a existir uma vez só.

📄 app/layout.tsx
export default function RootLayout({ children }) {
  return (
    <html lang="pt-BR">
      <body>
        <header>Minha Loja</header>   ← escrito UMA vez

        {children}                       ← cada página entra aqui

        <footer>© 2026</footer>      ← e o rodapé também
      </body>
    </html>
  );
}
  • O que está no layout aparece em todas as páginas do site
  • Mudou o menu aqui? Mudou no site inteiro, de uma vez
  • O layout raiz é obrigatório e é o único lugar com <html> e <body>
  • children é o buraco onde a página da vez é encaixada
Por que "children". É a palavra que o React usa pra dizer "o conteúdo que vem de dentro". Você não precisa entender o mecanismo hoje — só saber que é ali que a página entra.
📄 app/page.tsx
export default function Home() {
  return (
    <main>
      <h1>Bem-vindo à Minha Loja</h1>
    </main>
  );
}

Uma função com nome, que devolve HTML. É um componente — o mesmo conceito das seções anteriores. O export default na frente é o que diz ao Next: "esta é a página desta pasta".

Criando uma rota nova

Este é o exercício que fecha a aula, e ele é o coração do desafio da semana. Vamos criar a página /sobre.

Passo 1 — crie a pasta

Dentro de app/, crie uma pasta chamada sobre. O nome da pasta é o endereço.

Passo 2 — crie o arquivo

Dentro dela, um arquivo chamado exatamente page.tsx:

📄 app/sobre/page.tsx
export default function Sobre() {
  return (
    <main>
      <h1>Sobre mim</h1>
      <p>Meu nome é Fulana e este é meu primeiro projeto Next.js.</p>
    </main>
  );
}

Passo 3 — abra no navegador

Vá em http://localhost:3000/sobre. A página está lá. Você não configurou rota nenhuma — só criou uma pasta e um arquivo.

E repare: o cabeçalho do layout aparece nela também, sem você ter escrito nada. É exatamente o problema das doze páginas, resolvido.

Passo 4 — ligue as duas páginas

Pra navegar entre elas, o Next tem uma tag própria. No layout.tsx:

import Link from "next/link";

// ...dentro do header:
<Link href="/">Início</Link>
<Link href="/sobre">Sobre</Link>
Por que Link e não <a>. Com <a> o navegador recarrega a página inteira — tela branca e tudo de novo. Com Link, o Next troca só o que mudou e a navegação fica instantânea. Use sempre Link para páginas do seu próprio site; <a> só para links externos.

Deploy na Vercel

Vamos publicar na aula 1, antes de escrever a segunda linha de código. Não é enfeite: é o que transforma "na minha máquina funciona" num link que a equipe inteira vê.

  1. Rode pnpm build local. Passou? Ótimo — é o mesmo comando que a Vercel roda
  2. git push pro GitHub, em repositório público
  3. Em vercel.com → Add New… → Project → importe o repositório
  4. Não mexa em nenhuma configuração. A Vercel reconhece o Next sozinha
  5. Deploy

A partir daí, todo git push na branch principal republica. E cada Pull Request ganha um preview deployment com URL própria — o que vai ser essencial pro code review do projeto em equipe.

Rode pnpm build antes de dar push. É literalmente o que a Vercel executa. Erro de tipo que o dev tolera, o build reprova — e é bem mais rápido descobrir isso local.

Erros comuns 🔧

404 numa página que acabei de criar

O arquivo precisa se chamar exatamente page.tsx, dentro de uma pasta. app/sobre.tsx não vira rota.

Port 3000 is already in use

Tem outra execução rodando. Pare a anterior, ou use pnpm dev -p 3001.

O CSS não aplica e nenhum erro aparece

Quase sempre é class escrito no lugar de className. No JSX o atributo tem outro nome.

Adjacent JSX elements must be wrapped…

Você devolveu dois elementos soltos. Envolva tudo num só — <main>, <div>, ou <>…</> se não quiser criar uma tag de verdade.

Unexpected token / erro estranho no JSX

Confira se toda tag fechou. No JSX <br> e <img> precisam virar <br /> e <img />.

Module not found: Can't resolve '@/components/…'

Confira a maiúscula no nome do arquivo. No Windows funciona botao quando o arquivo é Botao; no servidor da Vercel (Linux) não. É um erro que só aparece no deploy.

O build passa local e falha na Vercel

Quase sempre uma destas três: diferença de maiúscula em import, variável de ambiente que existe só na sua máquina, ou versão de Node diferente.

Disco cheio

node_modules de um projeto Next passa de 500 MB. Com vários projetos, o disco enche rápido — e o sintoma costuma ser um erro que não fala nada de disco. É outra razão pra usar pnpm, que compartilha os pacotes.
