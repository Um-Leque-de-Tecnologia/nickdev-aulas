Fundamentos e setup

A ideia que organiza o curso inteiro — o componente, uma peça de interface escrita uma vez e usada em muitos lugares — e o passo a passo pra deixar o ambiente pronto e o primeiro deploy no ar.

🎯 O que esta aula assume. Só isto: HTML, CSS e JavaScript básico (variável, função, array). Você não precisa saber React — a gente começa do zero aqui. Tudo que for de React ou de Next é ensinado ao longo do caminho. Se HTML ou JS estiverem enferrujados, fale nesta semana: recuperar agora é muito mais fácil do que na aula 5.

O dicionário desta aula

Toda área tem suas palavras estranhas, e programação tem muitas. Aqui estão as desta aula, em português normal. Volte aqui sempre que esbarrar numa que você esqueceu — isso é esperado, não é vergonha.

As ferramentas

PalavraO que é, em palavras simples
Terminal Uma janela preta onde você digita ordens pro computador em vez de clicar. É como conversar com a máquina por bilhetinhos: você escreve uma linha, aperta Enter, ela responde. Também chamam de "prompt", "console" ou "linha de comando" — é tudo a mesma janela.
Node Um programa que faz o JavaScript funcionar fora do navegador. Até hoje o seu JavaScript só rodava dentro do Chrome. O Node deixa ele rodar direto no seu computador, como qualquer outro programa.
Pacote (ou biblioteca) Um pedaço de programa que outra pessoa já escreveu e disponibilizou de graça pra você usar. Em vez de fazer tudo do zero, você pega pronto. É como usar farinha comprada em vez de moer o trigo.
npm O entregador dos pacotes. Você diz o que precisa, ele baixa da internet e guarda na pasta do projeto. Já vem junto com o Node — não precisa instalar.
Framework Um conjunto grande de coisas prontas, com um jeito certo de organizar seu projeto. Ele não te dá só peças: ele te dá a planta da casa. Next.js é um framework.

O projeto

PalavraO que é, em palavras simples
Raiz do projeto A pasta mais de fora do seu projeto — aquela que contém todas as outras. Quando eu disser "crie na raiz", é ali, não dentro de app/.
Componente Um pedaço de tela com nome próprio, escrito uma vez e usado em vários lugares. Um cabeçalho, um botão, um card. É a palavra mais importante do semestre.
JSX HTML escrito dentro do JavaScript. Só isso. Quando você vê <h1> no meio de um arquivo .tsx, aquilo é JSX.
export default Uma plaquinha que diz "esta é a peça principal deste arquivo, pode levar". Sem ela, outros arquivos não conseguem usar o que você escreveu.
import O contrário: "quero usar aqui uma peça que está em outro arquivo". Você escreve o nome dela e de onde ela vem.
Rota Um endereço do seu site. O /sobre em meusite.com/sobre é uma rota. Neste curso, criar uma pasta cria uma rota.

Colocar no ar

PalavraO que é, em palavras simples
Servidor Um computador que fica ligado o tempo todo, em algum lugar do mundo, esperando alguém pedir o seu site pra entregar. Não é nada mágico: é um computador, só que sempre acordado.
localhost:3000 O seu site rodando só na sua máquina, pra você testar. "localhost" quer dizer "aqui mesmo". Ninguém mais no mundo consegue abrir esse endereço.
Build Empacotar o projeto no formato final, pronto pra ser publicado. Enquanto você desenvolve, o projeto está espalhado e cheio de coisa de rascunho. O build junta tudo e limpa. Fala-se "rodar o build".
Repositório A pasta do seu projeto guardada na internet, com todo o histórico de mudanças. Fica no GitHub. Também chamam só de "repo".
Deploy Colocar o site no ar. Pegar o projeto que está na sua máquina e botar num servidor, pra qualquer pessoa conseguir abrir. Fala-se "fazer o deploy" ou "subir o projeto".
Vercel Uma empresa que hospeda sites de graça (até certo tamanho). É quem vai guardar o seu projeto e te dar um link. Foi criada pelas mesmas pessoas do Next.js, por isso combina tão bem.
Não decore nada disto. Ninguém aprende vocabulário técnico decorando lista — a gente aprende usando. Você vai ouvir cada uma dessas palavras dezenas de vezes no semestre, e daqui a um mês vai usar sem perceber. Esta tabela é só pra consultar quando travar.

O problema: HTML que se repete

Antes de falar de Next.js, vale entender que dor ele resolve. E é uma dor que você provavelmente já sentiu.

Imagine um site em HTML puro, com duas páginas. O cabeçalho é o mesmo nas duas:

<!-- index.html -->
<header>
  <h1>Minha Loja</h1>
  <nav>
    <a href="index.html">Início</a>
    <a href="sobre.html">Sobre</a>
  </nav>
</header>
<main>Bem-vindo!</main>

<!-- sobre.html — o MESMO cabeçalho, copiado -->
<header>
  <h1>Minha Loja</h1>
  <nav>
    <a href="index.html">Início</a>
    <a href="sobre.html">Sobre</a>
  </nav>
</header>
<main>Quem somos</main>

Copiar e colar funciona bem — com duas páginas. O problema aparece na décima.

A conta que não fecha

Agora o cliente pede pra adicionar "Contato" no menu. Seu site tem 12 páginas. Então:

  • Você abre 12 arquivos
  • Faz a mesma edição 12 vezes
  • Esquece uma — e o site fica inconsistente sem ninguém perceber

Repare no absurdo: o cabeçalho é uma coisa só, conceitualmente. Mas está escrito em doze lugares diferentes. É esse descompasso que todo o resto desta aula existe pra resolver.

Componente: a peça reutilizável

E se o cabeçalho fosse uma peça? Escrita uma vez, com um nome próprio, e usada em quantas páginas você quiser. Mudou a peça, mudou em todas de uma vez.

Essa peça tem nome: componente.

Guarde esta definição. Um componente é um pedaço de interface com nome próprio, escrito uma vez e reaproveitado onde precisar. É a palavra mais importante do semestre inteiro — tudo que vem depois é variação disso.

A analogia do LEGO

Você não esculpe um castelo de LEGO de um bloco só. Você monta peças pequenas — uma parede, uma janela, uma torre — e depois combina. Se a janela precisar mudar, você muda o molde da janela, não cada castelo.

Uma página em Next.js é isso: um monte de peças combinadas. Cabeçalho, lista de produtos, rodapé. Cada uma escrita separadamente, cada uma com seu nome.

JSX: HTML dentro do JavaScript

Na prática, um componente é uma função JavaScript comum — a mesma que você já sabe escrever. Com duas diferenças: o nome começa com letra maiúscula, e ela devolve HTML.

function Cabecalho() {
  return (
    <header>
      <h1>Minha Loja</h1>
      <nav>
        <a href="/">Início</a>
        <a href="/sobre">Sobre</a>
      </nav>
    </header>
  );
}

Esse HTML escrito dentro do JavaScript tem nome: JSX. Não é uma string, não está entre aspas — é escrito direto, e o Next entende.

Como se usa

Depois de criado, o componente vira uma tag:

<Cabecalho />

Igualzinho a uma tag HTML — só que quem inventou a tag foi você. É por isso que o nome precisa começar com maiúscula: é assim que o Next diferencia <header> (tag do HTML) de <Cabecalho /> (peça sua).

Três detalhes que pegam no começo

No HTML você escreveNo JSX viraPor quê
class="botao"className="botao"class já é palavra reservada do JavaScript
<br><br />toda tag precisa fechar, sem exceção
vários elementos soltostudo dentro de um elementoa função só consegue devolver uma coisa
O erro mais comum da primeira semana. Escrever class em vez de className. O estilo simplesmente não aplica e nenhum erro aparece. Quando o CSS "não funcionar sem motivo", confira isso primeiro.

React e Next: quem faz o quê

Dois nomes vão aparecer o semestre inteiro. Vale saber de quem é cada um — principalmente na hora de pesquisar no Google.

NomeO que éO que traz
React A biblioteca que permite escrever interface em componentes Componente, JSX, e a forma de combinar as peças
Next.js A ferramenta construída em volta do React Endereços, organização de pastas, e publicar no ar

React sozinho não sabe o que é uma página, nem o que é um endereço como /sobre. Ele sabe montar peças de interface — e só. Next.js é o que transforma essas peças num site de verdade.

A analogia. React é o motor. Next.js é o carro montado em volta do motor: direção, portas, placa. Você dirige o carro sem precisar pensar no motor separadamente — mas quando o erro é do motor, ajuda saber que ele tem outro nome.

Na prática, você vai escrever componentes (React) dentro da estrutura de pastas do Next. Sem precisar separar as duas coisas na cabeça.

Node 20.9+

Lembra do dicionário? Node é o programa que faz o JavaScript rodar fora do navegador. Sem ele, nada do que vem a seguir funciona — então é a primeira coisa a conferir.

O Next.js 16 precisa da versão 20.9 ou mais nova. Pra descobrir qual você tem, abra o terminal e digite:

$ node -v v22.19.0

Se aparecer menos que isso, ou "comando não encontrado", instale a versão LTS em nodejs.org e reabra o terminal.

Trabalha com vários projetos? Vale usar um gerenciador de versões — nvm (macOS/Linux) ou fnm (multiplataforma, mais rápido). Eles deixam cada projeto na sua versão de Node sem conflito.

npm

O npm é o entregador dos pacotes: você diz o que o projeto precisa, e ele baixa da internet. Lembra do dicionário — pacote é um pedaço de programa que outra pessoa já escreveu e deixou pronto pra você usar.

Boa notícia: você não precisa instalar nada. O npm vem junto com o Node. Se o node -v funcionou, o npm já está aí também.

Confira:

$ npm -v 10.8.2

Os quatro comandos que você vai usar o semestre inteiro

ComandoO que faz
npm installBaixa tudo que o projeto precisa. Você roda quando clona um projeto de outra pessoa, ou quando o seu node_modules some.
npm run devLiga o projeto enquanto você trabalha. Fica rodando; toda vez que você salva um arquivo, a página atualiza sozinha.
npm run buildEmpacota o projeto no formato final, pronto pra publicar. É o mesmo comando que a Vercel roda.
npm startRoda o projeto já empacotado. Você vai usar pouco — serve pra testar o resultado do build na sua máquina.
Cuidado com o run. É npm run dev e npm run build, mas npm install e npm start sem o run. Não tem lógica bonita — é assim e pronto. Se errar, o npm avisa.

Criar o projeto

$ npx create-next-app@latest meu-projeto

Ele vai fazer seis perguntas em inglês. Elas assustam na primeira vez, mas cada uma é simples. Responda assim:

A perguntaRespondaO que ela quer dizer
TypeScriptYes É o JavaScript com uma checagem a mais: ele avisa quando você mistura um número com um texto, por exemplo. Erro que ele pega no editor não vira problema com o site no ar.
ESLintYes Um corretor automático, tipo o do Word. Ele sublinha código suspeito enquanto você escreve.
Tailwind CSSNo É outra maneira de escrever CSS. Ainda não — até a aula 8 a gente usa o CSS que você já sabe.
App RouterYes É o jeito novo do Next organizar as páginas, aquele em que a pasta vira o endereço. É o assunto do curso.
TurbopackYes O motor que monta o seu site enquanto você trabalha. Esse é o mais rápido, e já vem como padrão.
Import alias @/*Yes Um apelido pra pasta do projeto. Sem ele, pra buscar um arquivo você escreveria ../../../components/Cabecalho. Com ele, escreve @/components/Cabecalho. Bem melhor.
Se você errar alguma, não entre em pânico. Apague a pasta que ele criou e rode o comando de novo. Leva um minuto. É bem mais rápido do que tentar consertar depois.
Por que Tailwind fica pra depois. Tailwind é uma forma diferente de escrever CSS, e aprender ela agora seria uma novidade em cima da outra. Você já sabe CSS — então até a aula 8 o estilo vai no app/globals.css, do jeito de sempre. Lá a gente entra no Tailwind, e você vai entender o que ele resolve porque terá sentido a diferença na própria mão.
Responda igual à turma. Quem marcar Yes em Tailwind vai ficar com um projeto diferente do de todo mundo — e os exemplos da aula não vão bater.

A regra do App Router

Pasta = rota. Arquivo page.tsx = a página. Não existe arquivo de configuração de rotas.

Você criaURL que nasce
app/page.tsx/
app/sobre/page.tsx/sobre
app/contato/page.tsx/contato
app/blog/posts/page.tsx/blog/posts
Pegadinha nº 1: criar app/sobre.tsx em vez de app/sobre/page.tsx. Sem o arquivo chamado exatamente page.tsx dentro da pasta, a rota não existe — e você toma 404 sem nenhum erro no terminal.

Os outros nomes reservados — layout, loading, error, not-found, template — são o assunto da aula 2.

layout e page

Aqui a promessa do começo do guia é paga. Lembra do cabeçalho copiado em doze arquivos? O layout.tsx é onde ele passa a existir uma vez só.

📄 app/layout.tsx
export default function RootLayout({ children }) {
  return (
    <html lang="pt-BR">
      <body>
        <header>Minha Loja</header>   {/* ← escrito UMA vez */}

        {children}                       {/* ← cada página entra aqui */}

        <footer>© 2026</footer>      {/* ← e o rodapé também */}
      </body>
    </html>
  );
}
  • O que está no layout aparece em todas as páginas do site
  • Mudou o menu aqui? Mudou no site inteiro, de uma vez
  • O layout raiz é obrigatório e é o único lugar com <html> e <body>
  • children é o buraco onde a página da vez é encaixada
Por que "children". É a palavra que o React usa pra dizer "o conteúdo que vem de dentro". Você não precisa entender o mecanismo hoje — só saber que é ali que a página entra.
📄 app/page.tsx
export default function Home() {
  return (
    <main>
      <h1>Bem-vindo à Minha Loja</h1>
    </main>
  );
}

Uma função com nome, que devolve HTML. É um componente — o mesmo conceito das seções anteriores. O export default na frente é o que diz ao Next: "esta é a página desta pasta".

Criando uma rota nova

Este é o exercício que fecha a aula, e ele é o coração do desafio da semana. Vamos criar a página /sobre.

Passo 1 — crie a pasta

Dentro de app/, crie uma pasta chamada sobre. O nome da pasta é o endereço.

Passo 2 — crie o arquivo

Dentro dela, um arquivo chamado exatamente page.tsx:

📄 app/sobre/page.tsx
export default function Sobre() {
  return (
    <main>
      <h1>Sobre mim</h1>
      <p>Meu nome é Fulana e este é meu primeiro projeto Next.js.</p>
    </main>
  );
}

Passo 3 — abra no navegador

Vá em http://localhost:3000/sobre. A página está lá. Você não configurou rota nenhuma — só criou uma pasta e um arquivo.

E repare: o cabeçalho do layout aparece nela também, sem você ter escrito nada. É exatamente o problema das doze páginas, resolvido.

Passo 4 — ligue as duas páginas

Pra navegar entre elas, o Next tem uma tag própria. No layout.tsx:

import Link from "next/link";

// ...dentro do header:
<Link href="/">Início</Link>
<Link href="/sobre">Sobre</Link>
Por que Link e não <a>. Com <a> o navegador recarrega a página inteira — tela branca e tudo de novo. Com Link, o Next troca só o que mudou e a navegação fica instantânea. Use sempre Link para páginas do seu próprio site; <a> só para links externos.

Deploy na Vercel

Deploy é colocar o site no ar — tirar o projeto da sua máquina e botar num computador que fica ligado o tempo todo, pra qualquer pessoa conseguir abrir.

Até agora o seu site só existe em localhost:3000, e "localhost" quer dizer "aqui mesmo": só você enxerga. Vamos mudar isso hoje, na aula 1, antes de escrever a segunda linha de código. Não é enfeite — é o que transforma "na minha máquina funciona" num link que você manda pra qualquer pessoa.

O caminho, passo a passo

  1. Rode npm run build no seu computador. Esse comando empacota o projeto no formato final. Se ele reclamar de alguma coisa, conserte antes de continuar — é o mesmo comando que a Vercel vai rodar
  2. Mande o projeto pro GitHub (é onde o código fica guardado na internet). O repositório precisa ser público
  3. Entre em vercel.com e faça login com a sua conta do GitHub
  4. Clique em Add New… → Project e escolha o repositório que você acabou de subir
  5. Não mexa em configuração nenhuma. A Vercel reconhece que é um projeto Next sozinha
  6. Clique em Deploy e espere. Em um ou dois minutos ela te devolve um link
Abra o link no celular. Sério, faça isso. É o momento em que deixa de ser exercício e vira um site de verdade — e essa sensação é metade do motivo da gente publicar já na primeira aula.

E depois?

A partir daqui você não publica mais nada na mão. Toda vez que você mandar código novo pro GitHub, a Vercel percebe sozinha e atualiza o site em um ou dois minutos. Você programa, manda, e pronto.

Mais pra frente, quando vocês estiverem trabalhando em equipe, ela ainda vai gerar um link separado pra cada mudança em teste — assim dá pra ver como ficou antes de mexer no site de verdade. Isso é assunto da aula de deploy, mas já vale saber que existe.

Rode npm run build antes de mandar pro GitHub. É exatamente o mesmo comando que a Vercel vai rodar. Se ele reclamar aqui, ia reclamar lá também — e é bem mais rápido descobrir no seu computador do que esperar o site falhar.

Erros comuns 🔧

404 numa página que acabei de criar

O arquivo precisa se chamar exatamente page.tsx, dentro de uma pasta. app/sobre.tsx não vira rota.

Port 3000 is already in use

Tem outra execução rodando. Pare a anterior, ou use npm run dev -p 3001.

O CSS não aplica e nenhum erro aparece

Quase sempre é class escrito no lugar de className. No JSX o atributo tem outro nome.

Adjacent JSX elements must be wrapped…

Você devolveu dois elementos soltos. Envolva tudo num só — <main>, <div>, ou <>…</> se não quiser criar uma tag de verdade.

Unexpected token / erro estranho no JSX

Confira se toda tag fechou. No JSX <br> e <img> precisam virar <br /> e <img />.

Module not found: Can't resolve '@/components/…'

Confira a maiúscula no nome do arquivo. No Windows funciona botao quando o arquivo é Botao; no servidor da Vercel (Linux) não. É um erro que só aparece no deploy.

O build passa local e falha na Vercel

Quase sempre uma destas três: diferença de maiúscula em import, variável de ambiente que existe só na sua máquina, ou versão de Node diferente.

Disco cheio

node_modules de um projeto Next passa de 500 MB. Com vários projetos, o disco enche rápido — e o sintoma costuma ser um erro que não fala nada de disco. Se algo parar de funcionar sem explicação, confira o espaço livre antes de qualquer outra hipótese.
