A fronteira no lugar certo 🧭

Uma entrega completa, de uma equipe. Repare no tamanho: são umas trinta linhas de código novo. O que separa uma entrega boa de uma mediana aqui é inteiramente o README — porque o difícil desta aula nunca foi escrever a linha, foi saber onde ela vai.

O README — metade da nota está aqui
README.md · a seção nova
## A fronteira Depois desta aula, quatro arquivos do projeto rodam no navegador. Nenhum deles é página ou layout. | arquivo | por que é de cliente | |---|---| | `app/vagas/error.tsx` | chama `retry` num onClick, e reage a um erro que acontece depois da página montada | | `components/MenuLink.tsx` | `usePathname` — em que endereço a pessoa está é informação do navegador dela | | `components/BotaoVoltar.tsx` | `useRouter` — o histórico de navegação é do navegador; um `<Link>` não serve porque leva a um endereço fixo, e "voltar" depende de onde a pessoa veio | | `components/BotaoCopiarLink.tsx` | as duas razões juntas: tem `onClick` e usa `navigator.clipboard` | ### A prova de que a página continua no servidor O `console.log` da página da vaga sai no terminal do `npm run dev`, nunca no console do navegador. Print em `docs/servidor.png`. [servidor] montando a vaga 1 GET /vagas/1 200 in 2143ms ### Um componente que a gente quebrou em dois O `BotaoVoltar` estava dentro do `Cabecalho`, e a gente tinha posto o `"use client"` no cabeçalho inteiro. Separamos: o cabeçalho voltou a ser servidor e só o botão desceu. O logo e os links do menu não precisavam de JavaScript nenhum para aparecer. ### O que a pessoa que usa o site ganha Com a fronteira na folha, o navegador baixa só o código dos botões. Com ela na raiz, baixaria também o título, a descrição e a lista de vagas — que já chegam prontos como HTML e não precisam de JavaScript para existir na tela. Em conexão ruim, isso é a diferença entre ler a vaga na hora e olhar para uma tela em branco esperando.

Por que esse README pontua

Cada justificativa nomeia a causa, não o sintoma. "Usa usePathname" seria meia resposta. A entrega diz por que usePathname obriga o cliente: porque a informação é do navegador. Isso é entendimento, não decoreba.

A linha do BotaoVoltar responde a pergunta difícil. O desafio perguntava por que um <Link> não resolve. A resposta — "Link leva a um endereço fixo, e voltar depende de onde a pessoa veio" — mostra que a equipe pensou, em vez de repetir o enunciado.

A seção do componente quebrado em dois é ouro. Ninguém pediu que encontrassem um problema; pediram que procurassem. Eles acharam, consertaram e contaram. É o sinal mais forte de que a aula pegou.

A última seção fala de gente. "A diferença entre ler a vaga na hora e olhar para uma tela em branco" — a equipe traduziu uma decisão técnica em consequência para quem usa. É isso que se cobra num code review de verdade.

O código

São três arquivos, e eles estão inteiros e comentados em Código do desafio. O resumo do que a equipe escreveu:

  • components/BotaoCopiarLink.tsx — 12 linhas. "use client" na primeira, recebe titulo por prop, copia location.href.
  • components/VagasParecidas.tsx — um Server Component async, com a espera de dois segundos dentro dele.
  • app/vagas/[id]/page.tsx — ganhou quatro linhas: o import dos dois, o <BotaoCopiarLink> e o <Suspense> em volta das parecidas. Não ganhou "use client".
  • components/Cabecalho.tsx — perdeu o "use client" que tinha desde a aula 02, quando o BotaoVoltar saiu de dentro dele.
Por que essa entrega funciona

A fronteira está na folha

Nenhuma página, nenhum layout. Os quatro arquivos de cliente somam menos de 40 linhas juntos.

Testaram, não só criaram

O print do terminal prova o servidor. O relato do Suspense prova que alguém recarregou e olhou a ordem em que as coisas apareceram.

Acharam um problema antigo

O "use client" no cabeçalho vinha da aula 02 e ninguém tinha percebido. A auditoria serviu para o que existe.

Checklist batido
  • ✅ Botão de copiar funciona, em arquivo próprio, recebendo prop.
  • ✅ Página da vaga sem "use client", com o log no terminal.
  • ✅ Nenhum layout.tsx ou page.tsx de cliente.
  • ✅ Seção lenta dentro de <Suspense>, com o título aparecendo antes.
  • ✅ README com a tabela, o print, o antes-e-depois e a frase sobre quem usa.
  • ✅ npm run build passa.
  • ✅ Commits de todas as pessoas da equipe.
O que derruba uma entrega
  • ❌ "use client" na página "porque assim funciona". Funciona mesmo — e leva a vaga inteira para o navegador sem precisar. É o erro que o desafio existe para pegar.
  • ❌ A espera no lugar errado. Se o await dos dois segundos está na página, a tela fica branca e o Suspense vira decoração.
  • ❌ Justificativa que repete o enunciado. "É de cliente porque precisa do navegador" não diz nada. O que precisa do navegador?
  • ❌ Um useState aparecendo do nada. Não foi ensinado, não era necessário, e quase sempre vem de código copiado sem leitura.

O que a aula 04 faz com isto

A espera de dois segundos que vocês simularam vira uma busca de dados de verdade. E aí o Suspense deixa de ser exercício e passa a ser a razão de a página abrir rápido mesmo com um banco lento do outro lado.

Composição avançada — como um componente de cliente pode envolver um de servidor usando children — está no guia de Next.js. Não é exigido agora, mas é o próximo degrau natural.
