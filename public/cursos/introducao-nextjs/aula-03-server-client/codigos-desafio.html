A fronteira, linha por linha

O desafio resolvido, comentado. Use como referência quando travar — mas tente antes. São três arquivos novos e uma mudança pequena na página da vaga; o que importa aqui não é o tamanho do código, é onde cada pedaço roda.

🧩

Três arquivos novos, uma página mexida

components/BotaoCopiarLink.tsx · components/VagasParecidas.tsx · app/vagas/[id]/page.tsx (alterado).

Repare no que não mudou: nenhum layout.tsx, nenhum arquivo da listagem. A interatividade entrou por uma porta pequena.

1 · O componente de cliente
components/BotaoCopiarLink.tsx
"use client";
// ↑ Primeira linha do arquivo, antes de qualquer import.
//   Sem ela, o onClick abaixo não tem quem o escute.

export default function BotaoCopiarLink({ titulo }: { titulo: string }) {
  return (
    <button
      type="button"
      onClick={() => {
        // location e navigator só existem no navegador.
        // É a segunda razão para este arquivo ser de cliente.
        navigator.clipboard.writeText(location.href);
        alert(`Link de "${titulo}" copiado!`);
      }}
    >
      🔗 Copiar link
    </button>
  );
}
as duas razões, no mesmo arquivo

1. O clique. Acontece depois que a página já está na tela, no dedo da pessoa. O servidor terminou o trabalho dele e foi embora.

2. As APIs do navegador. navigator.clipboard e location são do computador de quem acessa. No servidor, essas palavras não existem.

Qualquer uma das duas já obrigaria o "use client". Aqui as duas aparecem juntas — é o exemplo mais honesto que existe.

por que ele recebe titulo por prop

O componente poderia ler o título do próprio DOM, ou ter o texto chumbado. Recebendo por prop, ele vira reutilizável — serve para qualquer vaga — e, principalmente, prova que dado atravessa a fronteira: uma string sai do servidor e chega inteira no navegador.

2 · A seção lenta
components/VagasParecidas.tsx
// SEM "use client" — este é um Server Component, e é justamente
// por isso que ele pode ser async e esperar.
import { vagas } from "@/data/vagas";
import Link from "next/link";

export default async function VagasParecidas({
  area,
  idAtual,
}: {
  area: string;
  idAtual: string;
}) {
  // Espera de mentira, para você VER o Suspense funcionando.
  // Na aula 04 isso vira uma consulta de verdade.
  await new Promise((r) => setTimeout(r, 2000));

  const parecidas = vagas.filter(
    (v) => v.area === area && v.id !== idAtual
  );

  if (parecidas.length === 0) return <p>Nenhuma vaga parecida por enquanto.</p>;

  return (
    <ul>
      {parecidas.map((v) => (
        <li key={v.id}>
          <Link href={`/vagas/${v.id}`}>{v.titulo}</Link> · {v.empresa}
        </li>
      ))}
    </ul>
  );
}
o await mora aqui dentro, não na página

É o detalhe que separa quem entendeu de quem copiou. Se o await dos dois segundos estivesse na página, a página inteira esperaria — e o Suspense não teria o que fazer.

Ele está dentro do componente que o Suspense envolve. Assim o Next manda o resto da página na hora e completa este pedaço quando ficar pronto.

3 · A página, que continua no servidor
app/vagas/[id]/page.tsx
// Continua SEM "use client". É um Server Component.
import { Suspense } from "react";
import { notFound } from "next/navigation";
import { vagas } from "@/data/vagas";
import BotaoCopiarLink from "@/components/BotaoCopiarLink";
import VagasParecidas from "@/components/VagasParecidas";

export default async function PaginaDaVaga({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const vaga = vagas.find((v) => v.id === id);
  if (!vaga) notFound();

  // A prova do desafio: este log sai no TERMINAL, não no navegador.
  console.log("[servidor] montando a vaga", vaga.id);

  return (
    <article>
      <h1>{vaga.titulo}</h1>
      <p>{vaga.empresa} · {vaga.local}</p>
      <p>{vaga.descricao}</p>

      {/* Um componente de cliente dentro de um de servidor: pode. */}
      {/* O titulo é uma string — atravessa a fronteira sem problema. */}
      <BotaoCopiarLink titulo={vaga.titulo} />

      <h2>Vagas parecidas</h2>
      <Suspense fallback={<p>procurando vagas parecidas…</p>}>
        <VagasParecidas area={vaga.area} idAtual={vaga.id} />
      </Suspense>
    </article>
  );
}
três coisas para reparar

1. O <h2>Vagas parecidas</h2> está fora do Suspense. Assim o título da seção aparece na hora e a pessoa já sabe o que está carregando ali.

2. O BotaoCopiarLink é usado como qualquer outro componente. Server usando Client é o caminho fácil — o contrário é que tem regra.

3. O await params continua igual à aula 02. No Next 16 os parâmetros da rota chegam como Promise, e isso não mudou por causa da fronteira.

## A fronteira

Quatro arquivos do projeto rodam no navegador. Cada um tem motivo:

| arquivo | por quê |
|---|---|
| `app/vagas/error.tsx` | chama `retry` num onClick |
| `components/MenuLink.tsx` | `usePathname` — o endereço é do navegador |
| `components/BotaoVoltar.tsx` | `useRouter` — o histórico é do navegador |
| `components/BotaoCopiarLink.tsx` | onClick + `navigator.clipboard` |

Nenhum `layout.tsx` ou `page.tsx` leva a linha.

**A prova:** o `console.log` da página da vaga sai no terminal do
`npm run dev`, não no console do navegador — print em `docs/servidor.png`.

**O que a pessoa ganha:** com a fronteira na folha, o navegador baixa só
o código do botão. Com ela na raiz, baixaria também o título, a descrição
e a lista inteira — que já vieram prontos como HTML e não precisam de
JavaScript nenhum para aparecer.
Como testar
🧪

Os três testes que provam cada entrega

  • O botão: clique e cole em qualquer lugar. Tem que ser o endereço da vaga.
  • O servidor: recarregue com o terminal visível. O [servidor] aparece lá, e nunca no console do navegador.
  • O Suspense: recarregue e conte até dois. O título tem que estar visível antes da lista de parecidas.

Para ver o Suspense com calma, use o throttling do painel Network — ou suba a espera para cinco segundos enquanto testa, e volte para dois antes de entregar.

Se der errado
🔧

Event handlers cannot be passed to Client Component props

Duas causas. Ou faltou o "use client" no arquivo do botão — e aí o onClick não tem quem o escute. Ou você tentou passar uma função como prop de uma página de servidor para um componente de cliente: função não atravessa a fronteira.

🔧

navigator is not defined ou location is not defined

O arquivo está rodando no servidor, onde essas palavras não existem. Confirme que o "use client" é a primeira linha do arquivo — antes dos imports, com aspas e ponto e vírgula.

🔧

A página inteira fica branca por dois segundos

O await está no lugar errado — provavelmente na página, e não dentro do componente que o Suspense envolve. Enquanto a página espera, não há o que mostrar.

🔧

O console.log aparece no navegador

Alguma coisa empurrou a página para o cliente. Procure um "use client" no page.tsx ou num layout.tsx acima dele — a linha vale para o arquivo e para tudo que ele importa.

O que a correção procura
sinalo que ele indica
✅ A fronteira está na folhaNenhuma página, nenhum layout de cliente. Os arquivos com "use client" somam poucas linhas juntos.
✅ O print do terminalAlguém rodou e olhou. É a diferença entre entregar e conferir.

Onde isso continua

Na aula 04 a espera de dois segundos que vocês simularam vira uma busca de dados de verdade — e aí o Suspense deixa de ser exercício e passa a ser a razão de a página abrir rápido mesmo com um banco lento do outro lado.

Composição avançada — como um componente de cliente pode envolver um de servidor usando children — está no guia de Next.js. Não é exigido agora, mas é o próximo degrau.
