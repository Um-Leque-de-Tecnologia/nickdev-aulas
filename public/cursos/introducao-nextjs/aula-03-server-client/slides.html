// conceito 1

Uma pergunta simples

Você põe um console.log dentro de uma página. Onde ele aparece?

📄 app/vagas/page.tsx
export default function Vagas() {
  console.log("oi, alguém me vê?");
  return <h1>Vagas</h1>;
}

No console do navegador

É onde quase todo mundo procura. Não está lá.

No terminal onde você rodou npm run dev

É ali que ele aparece. E isso não é detalhe — é a aula inteira.

O seu componente rodou no servidor. O navegador nunca viu esse código — ele recebeu só o resultado.

Isso é o padrão

Todo arquivo que você escreveu até agora é assim. Você não fez nada para isso — é o normal.

Esses arquivos têm nome: Server Components. Componentes que rodam no servidor. Você já escreveu uns dez sem saber.

// conceito 2

O dia em que isso não basta

Você quer um botão Copiar link da vaga. A pessoa clica, o endereço vai para a área de transferência.

📄 o botão que você imagina
export default function BotaoCopiar() {
  return (
    <button onClick={() => navigator.clipboard.writeText(location.href)}>
      Copiar link
    </button>
  );
}

O clique

Acontece no dedo da pessoa, depois que a página já está na tela. O servidor já terminou o trabalho dele e foi embora.

navigator

É a área de transferência do computador dela. No servidor essa palavra não existe.

Duas coisas que só existem no navegador. É por isso que precisa haver um jeito de dizer: este arquivo aqui é diferente.

// conceito 2 · a linha

É essa a linha

📄 components/BotaoCopiar.tsx
"use client";

export default function BotaoCopiar() {
  return (
    <button onClick={() =>
      navigator.clipboard.writeText(location.href)
    }>
      Copiar link
    </button>
  );
}
1Vai na primeira linha do arquivo. Antes dos imports, antes de tudo.
2Com aspas e ponto e vírgula. Não é comentário, é uma instrução.
3Ela diz: mande este arquivo para o navegador também. Aí o clique tem quem o escute.
o nome disso

Um arquivo com essa linha é um Client Component. Sem ela, é um Server Component — que é o padrão. Você nunca escreve "use server" para isso: o servidor já é o normal.

// conceito 3

Marque a folha, não a raiz

Tudo que um Client Component usa por dentro vai junto para o navegador. Então quanto menor ele for, melhor.

evite
📄 app/vagas/[slug]/page.tsx
"use client"; // ← na página inteira

export default function Vaga() {
  return (
    <article>
      <h1>Pessoa Dev Júnior</h1>
      <p>A descrição inteira…</p>
      <button onClick={…}>Copiar</button>
    </article>
  );
}

O título e a descrição também viajam para o navegador — sem precisar.

faça assim
📄 app/vagas/[slug]/page.tsx
// sem "use client" — segue no servidor
import BotaoCopiar from "@/components/BotaoCopiar";

export default function Vaga() {
  return (
    <article>
      <h1>Pessoa Dev Júnior</h1>
      <p>A descrição inteira…</p>
      <BotaoCopiar />
    </article>
  );
}

Só o botão atravessa. O resto continua sendo HTML pronto.

A regra: um Server Component pode usar um Client Component à vontade. O contrário é que tem limite — e é o que a gente vê agora.

// conceito 4

O que atravessa a fronteira

O servidor entrega dados prontos para o componente de cliente — mas só o que couber num pacote de texto.

Atravessa

  • Texto, número, true/false
  • Listas e objetos de dados
  • null e undefined

Não atravessa

  • Funções — a mais comum
  • Datas, classes, coisas com método dentro
  • Conexão de banco, e tudo que é do servidor
por quê

O que sai do servidor vira texto para viajar pela internet. Um número vira "42" e volta a ser número. Uma função não tem como virar texto — e é por isso que o erro do lab 2 falava em event handlers.

// conceito 5

O loading.tsx, mas de um pedaço só

Na aula 02 você fez uma tela de espera para a página inteira. E quando só um pedaço é lento?

📄 app/vagas/[slug]/page.tsx
import { Suspense } from "react";

export default function Vaga() {
  return (
    <article>
      <h1>Pessoa Dev Júnior</h1>   {/* aparece na hora */}

      <Suspense fallback={<p>carregando vagas parecidas…</p>}>
        <VagasParecidas />          {/* chega quando ficar pronto */}
      </Suspense>
    </article>
  );
}

O título não espera o pedaço lento. O servidor manda o que já tem, e completa depois — sem a pessoa olhar para uma tela em branco. É o mesmo que o loading.tsx faz, com a mira menor.

// antes de ir

O que fica de hoje

  • Servidor é o padrão. Todo arquivo seu roda lá, a menos que você diga o contrário.
  • "use client" na primeira linha manda o arquivo também para o navegador.
  • Você precisa dela quando tem clique ou algo que só existe no navegador.
  • Marque a folha, não a raiz — quanto menor o componente de cliente, menos viaja.
  • Pela fronteira passa dado. Função, não.
