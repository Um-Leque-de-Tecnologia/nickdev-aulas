Desafio · Aula 03

A fronteira no Leque de Vagas 🧭

O projeto já tem rotas, telas de espera e de erro. Agora ele vai ganhar interatividade — sem que a página inteira desça para o navegador junto. Três entregas: um componente de cliente mínimo, uma auditoria de cada "use client" que já existe no projeto, e um pedaço lento que não trava o resto da página.

🎯

O objetivo

Até aqui todo arquivo do projeto rodava no servidor e ninguém precisou pensar nisso. A partir de hoje isso vira uma decisão consciente: o que fica no servidor, o que desce para o navegador, e por quê.

Este desafio é curto de código e longo de justificativa. É de propósito — a parte difícil de Server e Client Components nunca é escrever a linha, é saber onde pôr.

👥

Entregável de equipe, no mesmo repositório

Continua no repositório do Leque de Vagas, na mesma branch de trabalho da equipe. Cada pessoa faz pelo menos um commit com autoria própria — o histórico do Git é parte da avaliação.

📖

Travou numa palavra?

Server Component, Client Component, fronteira, prop, serializável, Suspense, streaming — todas estão no guia de Next.js. Consultar não é trapaça: é o que todo mundo que programa faz o dia inteiro.

Entrega 1 · O componente de cliente
01

Um botão que copia o link da vaga

Na página de uma vaga, um botão Copiar link. A pessoa clica e o endereço da vaga vai para a área de transferência.

  • O componente vive em components/, num arquivo só dele.
  • Ele recebe o título da vaga por prop e usa esse texto no rótulo ou na confirmação — assim você prova que dado atravessa a fronteira.
  • A página da vaga continua sem "use client".

Como confirmar que copiou: cole em qualquer lugar depois de clicar. Se quiser dar retorno visual na tela, pode — mas não é exigido, e não vale usar nada que a aula não ensinou.

02

A prova de que a página continua no servidor

Depois de o botão funcionar, ponha um console.log na página da vaga e recarregue.

  • Ele tem que aparecer no terminal do npm run dev.
  • Tire um print desse terminal e guarde — vai para o README.

Se o log aparecer no console do navegador, alguma coisa empurrou a página para o cliente. Ache o quê antes de seguir.

03

Procure fronteira grande demais

Percorra o projeto e confirme que nenhum "use client" está num arquivo maior do que precisa. Em especial:

  • Nenhum layout.tsx leva a linha.
  • Nenhum page.tsx leva a linha.
  • Todo arquivo que leva é um componente pequeno, de uma responsabilidade.

Achou um grande demais? Quebre em dois: a parte que precisa do navegador vira um componente próprio, o resto fica no servidor. Descreva o antes e o depois no README.

Entrega 3 · O pedaço que não trava a página
04

Uma seção lenta, dentro de Suspense

Na página da vaga, acrescente uma seção Vagas parecidas — outras vagas da mesma área ou da mesma empresa.

  • O componente dessa seção é async e espera de propósito: dois segundos, com await new Promise(r => setTimeout(r, 2000)). Isso simula um banco lento, que vocês vão ter de verdade mais pra frente.
  • Envolva ele num <Suspense> com um fallback que diga o que está acontecendo.
  • O título e a descrição da vaga têm que aparecer na hora, sem esperar os dois segundos.

O teste: recarregue e conte. Se a página inteira ficar branca por dois segundos, o Suspense está no lugar errado — ou a espera está acontecendo fora dele.

O README da equipe
📝

Metade da nota está aqui

Acrescente ao README do projeto uma seção ## A fronteira com:

  • A tabela da auditoria — os quatro arquivos e a justificativa de cada um.
  • O print do terminal mostrando o console.log do servidor.
  • Se vocês quebraram algum componente em dois: o antes e o depois, e por quê.
  • Uma frase respondendo: o que a pessoa que usa o site ganha com a fronteira estar na folha em vez de na raiz?
Requisitos mínimos
  • O botão de copiar funciona e vive num arquivo próprio, com "use client".
  • Ele recebe pelo menos uma prop vinda da página.
  • A página da vaga não tem "use client", e o console.log dela sai no terminal.
  • Nenhum layout.tsx nem page.tsx do projeto tem "use client".
  • A seção lenta está dentro de <Suspense> e o resto da página não espera por ela.
  • O README tem a seção ## A fronteira completa.
  • npm run build passa sem erro.
Extras, pra quem quiser ir além ✨
  • Um segundo <Suspense> na listagem, para um bloco de estatísticas lento.
  • Um fallback que imita o formato do conteúdo real (esqueleto cinza) em vez de um texto.
  • Medir no painel Network o JavaScript baixado antes e depois de encolher a fronteira, e pôr os dois números no README.
O que NÃO pode 🚫
  • "use client" em layout.tsx ou em page.tsx. É o erro que este desafio existe para evitar.
  • Passar função como prop para um componente de cliente. Não atravessa — e o erro vai te dizer isso.
  • Usar useState, useEffect ou qualquer hook. Não foi ensinado, não é necessário aqui, e não conta ponto.
  • Buscar dados de API externa. Isso é a aula 04 — aqui a lentidão é simulada de propósito.
  • Instalar biblioteca nova.
