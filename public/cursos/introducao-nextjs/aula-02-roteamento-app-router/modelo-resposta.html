README.md
# Leque de Vagas — Equipe 3 Projeto da disciplina Introdução ao Next.js. Entrega da aula 02: o mapa de rotas. 🔗 No ar: https://leque-de-vagas-equipe-3.vercel.app ## Equipe | Pessoa | O que fez nesta entrega | |---------|--------------------------------------------------| | Alice | rota /vagas/[id], notFound e not-found da vaga | | Bruno | listagem /vagas, layout aninhado, loading | | Carla | /empresas/[slug] e route group (institucional) | | Diego | MenuLink com link ativo, error.tsx, CSS | ## Tabela de rotas | Arquivo | URL | |----------------------------------------|------------------------| | app/page.tsx | / | | app/vagas/page.tsx | /vagas | | app/vagas/[id]/page.tsx | /vagas/1, /vagas/2 … | | app/empresas/[slug]/page.tsx | /empresas/aurora-tech | | app/(institucional)/termos/page.tsx | /termos | | app/(institucional)/privacidade/page.tsx | /privacidade | | app/not-found.tsx | qualquer URL inválida | ## Por que a pasta [id] resolve o problema Antes a gente ia criar uma pasta pra cada vaga. Com 6 vagas já dava trabalho; com 200 seria impossível, e toda vaga nova exigiria criar pasta na mão e publicar de novo. A pasta [id] é uma pasta só que atende qualquer valor naquele lugar da URL. O Next entrega pra página o pedaço que veio no endereço, dentro de `params`, e a gente usa esse pedaço pra achar a vaga certa na lista. O que a gente achou mais interessante: o arquivo não muda quando a lista cresce. A gente adicionou duas vagas depois de tudo pronto e não precisou tocar em nenhuma linha de código — só na lista de dados. ## A decisão do link ativo A gente escolheu deixar o "Vagas" aceso também em /vagas/1, usando `caminho.startsWith(href)` em vez de `===`. O motivo: quando a pessoa está lendo uma vaga, ela ainda está "dentro" da seção de vagas, e apagar o menu ali deixa a pessoa sem saber onde está. O problema que isso criou: o link "/" ficava aceso em TODAS as páginas, porque toda URL começa com "/". A gente tratou a home separado: const ativo = href === "/" ? caminho === "/" : caminho.startsWith(href); ## Onde cada arquivo especial ficou, e por quê - `app/vagas/loading.tsx` — na pasta de vagas, não na raiz, porque só a listagem demora. O cabeçalho continua na tela. - `app/vagas/[id]/error.tsx` — na pasta da vaga: se uma vaga quebrar, o resto do site continua funcionando. - `app/vagas/[id]/not-found.tsx` — pra dar uma mensagem sobre vaga específica ("pode ter sido preenchida"), diferente do 404 genérico do site. - `app/not-found.tsx` — na raiz, pra qualquer endereço errado. ## Prints das telas especiais | Tela | Como testamos | Print | |------------------|----------------------------|--------------------| | loading | setTimeout de 2s temporário| ![](docs/load.png) | | error | throw new Error temporário | ![](docs/erro.png) | | not-found (vaga) | acessando /vagas/9999 | ![](docs/404v.png) | | 404 do site | acessando /pagina-errada | ![](docs/404.png) | ## Saída do build Route (app) ┌ ○ / ├ ○ /_not-found ├ ○ /privacidade ├ ○ /termos ├ ○ /vagas ├ ƒ /empresas/[slug] └ ƒ /vagas/[id] Repare que /termos e /privacidade aparecem sem o "(institucional)" — foi assim que a gente confirmou que o route group estava certo. ## O que foi mais difícil Duas coisas. A primeira: a vaga nunca era encontrada. A gente tinha escrito `id: 1` sem aspas no data/vagas.ts, e o que vem da URL é sempre texto. `"1" === 1` dá falso, então caía sempre no notFound(). Demorou uns 30 minutos pra achar. A segunda: o erro do usePathname. A primeira reação foi colocar "use client" no layout.tsx, que resolveu na hora. Mas o guia avisa pra não fazer isso, então a gente tirou e criou o MenuLink separado. Ainda não entendemos por que isso importa — ficou anotado pra perguntar na aula 3.
🎯

Por que esse README pontua

Três coisas que ele faz e um README mediano não faz. Justifica as escolhas — não só diz onde pôs o loading.tsx, diz por quê. Conta um erro de verdade, com o sintoma e a causa: quem escreveu aquele parágrafo do "1" === 1 não vai mais cair nele. E admite uma dúvida em aberto sobre o "use client", em vez de fingir domínio — o que é exatamente o gancho da aula 03.

O código
app/vagas/[id]/page.tsx
import Link from "next/link";
import { notFound } from "next/navigation";
import { vagas } from "@/data/vagas";

export default async function PaginaDaVaga({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const vaga = vagas.find((v) => v.id === id);

  if (!vaga) {
    notFound();
  }

  return (
    <article className="vaga">
      <h1>{vaga.titulo}</h1>

      <p>
        <Link href={`/empresas/${vaga.empresaSlug}`}>{vaga.empresa}</Link>
        {" · "}{vaga.area} · {vaga.senioridade} · {vaga.local}
      </p>

      {vaga.aceitaIniciante && (
        <p className="selo">Aceita quem está começando</p>
      )}

      <p>{vaga.descricao}</p>
      <Link href="/vagas">← todas as vagas</Link>
    </article>
  );
}
components/MenuLink.tsx
"use client";

import Link from "next/link";
import { usePathname } from "next/navigation";

export default function MenuLink({
  href,
  children,
}: {
  href: string;
  children: React.ReactNode;
}) {
  const caminho = usePathname();

  // a home só acende nela mesma; as outras acendem na seção toda
  const ativo =
    href === "/" ? caminho === "/" : caminho.startsWith(href);

  return (
    <Link
      href={href}
      className={ativo ? "menu-link ativo" : "menu-link"}
      aria-current={ativo ? "page" : undefined}
    >
      {children}
    </Link>
  );
}
app/vagas/[id]/error.tsx
"use client";

export default function ErroDaVaga({
  error,
  retry,
}: {
  error: Error & { digest?: string };
  retry: () => void;
}) {
  return (
    <div className="aviso">
      <h2>Não consegui carregar esta vaga</h2>
      <p>Pode ter sido instabilidade. Tente de novo.</p>
      <button onClick={() => retry()}>Tentar de novo</button>
    </div>
  );
}

Por que essa entrega funciona

O mapa está de pé

As duas rotas dinâmicas funcionam, o route group não vazou pra URL e o layout aninhado aparece só onde devia. A lista do build prova tudo isso de uma vez.

Testou, não só criou

Os quatro arquivos especiais têm print e a explicação de como foram testados. Criar o arquivo é fácil; provar que ele aparece é o que conta.

Decidiu e justificou

O link ativo não foi "o que o exemplo fazia": foi uma escolha, com motivo e com o problema que ela criou, resolvido no código.

👥

E a parte de equipe

A tabela de quem fez o quê no topo do README não é burocracia: ela combina com o histórico de commits, e é o que me deixa avaliar a equipe sem ter que adivinhar. Uma entrega em que só uma pessoa commitou perde nota mesmo estando impecável — porque o objetivo do projeto é que todo mundo saiba fazer, não que o projeto exista.

Checklist batido
  • Rota /vagas/[id] com await params
  • Segunda rota dinâmica em /empresas/[slug]
  • notFound() chamado quando o id ou o slug não existe
  • loading, error e not-found nos lugares certos, com print de cada um
  • app/not-found.tsx na raiz
  • layout.tsx aninhado em app/vagas/
  • Route group (institucional) sem prefixo na URL
  • Link ativo com usePathname, e a decisão explicada
  • "use client" só no MenuLink e no error.tsx — não no layout
  • Tabela de rotas e saída do build no README
  • Publicado na Vercel, com commits de todo mundo
