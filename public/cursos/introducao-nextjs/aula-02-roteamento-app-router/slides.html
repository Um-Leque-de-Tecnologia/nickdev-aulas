o problema · e agora a conta é maior

Um site de vagas com 200 vagas

Cada vaga precisa da sua própria página, com seu próprio endereço. Com o que você sabe até agora, isso seria:

app/ └── vagas/ ├── vaga-1/page.tsx → /vagas/vaga-1 ├── vaga-2/page.tsx → /vagas/vaga-2 ├── vaga-3/page.tsx → /vagas/vaga-3 ├── ... └── vaga-200/page.tsx → e assim até desistir

Repare que é o mesmo problema da aula passada, só que maior: uma coisa só — a página de uma vaga — escrita em duzentos lugares. E quando entrar uma vaga nova amanhã, você cria a pasta na mão?

a ideia · a peça-chave da aula

Uma pasta que vale por todas

E se, em vez de duzentas pastas com nome fixo, existisse uma pasta cujo nome é um espaço em branco — preenchido na hora, com o que veio na URL?

app/ └── vagas/ └── [id]/page.tsx → /vagas/QUALQUER-COISA
rota dinâmica · o nome da pasta entre colchetes

Os colchetes são o espaço em branco

Você acessaQuem respondeO que chega pra página
/vagas/12app/vagas/[id]/page.tsxid = "12"
/vagas/dev-juniorapp/vagas/[id]/page.tsxid = "dev-junior"
/vagas/qualquer-coisaapp/vagas/[id]/page.tsxid = "qualquer-coisa"

Uma pasta. Um arquivo. Infinitas páginas. O que muda de uma pra outra é só o pedacinho que veio na URL.

O nome dentro dos colchetes é escolha sua: [id], [slug], [vaga]. Ele vira o nome da caixinha que chega na sua função.

live code · como a página lê a URL

params: o que veio no endereço

📄 app/vagas/[id]/page.tsx
export default async function PaginaDaVaga({ params, }: { params: Promise<{ id: string }>; }) { const { id } = await params; // ← o pedaço que veio na URL return <h1>Vaga {id}</h1>; }
  • { params } — as chaves tiram a caixinha de dentro das props. Guarde essas chaves: o próximo slide é sobre elas.
  • params é a caixinha com o que veio na URL. A chave dentro dela tem o nome que está entre colchetes.
  • A parte depois dos : é só o tipo — você está avisando ao TypeScript o que vem na caixinha.
  • await quer dizer "espere chegar". A caixinha demora um instante pra ficar pronta, e essa palavra segura a fila até lá.
  • Pra usar await, a função precisa de async na frente. Vêm sempre em par.

Não precisa entender por que ela demora — isso é assunto da aula 04. Hoje basta saber o sintoma: se esquecer o await, o Next reclama ou aparece [object Promise] na tela em vez do valor.

a pegadinha · a que mais me chamam pra socorrer

O valor some — e ninguém avisa

🚫 Sem as chaves

PaginaDaVaga(params: …)

Na tela aparece "Vaga" sozinho. Sem erro vermelho, sem nada no terminal.

✅ Com as chaves

PaginaDaVaga({ params }: …)

Na tela aparece "Vaga 12".

  • O Next entrega uma sacola com a caixinha dentro — { params, searchParams }. As chaves são o que tira o params de dentro dela.
  • Sem as chaves, você deu o apelido params pra sacola inteira. O id sai undefined — e undefined o React não escreve na tela.

A vacina: deixe o Next escrever o tipo

export default async function PaginaDaVaga(props: PageProps<"/vagas/[id]">) { const { id } = await props.params; }

Aqui não tem chave pra esquecer — e se errar, o editor sublinha na hora.

Pior que o do await: o [object Promise] pelo menos aparece. Este deixa um buraco calado, e o build passa igual. Sumiu o valor e o terminal está limpo? Confira as chaves antes do await.

parte 2 · os nomes reservados

Arquivos que o Next já conhece

o conceito · guarde esta tabela

O nome do arquivo é a instrução

Dentro de app/, alguns nomes são reservados. Você não configura nada: criou o arquivo com esse nome, o comportamento existe.

ArquivoPra que serveAparece quando
page.tsxo conteúdo da rotasempre — sem ele a rota nem existe
layout.tsxa moldura em voltasempre, e não remonta ao navegar
loading.tsxo "carregando"enquanto a página está sendo preparada
error.tsxa tela de erroquando algo quebra ali dentro
not-found.tsxa tela de "não existe"quando o conteúdo não é encontrado
template.tsxmoldura que remontaigual ao layout, mas do zero a cada navegação

Cada um vale só pra pasta onde está e as de dentro dela. Um error.tsx em app/vagas/ não cobre o resto do site.

layout · agora em camadas

Moldura dentro de moldura

app/ ├── layout.tsx cabeçalho do site ├── page.tsx └── vagas/ ├── layout.tsx filtros da área de vagas ├── page.tsx /vagas └── [id]/ └── page.tsx /vagas/12

Em /vagas/12 aparecem

O cabeçalho do site (layout de fora) + os filtros (layout de vagas) + a página da vaga. Um dentro do outro, como bonecas russas.

O detalhe que importa

Ao pular de /vagas/12 pra /vagas/13, os dois layouts não são remontados. Só o miolo troca — e é por isso que a navegação não pisca.

Foi o gancho que ficou no fim da aula passada: "por que a página não pisca ao navegar?" — é isto. O Next troca só a parte que mudou.

loading · o "peraí, tô indo"

Uma tela de espera de graça

📄 app/vagas/loading.tsx
export default function Loading() { return <p>Carregando vagas…</p>; }
  • Criou o arquivo, pronto. Não precisa importar nem ligar em lugar nenhum.
  • Ele aparece sozinho enquanto o page.tsx daquela pasta se prepara.
  • O cabeçalho e os filtros continuam na tela — só o miolo mostra o "carregando".

É a diferença entre uma tela branca e um site que responde. Custa três linhas.

error · quando alguma coisa quebra

Um erro não derruba o site inteiro

📄 app/vagas/error.tsx
"use client"; // ← obrigatório aqui. explicação na aula 03 export default function Error({ error, retry }) { return ( <div> <h2>Algo deu errado nas vagas</h2> <button onClick={() => retry()}>Tentar de novo</button> </div> ); }

Sobre o "use client": essa linha diz "este arquivo também roda no navegador da pessoa". Por que ela existe e quando usar é a aula 03 inteira. Hoje o combinado é: onde eu escrever essa linha, escreva também — e siga.

not-found · quando não existe

O 404 que você escreve

📄 app/vagas/[id]/page.tsx
import { notFound } from "next/navigation"; const vaga = vagas.find((v) => v.id === id); if (!vaga) { notFound(); // ← para tudo aqui }
📄 app/vagas/[id]/not-found.tsx
export default function NaoAchei() { return ( <p> Essa vaga não existe ou já foi preenchida. </p> ); }

Sem isso, /vagas/banana mostraria uma página quebrada. Com isso, mostra uma tela sua, com o cabeçalho no lugar e um caminho de volta. Rota dinâmica sem 404 é rota dinâmica pela metade.

o encaixe · quem envolve quem

A ordem das camadas

<layout> a moldura <error> pega o que quebrar aqui dentro <loading> enquanto o miolo não vem <not-found> <page /> o conteúdo </not-found> </loading> </error> </layout>

De fora pra dentro. Repare que o error fica por fora do loading — e o layout fica por fora de tudo.

Consequência prática: um erro dentro do layout.tsx não é pego pelo error.tsx da mesma pasta, porque o layout está por fora dele. Quem pega é o error da pasta de cima.

route group · organizar sem mudar o endereço

A pasta entre parênteses

Às vezes você quer agrupar arquivos sem que isso apareça na URL. Parênteses no nome da pasta fazem exatamente isso: ela some do endereço.

app/ └── (institucional)/ ← some da URL ├── layout.tsx moldura só das páginas daqui ├── termos/page.tsx → /termos └── privacidade/page.tsx → /privacidade

Não é /institucional/termos — é /termos mesmo. Serve pra dar um layout diferente pra um grupo de páginas, ou só pra arrumar a casa quando app/ começa a ficar cheia.

catch-all · quando você não sabe quantos pedaços vêm

Três pontinhos, todos os níveis

PastaPegaNão pega
[id]/vagas/12/vagas/12/empresa
[...slug]/docs/a · /docs/a/b/c/docs (a raiz)
[[...slug]]/docs e tudo abaixo— pega tudo

Com [...slug], o que chega em params não é um texto: é uma lista. O endereço /docs/a/b vira ["a", "b"].

Serve pra documentação, categorias aninhadas, caminho de migalhas. No projeto de vocês provavelmente não vai aparecer — mas quando aparecer numa vaga de emprego, você já viu.

só pra você conhecer o nome · não cai no desafio

Existem mais duas, e são avançadas

Rotas paralelas @pasta

Duas telas no mesmo endereço, cada uma navegando por conta própria. Tipo um painel dividido em duas metades independentes.

Rotas interceptadas (.)pasta

Aquele Instagram em que você clica na foto e ela abre num modal por cima do feed — mas a URL muda como se fosse página cheia. E se você recarregar, vem a página cheia mesmo.

Nenhuma das duas entra no desafio. Estou mostrando só pra que o nome não seja novidade quando você esbarrar nele — e pra você saber que dá pra fazer aquele modal do Instagram sem gambiarra.

parte 3 · andar entre as telas

Navegação

Link · o que ele faz que o <a> não faz

Ele adianta o serviço

Com <a href>

O navegador joga fora a página inteira e baixa tudo de novo. Tela branca, cabeçalho remontado, rolagem perdida.

Com <Link>

Quando o link aparece na tela, o Next já vai buscando a página de destino em segundo plano. No clique, ela quase sempre já está ali.

import Link from "next/link"; <Link href={`/vagas/${vaga.id}`}>{vaga.titulo}</Link>

Esse adiantamento chama prefetch, e só acontece no site publicado — em npm run dev ele fica desligado. Se a navegação parecer lenta na sua máquina e rápida na Vercel, é isso, e está tudo certo.

link ativo · marcar em que página a pessoa está

usePathname: onde eu estou?

📄 components/MenuLink.tsx
"use client"; import { usePathname } from "next/navigation"; import Link from "next/link"; export default function MenuLink({ href, children }) { const caminho = usePathname(); // ← "/vagas", por exemplo const ativo = caminho === href; return ( <Link href={href} className={ativo ? "ativo" : ""}> {children} </Link> ); }

De novo o "use client": saber em que endereço a pessoa está só é possível no navegador dela. Por isso este arquivo precisa da linha. Na aula 03 isso vira uma regra clara, não um combinado.

useRouter · navegar sem clique num link

Quando quem manda é o código

📄 components/BotaoVoltar.tsx
"use client"; import { useRouter } from "next/navigation"; export default function BotaoVoltar() { const router = useRouter(); return <button onClick={() => router.back()}>Voltar</button>; }

push()

vai pra outra tela, e o botão voltar do navegador funciona

replace()

vai, mas apaga a tela anterior do histórico

back()

volta uma tela, igual à seta do navegador

Regra: se dá pra usar <Link>, use <Link>. O useRouter é pra quando não existe link pra clicar — depois de enviar um formulário, por exemplo. Vem de next/navigation, nunca de next/router (esse é o Next antigo).
