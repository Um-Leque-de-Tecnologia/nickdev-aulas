O esqueleto do Leque de Vagas 🗺️

Sua missão: montar o mapa de rotas do projeto do semestre. Uma rota dinâmica que atende qualquer vaga, telas de espera e de erro no lugar certo, um 404 que você escreveu, e um menu que sabe onde a pessoa está. É o primeiro entregável da equipe.

🎯

O objetivo

Provar que você entendeu a ideia central da aula: o endereço é a pasta, e o nome do arquivo é a instrução. Ao final, o seu projeto tem que ter uma pasta só — [id] — atendendo todas as vagas, e arquivos especiais em todos os lugares onde eles fazem diferença.

👥

Este é um entregável de equipe

Diferente do desafio 01, este vale por equipe, no repositório da equipe. Combinem quem faz o quê ainda hoje — as rotas são bem separadas, dá pra dividir sem ninguém pisar no pé do outro. Todo mundo precisa ter pelo menos um commit, e eu vou olhar isso.

📖

Travou numa palavra?

Segmento, slug, params, prefetch, hook — se alguma dessas aparecer aqui e você não lembrar o que é, o guia da aula tem um dicionário com todas elas em português simples. Consultar não é trapaça.

01

Os dados falsos das vagas

O projeto ainda não tem banco de dados — isso é a aula 06. Por enquanto as vagas moram num arquivo, e isso basta pra tudo que a gente vai fazer hoje.

Crie data/vagas.ts na raiz do projeto:

// data/vagas.ts
export type Vaga = {
  id: string;
  titulo: string;
  empresa: string;
  empresaSlug: string;
  area: string;
  senioridade: string;
  local: string;
  aceitaIniciante: boolean;
  descricao: string;
};

export const vagas: Vaga[] = [
  {
    id: "1",
    titulo: "Pessoa Desenvolvedora Front-end Júnior",
    empresa: "Aurora Tech",
    empresaSlug: "aurora-tech",
    area: "Front-end",
    senioridade: "Júnior",
    local: "Remoto",
    aceitaIniciante: true,
    descricao: "Trabalhar com React e Next.js num time de produto.",
  },
  // ...pelo menos mais 5
];

Mínimo de 6 vagas, com pelo menos 3 áreas diferentes e duas empresas repetindo — isso vai importar quando vocês montarem a página da empresa. Inventem à vontade, mas escrevam vagas que existiriam de verdade.

Repare que o id é texto, entre aspas. Não é frescura: o que vem da URL é sempre texto, e assim a comparação funciona direto. Se você usar número, vai precisar converter.

02

A estrutura que você vai construir

Este é o alvo. Cada linha aqui é uma coisa da aula de hoje:

app/
├── layout.tsx                  cabeçalho e rodapé do site
├── page.tsx                    → /
├── not-found.tsx               → 404 do site inteiro

Não precisa ficar bonito. O CSS desta entrega pode ser o mínimo pra ficar legível. O que eu vou olhar é o mapa de rotas funcionando — design entra a partir da aula 08.

03

A listagem em /vagas

Percorra a lista e monte um <Link> pra cada vaga. O endereço de cada link usa o id daquela vaga.

import Link from "next/link";
import { vagas } from "@/data/vagas";

export default function ListaDeVagas() {
  return (
    <ul>
      {vagas.map((vaga) => (
        <li key={vaga.id}>
          <Link href={`/vagas/${vaga.id}`}>{vaga.titulo}</Link>
        </li>
      ))}
    </ul>
  );
}

Aquele key={vaga.id} não é enfeite. Quando você gera uma lista, cada item precisa de um identificador único — senão o Next avisa no terminal. Por que isso existe é assunto de outra aula; hoje é receita.

04

A rota dinâmica ⭐

Este passo é o coração do desafio. Uma pasta [id], um arquivo, e todas as vagas atendidas.

// app/vagas/[id]/page.tsx
import { notFound } from "next/navigation";
import { vagas } from "@/data/vagas";

export default async function PaginaDaVaga({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const vaga = vagas.find((v) => v.id === id);

  if (!vaga) {
    notFound();
  }

  return (
    <article>
      <h1>{vaga.titulo}</h1>
      <p>{vaga.empresa} · {vaga.local}</p>
      <p>{vaga.descricao}</p>
    </article>
  );
}

A página precisa mostrar, no mínimo: título, empresa, área, senioridade, local e a descrição. E um <Link> pra /empresas/[slug] daquela empresa.

O await não é opcional. Sem ele você vê [object Promise] na tela, ou um erro no terminal. E lembre: se tem await dentro, precisa de async na frente da função.

05

loading, error e not-found

Três arquivos, cada um no seu lugar. Nenhum deles precisa ser importado — o Next encontra sozinho.

  • app/vagas/loading.tsx — o que aparece enquanto a listagem se prepara
  • app/vagas/[id]/error.tsx — com "use client" e um botão retry()
  • app/vagas/[id]/not-found.tsx — a tela de "essa vaga não existe", com link de volta
  • app/not-found.tsx — o 404 do site inteiro

Como testar cada um — e você precisa testar, um a um: o not-found abrindo /vagas/9999; o 404 geral abrindo /pagina-que-nao-existe; o loading e o error com os truques que estão no código comentado. Tire print dos quatro — eles vão pro README.

06

A página da empresa

Segunda rota dinâmica, agora com um slug em vez de um número: app/empresas/[slug]/page.tsx.

Ela mostra o nome da empresa e a lista de vagas daquela empresa — filtrando a lista pelo empresaSlug. Se nenhuma vaga bater, é notFound().

Por que duas rotas dinâmicas. Pra você ver que [id] e [slug] são a mesma ideia com nomes diferentes — o que está entre colchetes é escolha sua, e vira a chave que você lê no params.

07

O route group institucional

Crie app/(institucional)/ com um layout.tsx só dela e duas páginas: termos e privacidade.

O conteúdo pode ser um parágrafo de mentira. O que importa é o endereço ficar /termos — e não /institucional/termos.

Prove que funcionou: na tabela de rotas do README, essas duas linhas mostram o caminho do arquivo com (institucional) e a URL sem. É a prova de que você entendeu o que os parênteses fazem.

08

O menu com link ativo

Um componente MenuLink que marca sozinho a página atual, usado no cabeçalho do layout.tsx.

"use client";

import Link from "next/link";
import { usePathname } from "next/navigation";

export default function MenuLink({ href, children }) {
  const caminho = usePathname();
  const ativo = caminho === href;
  // ...devolve um Link com a classe "ativo" quando for o caso
}

O "use client" vai na primeira linha, antes dos imports. Se esquecer, o erro é You're importing a component that needs usePathname… — e agora você já sabe o que ele quer dizer.

Decida e explique no README: o link "Vagas" deve ficar aceso também em /vagas/1? Não existe resposta certa — existe a sua, justificada. Isso vale nota.

09

Build, tabela de rotas e deploy

$ npm run build

O build imprime a lista de rotas. Cole essa lista no README — é a prova mais rápida de que o mapa inteiro está de pé.

  • Todas as rotas do passo 02 aparecem na lista
  • /termos e /privacidade aparecem sem o (institucional)
  • /vagas/[id] aparece com os colchetes mesmo

Faltou alguma rota? Quase sempre é o arquivo que não se chama page.tsx, ou a pasta no lugar errado. O build é o jeito mais rápido de descobrir.

Depois: git push, e a Vercel publica sozinha.

O README da equipe

Além do que já vinha da aula 01, o README precisa ter:

  1. A tabela de rotas: cada arquivo e a URL que ele atende
  2. A saída do npm run build colada
  3. Uma explicação, com as palavras de vocês, de por que a pasta [id] resolve o problema de ter uma página por vaga
  4. A decisão sobre o link ativo (passo 08) e o motivo
  5. Prints das quatro telas especiais: loading, error, not-found da vaga e 404 do site
  6. Quem fez o quê na equipe
Requisitos mínimos
  • Rota dinâmica /vagas/[id] lendo o id com await params
  • Listagem em /vagas com <Link> pra cada vaga
  • Segunda rota dinâmica: /empresas/[slug]
  • notFound() chamado quando o id ou o slug não existe
  • loading.tsx, error.tsx e not-found.tsx nos lugares do mapa
  • app/not-found.tsx na raiz, com link de volta pra home
  • Um layout.tsx aninhado em app/vagas/
  • Route group (institucional) com duas páginas sem prefixo na URL
  • Menu com link ativo via usePathname
  • npm run build passando, com a lista de rotas no README
  • Publicado na Vercel, com o link no README
  • Commits de todo mundo da equipe
Extras, pra quem quiser ir além ✨
  • Um loading.tsx em formato de esqueleto — caixinhas cinzas no formato do conteúdo, em vez de "Carregando…"
  • Filtro por área usando searchParams: /vagas?area=dados
  • generateMetadata na página da vaga, pro título da aba virar o nome da vaga
  • Um BotaoVoltar com useRouter().back() na página de detalhe
  • Link ativo que acende na seção inteira (startsWith), tratando a home à parte
  • Um template.tsx em app/vagas/ com uma animação de entrada — e um parágrafo no README sobre a diferença que você viu
O que NÃO pode 🚫
  • Uma pasta por vaga — app/vagas/vaga-1/, vaga-2/… é exatamente o problema que a aula resolve
  • params sem await
  • params sem as chaves na assinatura — é ({ params }: { params: … }). Sem elas o valor some da tela sem dar erro
  • useRouter importado de next/router (é next/navigation)
  • <a href> para navegação interna
  • "use client" no layout.tsx raiz pra "resolver" o erro do menu — o componente que precisa é o MenuLink, não o layout inteiro
  • Pages Router — o curso inteiro é App Router
  • Subir node_modules ou .next
