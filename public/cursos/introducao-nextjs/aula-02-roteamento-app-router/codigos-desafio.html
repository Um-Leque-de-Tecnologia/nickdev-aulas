O mapa de rotas linha por linha

O desafio resolvido, comentado. Use como referência quando travar — mas tente antes. O que importa aqui não é a sintaxe: é entender por que uma pasta só atende todas as vagas.

Onze arquivos, e o site inteiro fica de pé

Repare enquanto lê: em nenhum deles você configura uma rota. As rotas nascem do lugar onde o arquivo está e do nome que ele tem. Essa é a ideia inteira do App Router.

💡

Por que o id é texto

Porque o que chega da URL sempre é texto. Acessando /vagas/1, o id vale "1" — com aspas. Se você guardasse o id como número, a comparação "1" === 1 daria falso e nenhuma vaga seria encontrada. Guardando como texto, a comparação funciona direto.

⚠️

Este arquivo NÃO leva "use client"

É a tentação nº 1 da semana: o menu dá erro pedindo "use client", e a pessoa põe a linha no layout raiz porque "resolveu". Resolve mesmo — e joga o site inteiro pro navegador, o que estraga tudo que vem nas próximas aulas. Quem precisa da linha é só o MenuLink. Na aula 03 isso vai fazer todo o sentido.

components/MenuLink.tsx ⭐

O único componente do desafio que roda no navegador — e o menor possível, de propósito.

"use client";   // a PRIMEIRA linha do arquivo, antes dos imports

import Link from "next/link";
import { usePathname } from "next/navigation";

export default function MenuLink({
  href,
  children,
}: {
  href: string;
  children: React.ReactNode;
}) {
  // usePathname devolve o endereço atual: "/", "/vagas", "/vagas/1"...
  const caminho = usePathname();
  const ativo = caminho === href;

  return (
    <Link
      href={href}
      className={ativo ? "menu-link ativo" : "menu-link"}
      // aria-current avisa o leitor de tela qual é a página atual
      aria-current={ativo ? "page" : undefined}
    >
      {children}
    </Link>
  );
}
💡

Por que só este arquivo é "client"

Porque a pergunta "em que endereço a pessoa está?" só tem resposta no navegador dela. Isolando essa necessidade num componente minúsculo, o resto do site continua sendo montado no servidor — que é mais rápido e o padrão do curso. Essa técnica tem nome, e é metade da aula 03.

app/vagas/[id]/page.tsx ⭐

O arquivo mais importante do desafio. Uma pasta, todas as vagas.

import type { Metadata } from "next";
import Link from "next/link";
import { notFound } from "next/navigation";
import { vagas } from "@/data/vagas";

// EXTRA: faz o título da aba virar o nome da vaga.
export async function generateMetadata({
  params,
}: {
  params: Promise<{ id: string }>;
}): Promise<Metadata> {
  const { id } = await params;
  const vaga = vagas.find((v) => v.id === id);
  return { title: vaga ? `${vaga.titulo} · Leque de Vagas` : "Vaga não encontrada" };
}

export default async function PaginaDaVaga({
  // 1. a caixinha com os pedaços da URL chega aqui
  params,
}: {
  // Promise = ela chega como um "vale", não pronta
  params: Promise<{ id: string }>;
}) {
  // 2. await troca o vale pelo valor
  const { id } = await params;

  // 3. procura a vaga com esse id
  const vaga = vagas.find((v) => v.id === id);

  // 4. não achou? para tudo e mostra o not-found.tsx desta pasta
  if (!vaga) {
    notFound();
  }

  return (
    <article className="vaga">
      <h1>{vaga.titulo}</h1>

      <p>
        <Link href={`/empresas/${vaga.empresaSlug}`}>{vaga.empresa}</Link>
        {" · "}{vaga.area} · {vaga.senioridade} · {vaga.local}
      </p>

      {vaga.aceitaIniciante && <p className="selo">Aceita quem está começando</p>}

      <p>{vaga.descricao}</p>

      <Link href="/vagas">← todas as vagas</Link>
    </article>
  );
}
🎯

As quatro linhas que resolvem o problema da aula

1. a caixinha chega · 2. await troca o vale pelo valor · 3. procura na lista · 4. se não achou, notFound(). Duzentas vagas, um arquivo. Se amanhã entrarem mais cinquenta, nada aqui muda — é só a lista crescer.

🔎

Aquele && no meio do JSX

{condição && <algo />} quer dizer "se a condição for verdadeira, mostre isso; senão, não mostre nada". É o jeito mais curto de esconder um pedaço da tela, e você vai ver isso o semestre inteiro.

Como fazer o loading aparecer

Sua página fica pronta rápido demais pra você ver o loading. Pra testar, segure a página de propósito — e depois apague essa linha:

// no topo de app/vagas/page.tsx, SÓ PRA TESTAR:
export default async function ListaDeVagas() {
  // segura a página por 2 segundos, só pra ver o loading
  await new Promise((r) => setTimeout(r, 2000));
  // ...resto igual
}

🧪

Como fazer o error aparecer

Quebre a página de propósito por um instante — e depois apague: throw new Error("teste"); logo no começo do page.tsx. A tela de erro aparece, o cabeçalho continua no lugar, e o botão "tentar de novo" volta a funcionar assim que você apagar a linha.

💡

Sobre retry e reset

Se você achar reset em algum tutorial, não está errado — está velho. A partir do Next 16.3 o recomendado é retry, que além de limpar o erro busca os dados de novo. É mais um sinal de material desatualizado, como a gente viu nos slides.

app/empresas/[slug]/page.tsx

A segunda rota dinâmica. Mesma ideia do [id], outro nome — e prova que o nome entre colchetes é escolha sua.

import Link from "next/link";
import { notFound } from "next/navigation";
import { vagas } from "@/data/vagas";

export default async function PaginaDaEmpresa({
  params,
}: {
  // "slug", porque a pasta se chama [slug]
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;

  // filter devolve TODAS as que batem (find devolve só a primeira)
  const daEmpresa = vagas.filter((v) => v.empresaSlug === slug);

  if (daEmpresa.length === 0) {
    notFound();
  }

  return (
    <section>
      <h1>{daEmpresa[0].empresa}</h1>
      <p>{daEmpresa.length} vaga(s) aberta(s)</p>

      <ul>
        {daEmpresa.map((vaga) => (
          <li key={vaga.id}>
            <Link href={`/vagas/${vaga.id}`}>{vaga.titulo}</Link>
          </li>
        ))}
      </ul>
    </section>
  );
}

Aquele <>…</>

É um embrulho invisível. Uma função só consegue devolver uma coisa, mas às vezes você não quer criar uma <div> só pra isso. O <> agrupa sem virar tag nenhuma no HTML final. O nome dele é Fragment.

O que o build revela

Rode npm run build. Todas as rotas do mapa têm que aparecer nesta lista — e é ela que vai pro README.

$ npm run build Route (app) ┌ ○ / ├ ○ /_not-found ├ ○ /privacidade ├ ○ /termos ├ ○ /vagas ├ ƒ /empresas/[slug] └ ƒ /vagas/[id]
🔎

Leia esta lista com atenção

/termos e /privacidade aparecem sem o (institucional) — é a prova de que o route group funcionou. E /vagas/[id] aparece com colchetes mesmo: o Next está dizendo "esta rota atende qualquer valor aí". Os símbolos ○ e ƒ falam de como cada página é gerada — isso é a aula 04, ignore por enquanto.

Se der errado
# apareceu [object Promise] na tela → faltou await antes de params. e confira o async na frente da função. # a pagina abre mas o valor nao aparece ("Vaga" sem o numero) → faltaram as chaves: ({ params }: { params: … }), nao (params: …). sem elas params vira a sacola de props inteira e o id sai undefined. nao da erro nenhum e o build passa — por isso demora pra achar. # 404 na rota dinamica que voce criou → a pasta esta com colchetes mesmo? [id], nao (id) nem id. e o arquivo dentro se chama exatamente page.tsx? # /institucional/termos em vez de /termos → voce usou colchetes no lugar de parenteses. (institucional) some da URL. [institucional] nao. # You're importing a component that needs usePathname → faltou "use client" na PRIMEIRA linha do MenuLink.tsx. nao ponha no layout raiz pra resolver. # NextRouter was not mounted → voce importou useRouter de next/router. no App Router e next/navigation. # a vaga nunca e encontrada → o id do data/vagas.ts esta como numero? o que vem da URL e sempre texto. use "1", com aspas. # o loading.tsx nunca aparece → sua pagina fica pronta rapido demais. use o truque do setTimeout la em cima pra testar.
