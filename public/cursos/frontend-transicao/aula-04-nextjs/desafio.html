Desafio · Aula 04

Faça o Leque de Vagas crescer 🪭⚡

Na aula a gente construiu a base juntos. Agora o projeto é seu: novas rotas, um filtro que você inventa, a página das vagas salvas e tudo publicado na Vercel. Este é o mesmo projeto que vamos usar até o fim do módulo — capriche, porque ele vai pro seu portfólio.

🎯

O objetivo

Provar que você consegue criar rotas sozinha(o), decidir o que é Componente de Servidor e o que é de Cliente, e manter o estado da tela na URL. Não é sobre escrever muito código — é sobre entender onde cada coisa mora.

📦 De onde começar

Continue o projeto que você fez na aula. Se perdeu o fio em algum ponto, clone o repositório de referência e siga a partir dele — sem culpa, o importante é você conseguir avançar: 

git clone https://github.com/Um-Leque-de-Tecnologia/leque-de-vagas.git
cd leque-de-vagas
npm install
npm run dev
Nível 1 · o essencial (todo mundo faz)
01

A rota /empresas

essencial

Uma página que lista as empresas do mural — cada uma com o nome, o logo (emoji) e quantas vagas ela tem abertas.

  • Crie app/empresas/page.tsx
  • Crie a função listarEmpresas() em lib/vagas.ts
  • Adicione o link no cabeçalho
// dica: agrupar as vagas por empresa
export async function listarEmpresas() {
  const nomes = [...new Set(VAGAS.map((v) => v.empresa))];

  return nomes.map((nome) => {
    const vagas = VAGAS.filter((v) => v.empresa === nome);
    return { nome, logo: vagas[0].logo, total: vagas.length };
  });
}

Lembre: a página é Componente de Servidor. Ela pode ser async e dar await direto.

02

A rota dinâmica /empresas/[empresa]

essencial

Clicando numa empresa, você vê só as vagas dela.

  • Crie a pasta [empresa] dentro de app/empresas/
  • Lembre do await params — Next 16!
  • Empresa que não existe → notFound()
  • Use generateMetadata pro título ser o nome da empresa

Atenção ao acento e ao espaço: "Farol Analytics" na URL vira Farol%20Analytics. Ou você usa encodeURIComponent() ao montar o link, ou cria um slug pra empresa no lib/dados.ts (mais elegante — e é o que faríamos de verdade).

03

Um filtro novo, vivendo na URL

essencial

Além de área e nível, adicione o filtro de modelo de trabalho (Remoto / Híbrido / Presencial) na página /vagas.

  • O filtro vira ?modelo=Remoto na URL
  • Nada de useState — o estado é a URL
  • Ele precisa combinar com os filtros que já existem

Teste que vale ponto: aplique dois filtros, copie a URL, cole numa aba anônima. Chegou igual? Passou. 🎉

04

Os estados da tela em todas as rotas

essencial

Nenhuma rota nova pode ficar sem:

loading.tsx — de preferência um skeleton, não só a palavra "carregando"
Estado vazio — "nenhuma vaga com esses filtros", com um jeito de voltar
metadata — title e description próprios
404 — notFound() onde faz sentido
Nível 2 · pra consolidar (recomendado)
05

A página /salvas

recomendado

O botão ★ já guarda no localStorage. Agora mostre essas vagas numa página.

  • Como o localStorage só existe no navegador, esta página precisa de um Componente de Cliente
  • Leia o localStorage dentro do useEffect — nunca no corpo do componente
  • Trate o caso "nenhuma vaga salva ainda" com um link pra /vagas

Pense antes de codar: a lista de todas as vagas vem do servidor; só o "quais estão salvas" vem do navegador. Onde exatamente fica a fronteira "use client"? Essa é a pergunta do desafio.

06

Contador de salvas no cabeçalho

recomendado

Um ★ 3 no cabeçalho, mostrando quantas vagas você salvou.

Spoiler honesto: fazer o número atualizar na hora em que você clica na estrela de um card é difícil hoje — os dois componentes não conversam. Resolva do jeito que der (atualizar ao trocar de página já vale) e guarde a inquietação: é exatamente esse problema que Context e estado global resolvem, mais pra frente. 😏

07

Deixe com a sua cara

recomendado

O projeto é seu. Mexa no visual com CSS Modules:

  • Troque a paleta em globals.css (é tudo variável CSS — muda num lugar, reflete no site inteiro)
  • Troque a fonte com next/font/google
  • Adicione pelo menos três vagas suas em lib/dados.ts — inclusive uma da área que você quer trabalhar
  • Ajuste o texto da /sobre pra falar de você
Nível 3 · pra brilhar ✨
08

Extras

opcional
  • Ordenação por salário ou data, também na URL (?ordem=recentes)
  • Layout aninhado: app/vagas/layout.tsx com um sub-cabeçalho só das rotas de vaga
  • <Suspense>: o cabeçalho da lista aparece na hora, só os cards esperam
  • <Image> com logos reais em public/, no lugar dos emojis
  • Paginação: ?pagina=2 mostrando 6 vagas por vez
  • Acessibilidade: navegue o site inteiro só com Tab. Dá pra ver onde você está? O botão ★ é anunciado?
Requisitos mínimos pra entrega
  • Rota /empresas funcionando, linkada no cabeçalho
  • Rota dinâmica /empresas/[empresa] com await params
  • Filtro de modelo funcionando pela URL e combinando com os outros
  • loading.tsx e metadata nas rotas novas
  • Pelo menos 3 vagas novas criadas por você
  • npm run build passando sem erro
  • Publicado na Vercel, com o link no grupo 🌍
  • Código no GitHub, com commits que descrevem o que foi feito
O que NÃO pode 🚫
  • "use client" em página que não precisa (procure e apague os que sobraram)
  • <a href> pra link interno — use <Link>
  • .map() sem key
  • params.slug sem await (vai nem buildar 😅)
  • Lista sem tratar o caso vazio
Como entregar
  1. Rode npm run build e resolva o que aparecer
  2. Suba pro GitHub (repositório público, pra virar portfólio)
  3. Publique na Vercel
  4. Mande no grupo: o link do site + o link do repositório
  5. Escreva uma frase sobre o que foi mais difícil — a gente revisa isso junto na aula 05 💜
Materiais de apoio

Travou? Antes de espiar o código pronto, releia a seção do guia sobre o assunto e tente de novo. O erro que você resolve sozinha(o) é o que fica.
