Componente = função que devolve tela

Você já fez isso na aula 03, sem saber o nome bonito:

Aula 03 — JavaScript puro

function criarCard(p) {
  const d = document.createElement("div");
  d.innerHTML = `<h3>${p.titulo}</h3>`;
  return d;
}

Hoje — React

function VagaCard({ vaga }) {
  return (
    <article>
      <h3>{vaga.titulo}</h3>
    </article>
  );
}

Três regras de componente:

  1. O nome começa com letra maiúscula — é assim que o React sabe que é seu componente e não uma tag HTML
  2. Ele devolve a interface (com return)
  3. Um arquivo, um componente principal, exportado com export default
Atalho: no VS Code, digite rafce num arquivo .tsx vazio e aperte Tab. Ele escreve o esqueleto do componente pra você.

JSX — HTML dentro do JavaScript

JSX é HTML escrito direto no meio do JavaScript. Quase igual ao que você já sabe, com cinco diferenças:

No HTMLNo JSXPor quê
class="card"className="card"class já é palavra reservada do JS
for="email"htmlFor="email"for também é
onclick="f()"onClick={f}passa a função em si, não um texto
<br> <img><br /> <img />toda tag precisa fechar
style="color:red"style={{ color: "red" }}vira objeto JavaScript

As chaves { } são o portal pro JavaScript

const nome = "Nicoly";
const vagas = 9;

<p>Oi, {nome}! Temos {vagas} vagas.</p>
<p>Metade disso é {vagas / 2}.</p>
<p>{nome.toUpperCase()}</p>

Mostrar algo só às vezes

// só aparece se for verdadeiro
{vaga.remoto && <span>🏠 Remoto</span>}

// um ou outro (if/else em uma linha)
{salva ? "★" : "☆"}

Um return, um elemento só

Se precisar devolver dois elementos lado a lado, envolva num fragmento — a tag vazia <> </>, que não vira nada no HTML:

<>
  <h1>Título</h1>
  <p>Texto</p>
</>

Props — os parâmetros do componente

Props são os dados que um componente recebe de quem o usa. É exatamente a mesma ideia dos parâmetros de função da aula 02.

// definindo
function Selo({ texto, cor }) {
  return <span style={{ color: cor }}>{texto}</span>;
}

// usando (parece uma tag HTML sua)
<Selo texto="Remoto" cor="#A98CE0" />
<Selo texto="Júnior" cor="#F24487" />

Texto vai entre aspas; qualquer outra coisa (número, objeto, array, função, variável) vai entre chaves:

<VagaCard vaga={vaga} destaque={true} posicao={1} />

Com TypeScript

function Selo({ texto, cor }: { texto: string; cor: string }) {
  return <span style={{ color: cor }}>{texto}</span>;
}
Vale o esforço: com os tipos escritos, o VS Code passa a completar os nomes pra você e avisa na hora quando você digita vaga.titlo.

children — o conteúdo entre as tags

function Caixa({ children }) {
  return <div className="caixa">{children}</div>;
}

<Caixa><p>isto aqui vira o children</p></Caixa>

É exatamente assim que o layout.tsx funciona. 😉

Listas e keys

O .map() da aula 02 continua sendo a ferramenta — só que agora ele devolve componentes:

<div className={estilos.grade}>
  {vagas.map((vaga) => (
    <VagaCard key={vaga.slug} vaga={vaga} />
  ))}
</div>
A key é obrigatória. Ela é o "RG" de cada item: é como o React sabe qual card é qual quando a lista muda de ordem ou tamanho. Use algo único e estável — o slug, o id. Evite o índice do array quando a lista puder ser reordenada ou filtrada.

Lista vazia

{vagas.length === 0 ? (
  <p>Nenhuma vaga com esses filtros 😔</p>
) : (
  vagas.map((v) => <VagaCard key={v.slug} vaga={v} />)
)}

Nunca esqueça deste caso — é o que separa um projeto de estudo de um projeto que parece profissional.

Onde o React foi instalado?

Boa pergunta — e a resposta desmistifica metade do "mundo Node". O create-next-app instalou três pacotes pra você:

// package.json — o que o seu projeto depende
"dependencies": {
  "next": "^16.2.10",        o framework
  "react": "^19.2.7",       a biblioteca de componentes
  "react-dom": "^19.2.7"    o que põe o React na tela do navegador
}

Duas coisas nascem daí:

  • package.json — a lista de compras. Diz o que o projeto precisa. Vai pro Git.
  • node_modules/ — as compras em si. Milhares de arquivos baixados. Nunca vai pro Git (o .gitignore já bloqueia).
Por isso o node_modules não vai pro Git: ele é gerado. Com o package.json na mão, qualquer pessoa reconstrói a pasta inteira com um comando. Mandar 300 MB pro GitHub pra quê? 😄

E quando eu clono um projeto que já existe?

É o caso do desafio: você clona o leque-de-vagas do GitHub. Como o node_modules não veio junto, você precisa instalar as dependências antes de rodar:

git clone https://github.com/Um-Leque-de-Tecnologia/leque-de-vagas.git
cd leque-de-vagas

npm install      # lê o package.json e baixa tudo (demora 1–2 min)
npm run dev
Esqueceu o npm install? O erro é bem característico: Error: Cannot find module 'next' ou 'next' não é reconhecido como um comando. Sempre que clonar um projeto Node, o primeiro comando é npm install.

Instalando um pacote novo depois

Quando você quiser adicionar uma biblioteca ao projeto (numa aula futura vamos adicionar algumas), é assim:

npm install nome-do-pacote        # vai pra dependencies
npm install -D nome-do-pacote     # só pra desenvolver (devDependencies)

O comando já atualiza o package.json sozinho. Você não edita esse arquivo na mão pra instalar coisa.

Rotas por pasta

A regra do App Router cabe numa frase: pasta = rota, arquivo page.tsx = a página. Não existe arquivo de configuração de rotas.

Você criaURL que nasce
app/page.tsx/
app/sobre/page.tsx/sobre
app/vagas/page.tsx/vagas
app/vagas/[slug]/page.tsx/vagas/qualquer-coisa
Pegadinha nº 1 da aula: criar app/sobre.tsx em vez de app/sobre/page.tsx. Sem o arquivo chamado exatamente page.tsx dentro da pasta, a rota não existe e você toma 404.

Os arquivos com nome reservado

ArquivoO que faz
page.tsxa página. Só ela cria a rota.
layout.tsxmoldura ao redor da página e de tudo abaixo dela
error.tsxaparece se algo quebrar (precisa de "use client")
not-found.tsxseu 404
loading.tsx (aula 05)aparece automaticamente enquanto a página espera dados de fora. Hoje não temos o que esperar.

Pastas que NÃO viram rota (grupos de rotas)

Uma pasta entre parênteses serve só pra organizar — ela não entra na URL. É o que o projeto usa nas telas de conta:

app/(conta)/layout.tsx           ← layout só destas telas
app/(conta)/entrar/page.tsx      → /entrar   (e não /conta/entrar)
app/(conta)/cadastro/page.tsx    → /cadastro

Assim /entrar e /cadastro compartilham aquele cartão centralizado, sem que a URL fique mais comprida por causa disso. E os layouts se aninham: o cabeçalho e o rodapé do layout raiz continuam aparecendo por fora.

layout.tsx — escreva o cabeçalho uma vez

Aquela dor de copiar a <nav> em todo arquivo HTML? Resolvida:

📄 app/layout.tsx
import Cabecalho from "@/components/Cabecalho";
import Rodape from "@/components/Rodape";
import "./globals.css";

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="pt-BR">
      <body>
        <Cabecalho />
        <main>{children}</main>   ← a página entra aqui
        <Rodape />
      </body>
    </html>
  );
}

Pontos importantes:

  • O layout raiz é obrigatório e é o único lugar com <html> e <body>
  • Ao navegar entre páginas, o layout não é remontado — por isso o cabeçalho não pisca
  • Layouts se aninham: app/vagas/layout.tsx envolve tudo dentro de /vagas, dentro do layout raiz

Navegação com <Link>

❌ <a href="/vagas">

Recarrega o site inteiro. Tela branca, JavaScript do zero, tudo de novo.

✅ <Link href="/vagas">

Troca só o que mudou e já baixa a página antes de você clicar (prefetch). 
import Link from "next/link";

<Link href="/vagas">Ver as vagas</Link>
<Link href={`/vagas/${vaga.slug}`}>{vaga.titulo}</Link>
<Link href="/vagas?nivel=Estágio">Só estágios</Link>
Regra: link interno do seu site → sempre <Link>. Link pra fora (GitHub, LinkedIn) → <a> normal com target="_blank" rel="noopener noreferrer".

Rota dinâmica [slug]

Uma pasta com o nome entre colchetes cria uma página por item. Nove vagas no array = nove páginas no site, e você escreveu um arquivo só.

📄 app/vagas/[slug]/page.tsx
import { notFound } from "next/navigation";
import { buscarVagaPorSlug, listarSlugs } from "@/lib/vagas";

type Props = { params: Promise<{ slug: string }> };

// Diz ao Next quais slugs existem → ele pré-gera essas páginas no build.
export async function generateStaticParams() {
  const slugs = await listarSlugs();
  return slugs.map((slug) => ({ slug }));
}

export default async function PaginaVaga({ params }: Props) {
  const { slug } = await params;        ← Next 16: params é Promise!
  const vaga = await buscarVagaPorSlug(slug);

  if (!vaga) notFound();               ← renderiza o not-found.tsx

  return <h1>{vaga.titulo}</h1>;
}
Pegadinha nº 2 da aula: no Next 16, params é uma Promise. Escrever params.slug direto (como em todo tutorial de 2024) dá erro. Sempre const { slug } = await params;.

Componentes de Servidor

Este é o conceito mais importante da aula. No App Router, todo componente é de servidor por padrão.

Isso significa que o código dele roda no servidor, monta o HTML, e o navegador recebe a página já pronta. O componente em si não vira JavaScript enviado pro navegador.

Você ganhaNa prática
Página levemenos JavaScript pra baixar = abre rápido no 4G
SEOo Google lê o conteúdo já no HTML
Segurançachave de API e senha de banco ficam no servidor
Buscar dados sem enrolaçãoquando os dados vierem de fora (aula 05), basta await — sem useEffect, sem estado de "carregando" na mão

O que ele NÃO pode fazer

  • useState, useEffect e outros hooks
  • onClick, onChange e outros eventos
  • window, document, localStorage

Pra isso existe o Componente de Cliente. 👇

Componentes de Cliente — "use client"

Quando o componente precisa reagir a quem usa, ele também precisa rodar no navegador. Você marca isso com uma linha:

📄 components/SalvarButton.tsx
"use client";   ← tem que ser a PRIMEIRA linha do arquivo

import { useState } from "react";

export default function SalvarButton() {
  const [salva, setSalva] = useState(false);

  return (
    <button onClick={() => setSalva(!salva)}>
      {salva ? "★" : "☆"}
    </button>
  );
}

useState em 30 segundos

const [valor, setValor] = useState(inicial);
  • valor — o dado atual
  • setValor(novo) — troca o dado e redesenha a tela
  • Nunca faça valor = novo na mão: o React não fica sabendo

useEffect: pra depois que a tela apareceu

useEffect(() => {
  // só roda no navegador, depois de renderizar
  setSalva(lerDoLocalStorage(slug));
}, [slug]);   ← roda de novo quando slug mudar
Por que não ler localStorage direto no corpo do componente? Porque o servidor não tem localStorage. O HTML do servidor sairia diferente do que o navegador desenha, e o React reclama: "hydration mismatch". Leia sempre dentro do useEffect.

Quando precisa de "use client"

Preciso de…Qual componente
Buscar dados, ler banco, usar chave secretaServidor (padrão)
Só mostrar conteúdoServidor (padrão)
useState, useEffectCliente
onClick, onChange, onSubmitCliente
window, localStorage, animaçãoCliente

A fronteira: empurre o "use client" pra baixo

Este é o erro mais comum de quem está começando: colocar "use client" no topo da página. Aí tudo dentro dela vira cliente, e você perde as vantagens do servidor.

❌ "use client" na página

A página, a lista, os 9 cards — tudo vira JavaScript baixado pelo navegador. 
"use client";
export default function Pagina() {
  ...9 cards...
}

✅ "use client" só no botão

A página e os cards continuam no servidor. Só a estrela vai pro navegador. 
// SalvarButton.tsx
"use client";
export default function SalvarButton() {...}

A diretiva contamina pra baixo

Esta é a parte que confunde: tudo que um componente de cliente importa também vira cliente, mesmo sem ter a linha. No Leque de Vagas, o Filtros.tsx não tem "use client" — e mesmo assim roda no navegador, porque quem importa ele é o MuralDeVagas.

Por isso a diretiva vai na fronteira: no componente mais alto que realmente precisa de estado. Daí pra baixo, é automático.

Quem é cliente no nosso projeto

ArquivoPor quê
SalvarButton.tsxtem useState e onClick
MuralDeVagas.tsxguarda a busca e os filtros
FormEntrar.tsx / FormCadastro.tsxformulários com estado
error.tsxtem o botão "tentar de novo"
Filtros.tsx, CampoTexto.tsxpor contágio — não têm a diretiva

Todo o resto — páginas, layouts, Cabecalho, Rodape, VagaCard — é servidor.

Regras da fronteira

  • Um componente de cliente não pode importar um de servidor diretamente
  • Mas ele pode receber um de servidor como children ou prop
  • Props que atravessam a fronteira precisam ser "serializáveis": texto, número, array, objeto simples
  • De cliente pra cliente, função atravessa normalmente — é assim que o MuralDeVagas passa o aoMudarBusca pro Filtros
Custo honesto: filtrar no cliente obriga a lista inteira de vagas a viajar pro navegador. Funciona bem com 9 vagas — e é o que a gente sabe fazer hoje. Na aula 05 o filtro volta pro servidor e esse custo some.

De onde vêm os dados

Hoje não tem backend. As vagas moram num arquivo do próprio projeto. Nada é buscado de fora — nem API, nem banco. Buscar dados externos é a aula 05 inteira.
📄 lib/dados.ts
export const VAGAS = [
  { slug: "estagio-front-end-nuvem-rosa",
    titulo: "Estágio em Front-end",
    empresa: "Nuvem Rosa",

Como os dados já estão na memória, a leitura é instantânea: não precisa de async, nem de await, nem de estado de carregando.

export default function PaginaVagas() {

Repare que nenhuma página conhece o lib/dados.ts. Todas passam pelo lib/vagas.ts:

Isto é arquitetura, não frescura. Na aula 05 os dados passam a vir de fora. Como todas as páginas falam só com o lib/vagas.ts, só esse arquivo muda — as páginas nem ficam sabendo. É a diferença entre código que aguenta crescer e código que precisa ser reescrito.

useState e estado derivado

Estado é a memória do componente: um dado que, quando muda, faz a tela se redesenhar sozinha.

const [busca, setBusca] = useState("");
//      ↑       ↑                  ↑
//  o valor  como mudar     o valor inicial
  • busca — o dado agora. Você lê, nunca escreve direto
  • setBusca(novo) — troca o dado e redesenha a tela
  • busca = "x" — ❌ nunca. O React não fica sabendo
O erro que todo mundo comete uma vez: mudar a variável na mão e ficar quinze minutos procurando por que a tela não atualizou. Se não passou pelo setAlgumaCoisa, o React não redesenha.

⭐ Estado derivado — a regra que evita metade dos bugs

Se dá pra calcular a partir do que você já tem, não guarde em estado.

❌ dois estados que precisam combinar

const [busca, setBusca] = useState("");
const [lista, setLista] = useState(vagas);

// e agora, em TODO lugar que mexe na
// busca, você tem que lembrar de
// atualizar a lista também. Um dia
// você esquece — e a tela mente.

✅ um estado, o resto é conta

const [busca, setBusca] = useState("");

// recalculado a cada renderização,
// sempre coerente com a busca
const visiveis = filtrarVagas(vagas, { busca });

Dois estados que precisam "combinar" um com o outro são uma dupla que um dia vai brigar. Guarde o mínimo; derive o resto.

Componente controlado

No projeto, o MuralDeVagas guarda o estado e o Filtros só recebe valores e funções:

<Filtros
  busca={busca}
  aoMudarBusca={setBusca}
/>

O Filtros não guarda nada — ele avisa quem manda. Isso deixa ele simples de entender, fácil de reaproveitar e sem duas versões da verdade na aplicação.

Formulários controlados

É aqui que quase todo mundo trava — e é o pedaço de interface que mais aparece em teste técnico de vaga júnior. Vale dominar.

A ideia: o valor vem do estado

const [email, setEmail] = useState("");

<input
  value={email}
  onChange={(evento) => setEmail(evento.target.value)}
/>

O ciclo é: você digita → o onChange dispara → o estado muda → o React redesenha → o input mostra o valor novo. Parece uma volta desnecessária, mas é o que te dá controle: dá pra validar, formatar e desabilitar o botão a cada tecla.

Campo travado? Você colocou value={email} e esqueceu do onChange. Aí você digita e nada aparece: o valor está preso num estado que ninguém atualiza. É o bug nº 1 de formulário em React.

Enviar sem recarregar a página

function enviar(evento) {
  evento.preventDefault();   ← sem isto o navegador recarrega tudo

  const novos = validar();
  setErros(novos);
  if (Object.keys(novos).length > 0) return;

  setEnviando(true);
  // aula 05: aqui entra a conversa com o servidor
}

<form onSubmit={enviar} noValidate>

O noValidate desliga as mensagens automáticas do navegador — aquelas balõezinhas em inglês que você não controla. Assim as suas mensagens (em português, com o seu tom) são as únicas que aparecem.

Um componente pra não repetir campo

O /entrar tem 2 campos e o /cadastro tem 4. Escrever rótulo + input + erro seis vezes seria a dor da aula 03 de volta. Por isso existe o CampoTexto:

<CampoTexto
  id="email"
  rotulo="E-mail"
  tipo="email"
  valor={email}
  aoMudar={setEmail}
  erro={erros.email}
/>

Um componente, seis usos. É a componentização da aula 03 valendo de novo.

Estado de carregando

<button type="submit" disabled={enviando}>
  {enviando ? "Entrando…" : "Entrar"}
</button>

O disabled não é enfeite: sem ele, um clique duplo ansioso envia o formulário duas vezes — e cria duas contas.

Validação e feedback

Validar é fácil. Validar sem irritar é o que separa uma interface boa de uma chata.

Uma função que devolve os erros

function validar() {
  const novos = {};

  if (!email.trim()) {
    novos.email = "Escreva seu e-mail.";
  } else if (!email.includes("@")) {
    novos.email = "Esse e-mail não parece completo.";
  }

  if (senha.length < 6) {
    novos.senha = "A senha tem pelo menos 6 caracteres.";
  }

  return novos;   ← objeto vazio = está tudo certo
}

Uma função separada, que só recebe e devolve. Fácil de ler, fácil de testar e fácil de crescer quando aparecer uma regra nova.

Metadata e SEO

Você não escreve <head>. Você exporta um objeto e o Next monta as tags.

Página fixa

import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "Vagas",
  description: "Todas as vagas do mural.",
};

Página dinâmica

export async function generateMetadata({ params }: Props) {
  const { slug } = await params;
  const vaga = await buscarVagaPorSlug(slug);
  if (!vaga) return { title: "Vaga não encontrada" };

  return {
    title: `${vaga.titulo} — ${vaga.empresa}`,
    description: vaga.resumo,
    openGraph: { title: vaga.titulo, description: vaga.resumo },
  };
}

Template de título no layout raiz

export const metadata = {
  title: {
    default: "Leque de Vagas",
    template: "%s · Leque de Vagas",   ← %s vira o title da página
  },
};

Página com title: "Vagas" vira <title>Vagas · Leque de Vagas</title>.

Por que se importar: é o openGraph que faz seu link aparecer bonito quando alguém cola no WhatsApp ou no LinkedIn. Em portfólio, isso conta ponto.

Erros comuns 🔧

"Cannot find module 'next'" / "'next' não é reconhecido…"

Faltou o npm install. Acontece sempre que você clona um projeto: o node_modules não vem no Git, você precisa reconstruí-lo. Rode npm install na pasta do projeto e tente de novo.

"You're importing a component that needs useState…"

Faltou "use client" na primeira linha do arquivo. Coloque no componente menor possível, não na página.

"params should be awaited before using its properties"

Clássico do Next 16. Troque params.slug por const { slug } = await params; e deixe a função async.

404 numa página que eu acabei de criar

O arquivo precisa se chamar exatamente page.tsx, dentro da pasta. app/sobre.tsx não vira rota.

"Hydration failed" / "Text content did not match"

O HTML do servidor saiu diferente do navegador. Causas quase sempre: localStorage/window lidos fora do useEffect, ou Math.random() / hora atual no meio da renderização.

"Module not found: Can't resolve '@/components/…'"

Confira a maiúscula no nome do arquivo. No Windows funciona vagacard, no servidor da Vercel (Linux) não. Escreva igualzinho.

Digito no campo e nada aparece

Você colocou value={email} e esqueceu do onChange. O valor está preso num estado que ninguém atualiza. É o bug nº 1 de formulário em React.

A página recarrega quando envio o formulário

Faltou evento.preventDefault() na primeira linha da função de envio. Esse é o comportamento padrão do HTML — você precisa pedir pra ele não fazer isso.

Mudei a variável e a tela não atualizou

Alterar a variável direto (busca = "x") não avisa o React. Só o setBusca("x") redesenha a tela.

Meu CSS não aparece

Em CSS Module você precisa importar e usar className={estilos.card} — className="card" puro não funciona ali.

"Cannot read properties of undefined"

Você acessou um campo de algo que ainda não existe. Use vaga?.titulo ou verifique antes com if (!vaga) ….

Mudei o arquivo e nada mudou na tela

Salvou? O npm run dev ainda está rodando? Se sim, pare (Ctrl+C), apague a pasta .next e rode de novo.
