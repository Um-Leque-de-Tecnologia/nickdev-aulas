export default function Sobre() {

Depois o cabeçalho — o momento "adeus copiar-colar":

📄 components/Cabecalho.tsx
import Link from "next/link";

export default function Cabecalho() {
  return (
    <header>
      <Link href="/">🪭 Leque de Vagas</Link>
      <nav>
        <Link href="/vagas">Vagas</Link>
        <Link href="/sobre">Sobre</Link>

E colocamos ele no layout.tsx, uma vez só:

<body>
  <Cabecalho />

Momento "uau": troque um <Link> por <a> e navegue. A tela pisca. Volte pro <Link>. Não pisca. A turma inteira entende de uma vez.

  • Cabeçalho e rodapé no layout raiz

Servidor x Cliente — o conceito central

75 min

O bloco mais importante do dia. Vale ir devagar e conferir se todo mundo acompanhou antes de seguir.

1. Prove que roda no servidor. Coloque um console.log dentro da página e mostre que ele aparece no terminal, não no console do navegador. Silêncio na sala — e então a ficha cai.

2. Mostre o erro acontecer. Adicione useState num componente sem "use client" e deixe o Next reclamar. Leiam a mensagem juntos. Depois adicione a linha e resolva.

📄 components/SalvarButton.tsx
"use client";

import { useState } from "react";

export default function SalvarButton() {
  const [salva, setSalva] = useState(false);

  return (
    <button onClick={() => setSalva(!salva)}>
      {salva ? "★" : "☆"}
    </button>
  );
}

3. A fronteira. Mostre o "Ver código-fonte" da página: o HTML dos cards está lá, pronto. Só o botão virou JavaScript. Explique por que colocar "use client" na página inteira jogaria isso fora.

4. localStorage e o hydration mismatch. Leia o localStorage fora do useEffect, mostre o erro vermelho, e conserte movendo pro useEffect. É um erro que a turma vai encontrar sozinha depois — melhor ver acontecer aqui.

  • Todo mundo viu o console.log no terminal
  • Todo mundo provocou e leu o erro de useState sem "use client"
  • O botão ★ funciona e guarda no localStorage
  • A turma consegue responder: "isto aqui é servidor ou cliente?"

Rota dinâmica, metadata e os estados da tela

45 min

A página de detalhe da vaga. Comece criando a pasta com colchetes e deixe a turma reagir ao nome estranho.

📄 app/vagas/[slug]/page.tsx
import { notFound } from "next/navigation";

export default async function PaginaVaga({
  params,
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;   ← Next 16!
  const vaga = await buscarVagaPorSlug(slug);
  if (!vaga) notFound();

  return <h1>{vaga.titulo}</h1>;
}

Na sequência, sem pressa:

  • Fazer o card linkar pro detalhe com href={`/vagas/${vaga.slug}`}
  • Digitar uma URL inventada e ver o notFound() agir
  • Criar not-found.tsx com a cara do projeto
  • Criar loading.tsx — e mostrar ele aparecendo (o demora() em lib/vagas.ts existe exatamente pra isso)
  • generateMetadata — abrir a aba do navegador e ver o título mudar por vaga
  • generateStaticParams — rodar npm run build e mostrar as 9 páginas geradas na tabela do terminal
Momento forte: o npm run build mostrando ● (SSG) /vagas/[slug] com as 9 rotas listadas. "Você escreveu um arquivo. O Next fez nove páginas."

Busca e filtros na URL

60 min

Comece perguntando: "como vocês fariam a busca?". Quase todo mundo vai responder useState. Aí você mostra o caminho melhor.

export default async function PaginaVagas({
  searchParams,
}: {
  searchParams: Promise<{ busca?: string; area?: string }>;
}) {
  const { busca = "", area = "" } = await searchParams;
  const vagas = await listarVagas({ busca, area });
  ...
}
<form action="/vagas">
  <input type="search" name="busca" defaultValue={busca} />
  <button>Buscar</button>
</form>

Depois de funcionar, faça as três demonstrações que vendem a ideia:

  1. Copie a URL filtrada e cole em outra aba — o filtro veio junto
  2. Aperte voltar — o filtro desfaz sozinho
  3. Desligue o JavaScript no DevTools — a busca continua funcionando

Feche o bloco com a tabela do que mudou no Next.js 16: por que params e searchParams são Promise, e por que tutoriais antigos vão quebrar.

Se a turma travar

  • Alguém não conseguiu instalar o Node — coloque em dupla com quem conseguiu. Ninguém fica de fora do dia por causa de instalador.
  • Ritmos muito diferentes — quem terminou vira monitor. Explicar é o melhor jeito de fixar.
  • Erro de TypeScript no meio do live coding — leia a mensagem em voz alta e traduza. Normalizar erro é parte da aula.
  • Atrasou o cronograma — corte primeiro os bônus, depois o bloco de busca/filtros (vira desafio). Nunca corte o bloco de Servidor x Cliente.
