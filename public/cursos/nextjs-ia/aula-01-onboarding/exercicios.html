Exercícios em aula · Aula 01

O primeiro dia no time 🧭

Dois labs. No primeiro, você faz o Copilot explicar um repositório que nunca viu — e confere frase por frase, no arquivo. No segundo, você escreve o primeiro "use client" do LequePlay, depois de ler o erro que a falta dele provoca.

✅

Antes de começar

  • Node 20.9+ instalado: node -v responde 20.9 ou mais.
  • O lequeplay-web clonado e aberto no seu editor.
  • npm run dev sobe sem erro no terminal.
  • http://localhost:3000 abre o LequePlay no navegador.

Se alguma falhar, resolva agora. Os dois labs dependem das quatro, e ninguém pega ticket com o ambiente pela metade.

🧠

A habilidade do dia

Ninguém aqui precisa saber construir um app Next do zero. Precisa saber navegar e alterar um que já existe. É o primeiro dia de qualquer pessoa júnior num emprego de verdade — e a IA é a ferramenta que torna esse primeiro dia sobrevivível.

O copiloto acelera o tour. E ele afirma com a mesma segurança quando acerta e quando erra. Por isso o lab 1 não termina na resposta dele: termina no arquivo aberto na sua frente.

Os labs
LAB 1

O tour do repositório

~20 min

Fazer o Copilot explicar o lequeplay-web — e conferir cada afirmação abrindo o arquivo citado.

  1. Suba o produto. Cinco comandos, na ordem abaixo.
  2. Pergunte ao Copilot Chat, com a pasta do projeto aberta, nestas palavras: "o que este projeto faz e como os arquivos se organizam?"
  3. Numere a resposta. Cole num rascunho e quebre em afirmações — uma linha cada. Você vai conferir uma por uma.
  4. Abra o arquivo que cada afirmação cita. Marque a linha com confere, não confere ou não tinha como saber.
  5. Use a tabela abaixo. São cinco conferências que sempre rendem.
$ git clone https://github.com/Um-Leque-de-Tecnologia/lequeplay-web $ cd lequeplay-web $ npm install $ cp .env.example .env.local $ npm run dev ▲ Next.js 16.3.2 (Turbopack) - Local: http://localhost:3000 ✓ Ready ← o catálogo abre sem a API no ar, porque USAR_MOCK=true

"os dados vêm da API em API_URL"Seu .env.local. Com USAR_MOCK=true, quem serve é data/midias.json.

Guarde a resposta inteira. Ela volta no lab 2. Repare no tom: ele descreve o que não conferiu com a mesma calma com que descreve o que conferiu.

responda
  1. Alguma afirmação cita arquivo ou pasta que não existe na árvore? Qual?
  2. Ele falou de params ou searchParams? Disse que dá para ler direto, sem await?
  3. Qual afirmação ele não tinha como saber — porque depende de arquivo que não está no Git?
  4. Das afirmações que você numerou, quantas você conferiu abrindo o arquivo?
conferir depois de responder

1. Os três clássicos: pages/ no lugar de app/, uma pasta src/, e um arquivo de configuração inventado. A árvore real é app/, components/, lib/, data/, docs/ — sem pages/ e sem src/. Não existe tailwind.config.js: no Tailwind v4 a configuração mora no CSS, e aqui está no @import "tailwindcss" de app/globals.css. O arquivo de config do Next existe, mas é next.config.ts — e o que tem dentro dele é a raiz do Turbopack, não o que ele descreveu.

2. Esse é o erro mais caro do dia. No Next 16, params e searchParams são Promise e precisam de await. Está escrito e comentado em app/midias/page.tsx e em app/midias/[slug]/page.tsx. Um modelo treinado no Next 14 diz que são objetos comuns, com toda a calma do mundo.

3. O .env.local. O .gitignore ignora .env* — só o .env.example é versionado. Ele não tem como saber que o seu está com USAR_MOCK=true, que é justamente o que faz o front rodar sem a API. Se ele afirmou de onde vêm os dados, ele adivinhou.

4. Se a resposta for "nenhuma", o lab não aconteceu. A habilidade não é receber a explicação: é conferi-la. E o repositório já avisava — o AGENTS.md da raiz, que o próprio next dev escreve (não o time), diz em inglês que esta não é a Next.js que você conhece e manda ler a doc da versão instalada, em node_modules/next/dist/docs/. O framework avisa os modelos de que eles estão desatualizados.

Extra. As convenções que ele deveria seguir aqui estão em .github/copilot-instructions.md: versionado, escrito pelo time, e muda por PR como qualquer outro código.

LAB 2

O primeiro "use client" do projeto

~20 min

Escrever o primeiro componente de cliente do LequePlay — e chegar até ele pelo erro, não pela resposta pronta.

A ordem é o exercício. Peça, rode, leia o erro inteiro, e só então ponha a linha. Se você já sabe qual é a linha, melhor ainda: segure. O erro é o conteúdo do lab.

  1. Peça ao Copilot Chat, sem adiantar nada: "crie components/botao-copiar-link.tsx: um botão que copia o endereço da página atual para a área de transferência". Não escreva "use client" no pedido.
  2. Salve o que ele deu, do jeito que ele deu. Sem corrigir.
  3. Use na página do título: importe e ponha o componente em app/midias/[slug]/page.tsx, logo abaixo do <h1>.
  4. Abra http://localhost:3000/midias/a-ultima-linha.
  5. O erro aparece. Leia inteiro, em voz alta, antes de tocar em qualquer coisa.
  6. Agora sim: a linha, no topo do componente. Recarregue e clique.
// components/botao-copiar-link.tsx — o que ele costuma entregar
export function BotaoCopiarLink() {
  return (
    <button
      type="button"
      onClick={() => navigator.clipboard.writeText(location.href)}
      className="rounded-md border border-white/15 px-3 py-2 text-sm"
    >
      🔗 Copiar link
    </button>
  );
}
// app/midias/[slug]/page.tsx — duas linhas, nada mais
import { BotaoCopiarLink } from "@/components/botao-copiar-link";

// … dentro do return, logo abaixo do <h1> com o titulo:
<BotaoCopiarLink />

O erro, inteiro

Error: Event handlers cannot be passed to Client Component props. <button type="button" onClick={function onClick} className=... children=...> ^^^^^^^^^^^^^^^^^^ If you need interactivity, consider converting part of this to a Client Component.

Em português simples: "você me deu uma função para escutar o clique, e eu não tenho quem escute". O clique acontece no dedo da pessoa, depois que a página já está na tela — e a essa altura o servidor terminou o trabalho e foi embora. navigator e location também só existem lá, no navegador dela.

É essa a linha

// components/botao-copiar-link.tsx — primeira linha do arquivo
"use client";
  • Primeira linha, antes dos import. Com aspas e ponto e vírgula: não é comentário, é uma instrução para o Next.
  • Ela não tira o arquivo do servidor — ela acrescenta o navegador. O HTML continua vindo pronto; o que muda é que o código viaja junto, para o clique ter quem o escute.
  • Marque a folha, não a raiz. app/midias/[slug]/page.tsx continua Server Component: é lá que roda o await buscarMidia(slug), e esse acesso à API não desce para o navegador.

Confira que é o primeiro mesmo. Rode grep -rn "use client" app components lib antes e depois. Antes do seu commit, o repositório inteiro devolve zero linhas.

responda
  1. Em que arquivo a linha entrou? Por que não em app/midias/[slug]/page.tsx?
  2. O Copilot avisou que faltava a linha, sem você perguntar?
  3. Traduza o erro com as suas palavras, em uma frase.
  4. navigator.clipboard — por que ele não existe no servidor?
conferir depois de responder

1. Em components/botao-copiar-link.tsx. A linha marca uma fronteira, e tudo que está dentro de um componente de cliente viaja com ele. Se ela fosse para o page.tsx, a página inteira desceria para o navegador — junto com o await buscarMidia(slug), que é o acesso à API. O botão é uma folha: marque a folha.

2. Quase nunca avisa. E as convenções do time mandam avisar: .github/copilot-instructions.md diz que, ao sugerir "use client", ele deve explicar na mesma resposta por que é necessário. Guarde a cena — o mesmo tom de confiança apareceu quando ele acertou o resto do tour, no lab 1. O tom não distingue acerto de erro. Você distingue, abrindo o arquivo e rodando.

3. Vale qualquer frase com esse sentido: "eu recebi uma função para o clique, e ninguém no HTML pronto sabe executá-la". Se você conseguiu escrever a frase, você entendeu a fronteira — e é isso que a revisão vai te perguntar no PR.

4. Porque navigator e location são objetos do navegador. No servidor não existe janela, nem área de transferência, nem pessoa clicando. Um arquivo que precisa deles precisa rodar lá. Server Component é o padrão do projeto; "use client" é a exceção, e toda exceção vem com um motivo escrito.

Extra. O AGENTS.md da raiz já avisava que isso ia acontecer — e ele não foi escrito pelo time, foi gerado pelo próprio next dev.

Se travar
o que apareceo que costuma ser
Event handlers cannot be passed to Client Component propsÉ o erro do lab 2, e ele é esperado. Se continua depois da linha: ela não é a primeira do arquivo, ou entrou no arquivo errado.
This React hook only works in a client componentMesma causa, outra porta: o componente usa useState ou useEffect e ainda é Server Component.
params should be awaited before using its propertiesparams e searchParams são Promise no Next 16. Falta o await. Compare com app/midias/page.tsx, que já faz certo.
API_URL não está configurada. Veja o .env.exampleO .env.local não foi criado, ou está com USAR_MOCK=false. Rode cp .env.example .env.local e suba o npm run dev de novo.
Module not found: Can't resolve '@/components/botao-copiar-link'Nome do arquivo. Arquivos aqui são kebab-case, componentes são PascalCase. Confira letra por letra.
404 em /midias/alguma-coisaO slug não existe. Os oito slugs válidos estão em data/midias.json — por exemplo a-ultima-linha.
O .env.local mudou e a tela nãoVariável de ambiente é lida quando o servidor sobe. Pare o npm run dev e suba outra vez.

Daqui sai o ticket da semana

Os dois labs são treino, direto no lequeplay-web. O ticket pega o botão que você acabou de escrever e leva até o Pull Request: branch, npm run build passando, descrição preenchida e o Copilot Code Review comentando antes de qualquer humano.

O que a revisão lê primeiro é "a decisão que eu tomei" — está no .github/pull_request_template.md. Depois de hoje, você tem uma decisão para escrever ali: por que a linha entrou no componente, e não na página.
