O contrato deste curso

Isto não é uma sequência de exercícios. É uma simulação de emprego, e ela tem regras.

Você é o front

Você cuida do que a pessoa vê. O lequeplay-web é seu território — e ele não é dono dos dados.

O backend existe

Quem guarda o catálogo, as contas e as avaliações é a API. O combinado com ela está escrito em docs/api-contrato.md.

A IA em dois papéis

Ela é a sua ferramenta — e, nas últimas sprints, vira feature do produto. Hoje só o primeiro papel.

O vocabulário muda a partir de hoje

sprintticketPR code reviewdeploybacklog onboarding

O trabalho da semana não é um "desafio": é um ticket. Você pega um cartão do backlog, resolve numa branch e entrega por Pull Request. Quem revisa lê a sua justificativa antes de ler o seu código.

Uma regra que vale as oito sprints, e está escrita no README.md do produto: você é responsável pelo que entrega. Código que você não sabe explicar não vai para o PR. Não é moral — é que na revisão, e na entrevista, quem responde é você.

// a tese da aula

Você não conhece Next.js. Ótimo.

Dá para gastar três aulas de fundamento antes de tocar no produto. Seria outro curso — e ele já existe aqui no site. A saída é outra: mudar o que saber Next significa neste curso.

a frase que sustenta as oito aulas

Ninguém precisa saber construir um app Next do zero. Precisa saber navegar e alterar um que já existe.

O que não vai acontecer

Você não vai escrever um Next do zero hoje. Nem amanhã. Ninguém no seu futuro emprego vai te pedir isso na primeira semana.

O que vai acontecer

Você vai abrir um repositório que outra pessoa escreveu, achar o arquivo certo, entender por que ele é do jeito que é, e mudá-lo sem quebrar o resto.

É o primeiro dia de qualquer pessoa júnior num emprego de verdade. A diferença é que hoje você tem uma ferramenta que a geração anterior não tinha: um copiloto que lê o repositório inteiro em segundos. É ela que torna esse primeiro dia sobrevivível.

E ela erra. Erra com a mesma voz confiante de quando acerta. Conferir cada afirmação é a habilidade que este curso treina — começando no lab 1, daqui a pouco.

Duas regras que o mapa impõe

O nome page.tsx não é escolha

É o que faz a pasta virar endereço. Um arquivo chamado catalogo.tsx dentro de app/midias/ não vira rota nenhuma.

Colchete = pedaço que muda

[slug] atende qualquer título. Isso tem nome, regras e uma aula inteira — aula 03. Hoje guarde só o colchete.

Faça isso agora, com o professor: abra /midias/protocolo-aberto no navegador e ache, no editor, o arquivo que desenhou aquilo. É a habilidade número um do seu primeiro mês em qualquer time de front.

No console do navegador

F12 → aba Console. É onde quase todo mundo procura primeiro. Não está lá.

No terminal do npm run dev

Naquela janela que ficou aberta atrás do editor. É ali que ele aparece — e isso não é curiosidade, é a aula.

O comentário que já está nesse arquivo, escrito por quem veio antes de você, diz a mesma coisa em duas linhas: "este await roda no servidor, e o navegador recebe o HTML já pronto. Nenhuma credencial da API chega ao cliente."

// bloco 3 · e isso tem nome

Esses arquivos têm nome: Server Components

E o "sem exceção" do slide anterior não é força de expressão. Rode você mesmo, na raiz do projeto:

$ grep -rn "use client" app components lib $ # nenhum resultado. nem um.

Não existe um único "use client" no LequePlay hoje. Todo componente deste produto roda no servidor. Guarde isso: daqui a pouco você vai escrever o primeiro — e ele vai para o repositório de verdade.

// bloco 3 · o limite

O dia em que isso não basta: o clique

O ticket chegou. Na página de um título, um botão Copiar link: a pessoa clica e o endereço vai para a área de transferência dela — para mandar no grupo do trabalho.

Você pede ao Copilot. Ele responde em dois segundos, com a segurança de sempre:

📄 components/botao-copiar-link.tsx · o que o Copilot vai te dar
export function BotaoCopiarLink() {
  return (
    <button
      type="button"
      onClick={() => navigator.clipboard.writeText(location.href)}
    >
      🔗 Copiar link
    </button>
  );
}

Aceite como veio. Não corrija nada ainda — o próximo slide é a leitura desse arquivo, palavra por palavra.

// bloco 3 · o limite · por que não funciona

Três palavras que só existem no navegador

Elas estão num arquivo que hoje roda no servidor. Uma por uma:

onClick

O clique acontece no dedo da pessoa, depois que a página já está na tela. A essa altura o servidor terminou o trabalho e foi embora.

navigator

Área de transferência é coisa de navegador. No servidor essa palavra não existe.

location

O endereço da barra também só existe do lado de lá.

Isso não vai funcionar — e não é a sintaxe que está errada, é o lugar. E é exatamente por isso que o próximo slide é um lab.

A regra já estava escrita no .github/copilot-instructions.md do time: "Server Component é o padrão. Só use "use client" quando houver estado, efeito, evento de usuário ou API de navegador." O Copilot leu esse arquivo. E mesmo assim vai te entregar o botão sem a linha.

// bloco 3 · a fronteira

É essa a linha

O erro que você acabou de ver, e que vai reencontrar umas trinta vezes este semestre:

Error: Event handlers cannot be passed to Client Component props. <button type="button" onClick={function onClick}> ^^^^^^^^^^^^^^^^^^ If you need interactivity, consider converting part of this to a Client Component.

Em português: "você me deu uma função para escutar o clique, e eu não tenho quem escute". O servidor montou o HTML e foi embora. Ninguém ficou no navegador para ouvir o dedo da pessoa.

📄 components/botao-copiar-link.tsx · primeira linha
"use client";
1Primeira linha do arquivo, antes de qualquer import. Com aspas e ponto e vírgula: não é comentário, é uma instrução para o Next.
2Ela não tira o arquivo do servidor — ela acrescenta o navegador. O HTML continua vindo pronto; o que muda é que agora o código também viaja junto, para o clique ter quem o escute.
3Marque a folha, não a raiz. Tudo que estiver dentro de um componente de cliente viaja com ele.
// bloco 3 · a fronteira · onde marcar

Por que a folha, e não a raiz

A tentação é pôr a linha na página e resolver de uma vez. Olhe o que a página faz antes de fazer isso:

app/midias/[slug]/page.tsx servidor · faz await buscarMidia(slug) └─ components/botao-copiar-link.tsx "use client" ← a fronteira corta aqui

A linha no page.tsx

A página inteira desce para o navegador. O await buscarMidia(slug) perde o lugar onde rodava, e a chamada à API — com a API_URL junto — passa a ser problema do cliente.

A linha no botão

Só o botão viaja. A página continua buscando o dado no servidor, mandando HTML pronto, e o console.log dela continua saindo no terminal.

Um arquivo com essa linha é um Client Component. Sem ela, é um Server Component — que é o padrão. Você nunca escreve "use server" para isso: o servidor já é o normal. E o grep que a gente rodou agora acha exatamente um resultado: o seu.

⭐ bloco 3 · a lição que vale as oito aulas

Ele errou com a mesma voz de quando acerta

O Copilot não te enganou por má-fé. Ele te deu o Next que viu no treino — e esse Next mudou. A parte boa: o aviso já estava no repositório antes de você chegar.

<!-- BEGIN:nextjs-agent-rules --> # This is NOT the Next.js you know This version has breaking changes — APIs, conventions, and file structure may all differ from your training data. Read the relevant guide in `node_modules/next/dist/docs/` ... before writing any code. Heed deprecation notices.

Isso é o AGENTS.md, na raiz do lequeplay-web. Abra agora. E repare em quem o escreveu: ninguém do time. O bloco é escrito e re-adicionado pelo próprio next dev — dá para conferir em node_modules/next/dist/server/lib/generate-agent-files.js, como o próprio arquivo diz.

Leia de novo o que isso significa: o framework escreve, sozinho, um recado para os modelos de IA avisando que eles estão desatualizados sobre ele.

⭐ bloco 3 · a mesma lição, outro arquivo

O mesmo erro, na outra ponta do arquivo

Não é só o "use client". A assinatura da página mudou no Next 16, e o modelo aprendeu a antiga:

o que o modelo viu no treino 
export default function Pagina({ params }) {
  const midia = buscarMidia(params.slug);
  // ...
}

Funcionava. Hoje params.slug vem undefined, e o erro que aparece não fala em params coisa nenhuma.

o que o repositório faz 
export default async function PaginaDaMidia({
  params,
}: PageProps<"/midias/[slug]">) {
  const { slug } = await params;
  const midia = await buscarMidia(slug);
}

params e searchParams são Promise no Next 16. Precisam de await. Está assim no arquivo de verdade, agora.

A regra da casa, do README.md: quando a sugestão divergir da doc da versão instalada, a doc local ganha. Dois arquivos te protegem disso — o AGENTS.md, que o Next escreve, e o .github/copilot-instructions.md, que o time escreve e muda por PR.

O que a revisão lê primeiro

O campo que a revisão lê primeiro

O template de PR tem uma seção chamada "a decisão que eu tomei". Não é enfeite: é onde você escreve por que este componente é client e a página continuou server.

Código sem justificativa passa. Justificativa é o que faz você crescer — e é a pergunta que você vai ouvir numa entrevista.

O revisor robô erra também

O Copilot Code Review é um primeiro leitor rápido. Ele acha coisa boa e ele fala bobagem. Você decide o que aceitar — e responde o comentário dizendo por quê.

O template tem um campo para isso: "o que a IA sugeriu e eu recusei". Saber recusar é metade da habilidade.

O checklist do PR é curto e é levado a sério: roda sem erro no console · npm run build passa · navegação por teclado continua funcionando, com foco visível · sem any e sem ! para calar o compilador · se usei o Copilot, revisei linha a linha e sei explicar o que ficou.

🎫 o trabalho da semana

O seu primeiro ticket

O botão do lab 2 funciona na sua máquina. Isso não é uma entrega — é um rascunho. O ticket é transformá-lo em código que atravessa o code review e chega em produção.

O que entra

O BotaoCopiarLink acabado na página do título: rótulo claro, retorno visível para quem clicou, e "use client" só onde ele precisa estar.

Onde não entra

A app/midias/[slug]/page.tsx continua sem a linha. Se ela apareceu lá, o ticket voltou.

O que você defende

No campo "a decisão que eu tomei": por que a fronteira ficou na folha, e o que o Copilot sugeriu que você recusou.

Como fechar

  • Branch feat/ · npm run build passando · push · PR aberto com o template preenchido, seção por seção — inclusive o Fecha # lá em cima.
  • O Copilot Code Review vai comentar. Responda cada comentário — aceitando ou recusando com um motivo. Silêncio não fecha revisão.
  • Teste com o teclado antes de pedir revisão: Tab até o botão, Enter, foco visível. Está no checklist, e é onde este PR mais costuma cair.
  • Entrega antes da aula 02. Chegar com o PR aberto é o começo da próxima aula, não a lição de casa dela.

Os critérios de aceite, os casos de borda e o gabarito comentado estão no ticket da semana e nos códigos comentados. Leia o ticket inteiro antes de abrir o editor — inclusive a parte que diz o que não fazer.

O que fica de hoje

  • Você não precisa saber construir, precisa saber navegar. Abrir o repositório de outra pessoa, achar o arquivo e mudá-lo sem quebrar o resto é a habilidade do primeiro mês.
  • A pasta app é o mapa. O endereço na barra é o caminho da pasta, e page.tsx é o arquivo que desenha.
  • Servidor é o padrão. Todo componente roda lá, a menos que você diga o contrário — e "use client" não tira do servidor, acrescenta o navegador.
  • A linha vai na folha, não na raiz. Hoje o LequePlay tem exatamente um Client Component: o que você escreveu.
  • O copiloto afirma com a mesma segurança quando erra. Confira no arquivo, e quando a sugestão divergir da doc da versão instalada, a doc local ganha.
