Aula 01 · código do desafio

A API linha por linha

O desafio resolvido com o tema "livros", comentado. Use como referência quando travar — mas tente antes. Aqui o que importa não é a sintaxe: é entender quem cria os objetos.

🎨

O tema aqui é livros, o seu pode ser outro

Troque Livro por receitas, plantas, discos, jogos — o que te interessar. A estrutura não muda: um record, um @Service com a lista, um @RestController injetando por construtor.

Estrutura

Os pacotes

Tudo dentro do pacote da classe main — é o que o @ComponentScan varre.

📁 estrutura
src/main/java/com/seunome/biblioteca/
├── BibliotecaApplication.java   ← a classe main
├── model/
│   └── Livro.java                ← o record
├── service/
│   └── LivroService.java         ← regra e dados
└── controller/
    └── LivroController.java      ← fala HTTP
Se um pacote ficar fora daí — por exemplo com.seunome.controller, irmão em vez de filho — o Spring não encontra a classe e a rota dá 404 sem nenhum erro no terminal. É o erro mais difícil de achar da primeira semana.

pom.xml — só o que importa

O Initializr gera o arquivo inteiro. Estas são as partes que você deve saber ler:

📄 pom.xml
<parent>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-parent</artifactId>
  <version>4.1.0</version>      <!-- a versão do Spring -->
</parent>

<properties>
  <java.version>21</java.version>   <!-- a versão do Java -->
</properties>

<dependencies>
  <!-- traz Spring MVC + Tomcat embutido + Jackson (JSON) -->
  <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
  </dependency>

  <!-- reinicia sozinho quando você salva -->
  <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-devtools</artifactId>
    <optional>true</optional>
  </dependency>
</dependencies>
Repare no que NÃO está lá: nenhuma versão nas dependências. O parent já define versões compatíveis entre si — é isso que um "starter" resolve.
O código

Gerado pelo Initializr. Você não mexe nele hoje.

📄 BibliotecaApplication.java

import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class BibliotecaApplication {

  public static void main(String[] args) {
    SpringApplication.run(BibliotecaApplication.class, args);
  }
}

model/Livro.java

Um record: classe imutável com construtor, getters, equals, hashCode e toString prontos. É Java puro — nada de Spring aqui.

📄 model/Livro.java
package com.seunome.biblioteca.model;

// os nomes dos campos viram as chaves do JSON
public record Livro(
    String titulo,
    String autor,
    int ano,
    String genero,
    double nota) {
}
Por que record e não classe: ele só transporta dados, não tem comportamento. Imutável significa que ninguém altera um livro por acidente depois de criado.

service/LivroService.java

⭐ Onde os dados e a regra moram. Repare que ele não sabe que existe HTTP — nenhum import de web, nenhum System.out.

📄 service/LivroService.java
package com.seunome.biblioteca.service;

import com.seunome.biblioteca.model.Livro;
import org.springframework.stereotype.Service;
import java.util.Comparator;
import java.util.List;

// @Service diz ao Spring: crie uma instância disto e guarde
@Service
public class LivroService {

  // List.of devolve uma lista IMUTÁVEL — ninguém altera o acervo
  private final List<Livro> acervo = List.of(
      new Livro("Duna", "Frank Herbert", 1965, "Ficção", 9.2),
      new Livro("Neuromancer", "William Gibson", 1984, "Ficção", 8.7),
      new Livro("Vidas Secas", "Graciliano Ramos", 1938, "Drama", 9.0),
      new Livro("Torto Arado", "Itamar Vieira Junior", 2019, "Drama", 9.5),
      new Livro("O Cortiço", "Aluísio Azevedo", 1890, "Realismo", 8.4)
  );

  // rota 1: o acervo inteiro
  public List<Livro> listar() {
    return acervo;
  }

  // rota 2: o de maior nota. orElseThrow porque a lista pode estar vazia
  public Livro destaque() {
    return acervo.stream()
        .max(Comparator.comparingDouble(Livro::nota))
        .orElseThrow();
  }

  // rota 3: o filtro — a Stream API da aula de OO, aqui no service
  public List<Livro> porGenero(String genero) {
    return acervo.stream()
        .filter(livro -> livro.genero().equalsIgnoreCase(genero))
        .toList();
  }
}
O filtro mora aqui, não no controller. É a regra que separa as camadas: se amanhã a mesma busca precisar ser exposta por linha de comando, o service continua servindo sem mudar uma linha.

controller/LivroController.java

⭐ O coração do desafio. Repare no que não existe: nenhum new LivroService().

📄 controller/LivroController.java
package com.seunome.biblioteca.controller;

import com.seunome.biblioteca.model.Livro;
import com.seunome.biblioteca.service.LivroService;
import org.springframework.web.bind.annotation.*;
import java.util.List;

@RestController
@RequestMapping("/livros")   // prefixo de todas as rotas da classe
public class LivroController {

  private final LivroService service;

  // INJEÇÃO POR CONSTRUTOR
  // O Spring vê que este construtor pede um LivroService,
  // procura o bean e entrega pronto. Como só existe UM
  // construtor, o @Autowired é opcional — pode omitir.
  public LivroController(LivroService service) {
    this.service = service;
  }

  // GET /livros
  @GetMapping
  public List<Livro> listar() {
    return service.listar();
  }

  // GET /livros/destaque
  @GetMapping("/destaque")
  public Livro destaque() {
    return service.destaque();
  }

  // GET /livros/genero/Ficção
  // @PathVariable pega o pedaço da URL e entrega como parâmetro
  @GetMapping("/genero/{genero}")
  public List<Livro> porGenero(@PathVariable String genero) {
    return service.porGenero(genero);
  }
}
O controller é burro de propósito. Cada método dele faz uma coisa só: receber a requisição e repassar pro service. Se um dia você vir lógica de negócio aqui dentro, é sinal de que ela está no lugar errado.

Se der errado

Os quatro que mais aparecem, com a causa real:

# 404 na rota que você acabou de criar → a classe está fora do pacote da main, ou faltou @RestController # Port 8080 was already in use → tem outra execução rodando. Pare no ⏹ da IDE, ou: Linux/macOS: lsof -ti:8080 | xargs kill Windows: netstat -ano | findstr :8080 # No qualifying bean of type 'LivroService' → faltou @Service na classe, ou ela está fora do pacote varrido # imports do Spring em vermelho na IDE → você abriu o arquivo em vez da pasta do projeto; ou o Maven ainda não baixou. Recarregue o projeto Maven.
Leia a primeira linha do erro. O Spring costuma dizer exatamente o que faltou, e frequentemente sugere a correção num bloco Action logo abaixo. A pilha de 60 linhas quase nunca é onde está a resposta.
