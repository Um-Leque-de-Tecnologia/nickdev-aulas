Desafio · Aula 01

Sua primeira API REST 🌱

Criar um projeto Spring Boot do zero, com controller e service conversando por injeção de dependência, e publicar uma API com três rotas que respondem JSON. O tema do acervo é seu.

🎯

O objetivo

Provar que você entendeu o conceito central da aula: a sua classe declara o que precisa e o Spring entrega. Se em algum lugar do seu código tiver um new criando um service, o desafio não está cumprido — mesmo que a API funcione.

🎨

O tema é seu

Na aula usamos mídias, mas escolha o que você teria vontade de catalogar: livros, receitas, plantas, discos, jogos, trilhas de estudo. A estrutura é a mesma — e um tema que te interessa deixa o projeto muito mais fácil de terminar.

Passo a passo
01

Crie o projeto no Initializr

Em start.spring.io, com estas escolhas:

  • Maven · Java · Spring Boot 4.1.x (versão estável, sem SNAPSHOT)
  • Group com.seunome · Artifact do seu tema · Packaging Jar · Java 21
  • Dependências: Spring Web e Spring Boot DevTools

Só essas duas. Banco e segurança vêm nas próximas aulas — cada dependência a mais é mais coisa pra dar errado hoje.

02

Rode e confirme que subiu

$ ./mvnw spring-boot:run Tomcat initialized with port 8080 (http) Started SuaApplication in 1.4 seconds

Antes de escrever qualquer linha: garanta que o projeto vazio sobe. Se der erro aqui, é ambiente — e é bem mais fácil resolver agora que depois de escrever três classes.

03

Crie o record do seu domínio

Um record com pelo menos 4 campos, sendo ao menos um numérico e um textual. Exemplo com livros:

public record Livro(
    String titulo,
    String autor,
    int ano,
    String genero,
    double nota) {}
04

Crie o service ⭐

Anotado com @Service, guardando uma lista fixa de no mínimo 5 itens e expondo os métodos que o controller vai usar.

@Service
public class LivroService {

  private final List<Livro> acervo = List.of(
      new Livro("Duna", "Frank Herbert", 1965, "Ficção", 9.2),
      // ... pelo menos mais 4
  );

  public List<Livro> listar() { return acervo; }
}

Regra de camada: nada de System.out.println nem Scanner aqui dentro. O service não sabe que existe HTTP nem terminal — ele só recebe e devolve dados.

05

Crie o controller injetando por construtor ⭐

É aqui que o desafio é avaliado de verdade.

@RestController
@RequestMapping("/livros")
public class LivroController {

  private final LivroService service;

  // o Spring entrega o service pronto — sem new, sem @Autowired
  public LivroController(LivroService service) {
    this.service = service;
  }

  @GetMapping
  public List<Livro> listar() {
    return service.listar();
  }
}
06

Três rotas GET, uma com filtro

A terceira é a que exige pensar — ela recebe um parâmetro e filtra a lista:

GET /livrosDevolve o acervo inteiro.
GET /livros/destaqueDevolve um item só — o de maior nota, por exemplo.
GET /livros/genero/{genero}Filtra por gênero, usando @PathVariable.
Ou: GET /livros?genero=FicçãoMesma ideia com @RequestParam. Escolha uma.

Dica: o filtro é stream().filter(...).toList() — a Stream API que você já viu em OO. Ela vive no service, não no controller.

07

Teste com curl e publique

$ curl localhost:8080/livros $ curl localhost:8080/livros/destaque $ curl "localhost:8080/livros/genero/Ficção"

Depois suba num repositório público com um README.md explicando o que é a API, como rodar e quais são as rotas.

Não suba a pasta target/. O Initializr já gera um .gitignore correto — confira se ele veio junto.

Requisitos mínimos
  • Projeto Spring Boot 4.1.x com Java 21, rodando
  • Um record com pelo menos 4 campos
  • @Service com no mínimo 5 itens no acervo
  • @RestController com injeção por construtor
  • 3 rotas GET, uma delas recebendo parâmetro e filtrando
  • A filtragem acontece no service, não no controller
  • Todas as classes dentro do pacote da classe main
  • Repositório público com README.md e as rotas documentadas
Extras, pra quem quiser ir além ✨
  • Uma rota que devolve estatísticas: total de itens, nota média, contagem por gênero
  • Ordenação por parâmetro: /livros?ordenar=nota
  • Trocar a porta para 8081 em application.properties e explicar no README por quê
  • Uma segunda entidade, com o seu próprio service e controller
  • Devolver 404 quando o filtro não encontrar nada (spoiler: ResponseEntity, assunto da aula 02)
O que NÃO pode 🚫
  • new LivroService() em qualquer lugar — quem cria é o Spring
  • @Autowired em campo: a injeção é por construtor
  • Regra de negócio ou filtro dentro do controller
  • System.out.println ou Scanner no service
  • Classe fora do pacote da main — o Spring não vai achar
  • Tudo numa classe só, sem separar controller e service
Como entregar
  1. Confira que a aplicação sobe do zero: ./mvnw clean spring-boot:run
  2. Teste as três rotas com curl e cole a saída no README
  3. Suba num repositório público no GitHub
  4. Mande o link no grupo, junto com uma frase sobre o que foi mais difícil
