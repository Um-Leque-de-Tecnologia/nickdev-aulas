O projeto linha por linha

O desafio resolvido, comentado. Use como referência quando travar — mas tente antes. O que importa aqui não é a sintaxe: é entender onde cada arquivo roda.

Três arquivos, e só

A aula 1 inteira cabe em três arquivos. Cada um vai ganhar camadas nas próximas 18 aulas — mas a espinha é esta.

A estrutura
meu-primeiro-next/
├── app/
│   ├── layout.tsx        ← moldura + metadata + nav
│   ├── page.tsx          ← rota /
│   ├── sobre/page.tsx    ← rota /sobre
│   └── globals.css
├── public/
├── next.config.ts
└── package.json
app/layout.tsx
import type { Metadata } from "next";
import Link from "next/link";
import "./globals.css";

// vira <title> e <meta name="description"> sozinho
export const metadata: Metadata = {
  title: "Meu primeiro Next",
  description: "Projeto da aula 01 de Frontend Avançado",
};

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    // lang="pt-BR" importa: o leitor de tela usa pra escolher a voz
    <html lang="pt-BR">
      <body className="min-h-screen bg-zinc-950 text-zinc-100">
        /* o nav vive no layout: não remonta ao navegar */
        <nav className="flex gap-4 border-b border-white/10 p-4">
          <Link href="/">Início</Link>
          <Link href="/sobre">Sobre</Link>
        </nav>

        <main className="mx-auto max-w-2xl p-8">{children}</main>
      </body>
    </html>
  );
}
💡

Por que o nav fica no layout

Porque o layout não é remontado quando você troca de rota — só o children muda. Se o nav estivesse dentro de cada page, seria destruído e recriado a cada navegação: pisca, perde estado e desperdiça trabalho.

app/page.tsx
export default function Home() {
  // ⭐ ESTE LOG APARECE NO TERMINAL, não no console do navegador.
  // Porque este componente roda NO SERVIDOR: ele é executado lá,
  // vira HTML, e só o HTML viaja até quem acessa.
  console.log("[home] renderizando no servidor");

  return (
    <section>
      <h1 className="text-4xl font-bold">Meu primeiro Next</h1>
      <p className="mt-4 text-zinc-400">
        Se você está lendo isto, o servidor gerou este HTML antes de
        mandar pro seu navegador.
      </p>
    </section>
  );
}
🔬

Como provar sozinha(o)

Botão direito → Ver código-fonte da página. O texto do h1 está lá, no HTML cru. Numa SPA tradicional você veria só uma <div id="root"></div> vazia — o conteúdo só apareceria depois do JavaScript rodar.

Extra · a rota dinâmica

Se você fez o extra: app/oi/[nome]/page.tsx. Uma pasta entre colchetes, infinitas páginas.

// ⚠️ Next 16: params é uma Promise. Sempre await.
export default async function Oi({
  params,
}: {
  params: Promise<{ nome: string }>;
}) {
  const { nome } = await params;

  return <h1 className="text-3xl">Oi, {decodeURIComponent(nome)}!</h1>;
}
⚠️

O detalhe que quebra tutorial antigo

No Next 16, params e searchParams são Promise. Muito material da internet ainda faz params.nome direto — hoje isso é erro. A regra prática: se o tutorial não tem await params, ele é de antes do Next 15.

O que o build revela

Rode pnpm build e leia a tabela. É a teoria da aula impressa no terminal:

$ pnpm build Route (app) ┌ ○ / ├ ○ /_not-found ├ ○ /sobre └ ƒ /oi/[nome] ○ (Static) prerendered as static content ƒ (Dynamic) server-rendered on demand
🎯

Repare no que aconteceu

/ e /sobre ficaram estáticas — o HTML foi gerado uma vez, no build. Já /oi/[nome] é dinâmica, porque o Next não sabe de antemão quais nomes existem. E você não escolheu nada disso: o Next deduziu a estratégia de cada rota a partir do que o código faz. É o slide virando terminal — na aula 4 você aprende a controlar isso de propósito.

Se der errado
# 404 na rota que você criou → o arquivo precisa se chamar page.tsx, dentro da pasta. app/sobre.tsx não vira rota. # Port 3000 is already in use → pnpm dev -p 3001, ou pare a execução anterior # o log não aparece em lugar nenhum → olhe o TERMINAL onde o pnpm dev roda, não o navegador. Em rota estática ele roda uma vez só: reinicie o dev. # build passa local e falha na Vercel → quase sempre maiúscula em import. Windows ignora, Linux não.
