ecossistema · o que mudou no React

Três eras, um problema só

EraComo se pensavaO que doía

até 2018		ciclo de vida: componentDidMountlógica espalhada em três métodos diferentes

2019–2022		estado e efeito em funçõestudo rodava no navegador: bundle grande, dados sempre em useEffect

O fio que liga as três: tirar trabalho do navegador de quem acessa. Cada era empurrou mais um pedaço pra outro lugar.

a dor · por que a SPA pura não bastou

O que acontece numa SPA

// o que o servidor manda numa SPA pura <body> <div id="root"></div> <script src="/bundle.js"></script> </body> // ...e só depois de baixar e executar o JS // é que qualquer conteúdo aparece

Tela branca

quem está no 4G espera o bundle inteiro antes de ver qualquer coisa.

SEO sofre

o buscador recebe uma div vazia. Ele até executa JS, mas com atraso e sem garantia.

Cascata de dados

renderiza → useEffect → busca → renderiza de novo. Sempre um passo atrás.

o conceito central · guarde esta tabela

Quatro estratégias de renderização

SiglaQuando o HTML é geradoBoa para
CSR
client-side		no navegador, depois do JS carregarpainel atrás de login, editor, dashboard
SSR
server-side		a cada requisição, no servidorconteúdo por usuário: carrinho, feed, extrato
SSG
static		uma vez, no buildlanding, blog, documentação
ISR
incremental		no build, e revalida de tempos em temposcatálogo, notícias — muda, mas não a cada acesso

A pergunta certa não é "qual é a melhor". É "com que frequência este conteúdo muda, e ele é igual pra todo mundo?" A resposta escolhe a estratégia.

o pulo do gato · e é aqui que o Next muda tudo

Isso não é escolha do projeto

❌ Como era

Você escolhia uma estratégia pro site inteiro. "Este projeto é SSR." Fim.

✅ Como é no App Router

A escolha é por rota — e, com Partial Prerendering, até por pedaço da mesma página.

Uma página de produto pode ter: o cabeçalho e a descrição estáticos, o preço revalidado a cada minuto, e o "seus itens no carrinho" por requisição. Tudo na mesma tela.

Por isso o curso não tem uma aula de "SSR" e outra de "SSG". Tem aulas sobre onde o código roda e quando ele revalida — que é o que realmente decide.

setup · o combinado técnico

O ambiente do semestre

Node 20.9+

o Next 16 exige. Confira com node -v.

pnpm

gerenciador de pacotes. Mais rápido e economiza disco.

Next.js 16.3

versão vigente, com Turbopack por padrão.

$ node -v v22.19.0 # instala o pnpm (vem junto com o Node moderno) $ corepack enable pnpm $ pnpm -v 10.x

Por que pnpm e não npm: ele guarda cada pacote uma vez só no disco e liga por atalho. Com vários projetos Next na máquina, a diferença é de gigabytes.

mão na massa · criando o projeto

Um comando, projeto pronto

$ pnpm create next-app@latest meu-projeto ✔ TypeScript? Yes ✔ ESLint? Yes ✔ Tailwind CSS? Yes ✔ App Router? Yes ✔ Turbopack? Yes ✔ import alias (@/*)? Yes $ cd meu-projeto $ pnpm dev ▲ Next.js 16.3.0 (Turbopack) - Local: http://localhost:3000 ✓ Ready in 812ms

o que veio na caixa

A estrutura do App Router

meu-projeto/ ├── app/ ← rotas e UI │ ├── layout.tsx moldura de tudo │ ├── page.tsx a rota "/" │ └── globals.css ├── public/ arquivos estáticos ├── next.config.ts ├── tsconfig.json └── package.json

Pasta = rota

app/sobre/page.tsx vira /sobre. Sem arquivo de configuração de rotas.

Nomes reservados

page, layout, loading, error, not-found — cada um com um papel. Aula 2.

Tudo é servidor por padrão

Componente só vira cliente quando você pede. Aula 3.

live code · lendo o que veio pronto

layout.tsx: a moldura

📄 app/layout.tsx
export default function RootLayout({ children, }: { children: React.ReactNode; }) { return ( <html lang="pt-BR"> <body>{children}</body> ← a página entra aqui </html> ); }

Ele não remonta ao navegar entre rotas — só o children troca. É por isso que o cabeçalho não pisca e o estado dele sobrevive à navegação.

live code · o primeiro Server Component

Você já escreveu um, sem saber

📄 app/page.tsx
export default function Home() { // isto roda NO SERVIDOR console.log("onde eu apareço?"); return <h1>Olá, mundo</h1>; }

Faça o teste agora

Salve e olhe o terminal — não o console do navegador. O log está lá.

Por que importa

Este componente não virou JavaScript enviado pra quem acessa. Zero bytes de bundle.

Esse console.log no terminal é o momento em que a ficha cai. Guarde a surpresa — a aula 3 explica o mecanismo inteiro.
