Ambiente, projeto e deploy ▲

Sua missão: ambiente montado, projeto Next.js rodando, duas rotas escritas por você e tudo publicado na Vercel. Curto de propósito — o objetivo é que ninguém chegue na aula 2 travado em instalação.

🎯

O objetivo

Provar que o seu ambiente está pronto pro semestre inteiro e que você entendeu o conceito da aula: o código do App Router roda no servidor por padrão. Um dos requisitos é justamente você achar a prova disso.

🚀

Por que deployar já na aula 1

Porque "na minha máquina funciona" some quando existe um link público. A partir de agora, todo problema é visível pra equipe inteira — e o preview de cada Pull Request vira a base do code review do projeto.

Passo a passo
01

Confira o Node e instale o pnpm

$ node -v v22.19.0 # precisa ser 20.9 ou maior $ corepack enable pnpm $ pnpm -v 10.x

Guarde os dois prints. Eles entram no README — e me ajudam a diagnosticar rápido se algo der errado com você.

02

Crie o projeto

$ pnpm create next-app@latest meu-primeiro-next

Respostas: TypeScript Yes · ESLint Yes · Tailwind Yes · App Router Yes · Turbopack Yes · alias @/* Yes.

Confira a versão que aparece ao subir: precisa ser Next.js 16.3 ou mais recente. Se vier 15 ou menos, seu pnpm pegou cache antigo — rode com @latest explícito.

03

Ache o servidor ⭐

Este passo vale mais que os outros: é o conceito da aula virando experiência.

Em app/page.tsx, ponha um console.log com uma mensagem sua. Salve, recarregue a página no navegador e procure onde a mensagem apareceu.

export default function Home() {
  console.log("[Nicoly] este log apareceu onde?");
  return <h1>Olá</h1>;
}

Registre no README onde a mensagem apareceu e escreva, com suas palavras, por que foi ali. Essa frase é o que eu vou ler primeiro na correção.

04

Duas rotas e navegação

  • Personalize a home (app/page.tsx) com o nome do seu projeto
  • Crie app/sobre/page.tsx contando quem é você e o que espera do semestre
  • Ligue as duas com <Link> do next/link
import Link from "next/link";

<Link href="/sobre">Sobre mim</Link>

Use <Link>, não <a>. Depois de navegar, volte e repare: com <a> a tela pisca; com <Link> não. Anote a diferença — a aula 2 explica.

05

Rode o build antes de subir

$ pnpm build

É exatamente o comando que a Vercel executa. Se passar aqui, passa lá.

Repare na tabela que o build imprime — ela mostra, rota por rota, se ficou estática (○) ou dinâmica (ƒ). É a teoria da aula aparecendo na saída do terminal. Cole essa tabela no README.

06

Publique na Vercel

  1. Suba num repositório público no GitHub
  2. vercel.com → Add New… → Project → importe
  3. Não mexa em configuração nenhuma → Deploy
  4. Cole o link no README e mande no grupo
07

Marco do projeto: forme a equipe

Este passo é da equipe, não individual.

  • Equipe de 3 a 4 pessoas, definida
  • Um repositório da equipe, com todo mundo como colaborador
  • Um README.md com os nomes e uma ideia inicial de tema — não precisa estar fechado

Sobre o tema: escolham algo que vocês usariam de verdade. Projeto que a própria equipe não quer usar costuma morrer no checkpoint 2. O briefing formal é na aula 2.

Requisitos mínimos
  • Node 20.9+ e pnpm funcionando, com os prints no README
  • Projeto em Next.js 16.3+, criado com create-next-app
  • Rota /sobre escrita por você, ligada à home por <Link>
  • No README: onde o console.log apareceu e por quê
  • No README: a tabela de rotas que o pnpm build imprime
  • pnpm build passando sem erro
  • Publicado na Vercel, com o link no README
  • Equipe formada, com repositório e ideia de tema
Extras, pra quem quiser ir além ✨
  • Uma terceira rota dinâmica: app/oi/[nome]/page.tsx que cumprimenta quem está na URL
  • Configure metadata no layout e veja o título mudar na aba
  • Compare o HTML: abra "ver código-fonte" e confira que o conteúdo está lá, antes do JavaScript rodar
  • Abra um Pull Request no seu próprio repo só pra ver o preview deployment nascer
  • Meça no Lighthouse e anote a nota inicial — vamos comparar na aula 12
O que NÃO pode 🚫
  • Usar npm em vez de pnpm (o pnpm-lock.yaml precisa estar no repo)
  • Pages Router — o curso inteiro é App Router
  • <a href> para navegação interna
  • Subir node_modules ou .next (o .gitignore gerado já cuida — confira se veio)
  • Repositório privado: ele é parte do seu portfólio

Como entregar
  1. Rode pnpm build e resolva o que aparecer
  2. Suba pro GitHub, em repositório público
  3. Publique na Vercel
  4. Mande no grupo: link do site + link do repositório
  5. Escreva uma frase sobre o que foi mais difícil — a gente revisa junto na aula 2
