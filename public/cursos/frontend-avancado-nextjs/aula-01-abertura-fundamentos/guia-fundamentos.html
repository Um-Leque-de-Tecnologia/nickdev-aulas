Fundamentos e setup

O modelo mental que organiza o curso inteiro — onde o seu código roda e quando ele renderiza — e o passo a passo pra deixar o ambiente pronto e o primeiro deploy no ar.

🎯 O que esta aula assume. JavaScript moderno, React com componentes e hooks, HTML e CSS, e Git no dia a dia. O que for específico do Next é ensinado do zero. Se algum pré-requisito estiver enferrujado, fale nesta semana — recuperar agora é muito mais fácil do que na aula 5.

O que mudou no React

Pra entender por que o Next existe do jeito que existe, ajuda ver as três eras do React como tentativas de resolver o mesmo problema: tirar trabalho do navegador de quem acessa.

EraModelo mentalO que doía
Classes
até 2018		ciclo de vida (componentDidMount)a lógica de uma feature ficava espalhada em três métodos
Hooks
2019–2022		estado e efeito dentro de funçõestudo rodava no navegador: bundle grande e dados sempre em useEffect
Server Components
2023 em diante		parte do componente roda no servidoré o assunto deste curso

A era dos hooks resolveu a organização do código, mas deixou uma conta aberta: a aplicação inteira precisava chegar no navegador antes de qualquer coisa aparecer.

SPA, SSR, SSG e ISR

Quatro estratégias, uma única variável: quando o HTML é gerado.

SiglaHTML geradoBoa paraCusto

O problema da SPA pura

Numa SPA, o servidor manda basicamente isto:

<body>
  <div id="root"></div>
  <script src="/bundle.js"></script>
</body>

Três consequências, e todas aparecem em produção:

  • Tela branca até o bundle baixar e executar — quem está no 4G sente
  • SEO sofre: o buscador recebe uma div vazia. Ele executa JavaScript, mas com atraso e sem garantia
  • Cascata de dados: renderiza → useEffect → busca → renderiza de novo. Sempre um passo atrás

A escolha é por rota, não por projeto

Aqui está a mudança que realmente importa, e a razão de o curso não ter "uma aula de SSR e outra de SSG".

❌ Como era antes

Você escolhia uma estratégia para o site inteiro. "Este projeto é SSR." E pronto — inclusive para as páginas que nunca mudam.

✅ Como é no App Router

A escolha é por rota. E, com Partial Prerendering, até por pedaço da mesma página.

Uma página de produto pode ter, ao mesmo tempo:

  • Cabeçalho e descrição estáticos — não mudam entre acessos
  • Preço e estoque revalidados a cada minuto
  • "Seus itens no carrinho" por requisição, porque é de cada pessoa
Por isso o eixo do curso é outro. Em vez de decorar siglas, você vai aprender duas perguntas: onde este código roda (servidor ou cliente — aula 3) e quando ele revalida (aula 4). As siglas são consequência das respostas.

Como decidir na prática

Duas perguntas, nesta ordem:

  1. Este conteúdo é igual para todo mundo? Se não for, precisa ser gerado por requisição.
  2. Com que frequência ele muda? Nunca → estático. De vez em quando → revalidação. A cada acesso → dinâmico.

Exercite

CasoRespostaPor quê
Página "sobre nós"SSGigual pra todos, muda uma vez por ano
Extrato bancárioSSRdiferente por pessoa e sempre atual
Home de e-commerceISRigual pra todos, muda quando entra promoção
Editor de textoCSRtudo acontece depois que a pessoa entra
O erro clássico: tornar tudo dinâmico "por segurança". Funciona, e é caro — você paga servidor a cada acesso pra entregar conteúdo que nunca muda. Estático é o padrão; dinâmico é a exceção que você justifica.

Node 20.9+

O Next.js 16 exige Node 20.9 ou mais novo. Confira:

$ node -v v22.19.0

Se aparecer menos que isso, ou "comando não encontrado", instale a versão LTS em nodejs.org e reabra o terminal.

Trabalha com vários projetos? Vale usar um gerenciador de versões — nvm (macOS/Linux) ou fnm (multiplataforma, mais rápido). Eles deixam cada projeto na sua versão de Node sem conflito.

pnpm

Este curso usa pnpm em vez de npm. O Node moderno já traz o Corepack, que instala pra você:

$ corepack enable pnpm $ pnpm -v 10.x

Por que pnpm

Aspectonpmpnpm
Discocada projeto tem sua cópia de cada pacoteuma cópia global, ligada por atalho
Instalação—bem mais rápida a partir da segunda vez
Rigorpermite usar pacote que você não declaroubloqueia — o que evita bug que só aparece em produção
Na prática, o que muda pra você: quase nada. npm install vira pnpm install, npm run dev vira pnpm dev. Com cinco projetos Next na máquina, a economia de disco passa de 1 GB — o que, como a gente vai ver, não é detalhe.

A regra do App Router

Pasta = rota. Arquivo page.tsx = a página. Não existe arquivo de configuração de rotas.

Você criaURL que nasce
app/page.tsx/
app/sobre/page.tsx/sobre
app/blog/[slug]/page.tsx/blog/qualquer-coisa
Pegadinha nº 1: criar app/sobre.tsx em vez de app/sobre/page.tsx. Sem o arquivo chamado exatamente page.tsx dentro da pasta, a rota não existe — e você toma 404 sem nenhum erro no terminal.

Os outros nomes reservados — layout, loading, error, not-found, template — são o assunto da aula 2.

layout e page

📄 app/layout.tsx
export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="pt-BR">
      <body>{children}</body>
    </html>
  );
}
  • O layout raiz é obrigatório e é o único lugar com <html> e <body>
  • Ao navegar entre rotas ele não é remontado — só o children troca
  • Por isso o cabeçalho não pisca, e o estado dele sobrevive à navegação
📄 app/page.tsx
export default function Home() {
  return <h1>Olá, mundo</h1>;
}

O primeiro Server Component

Você já escreveu um, sem saber. No App Router, todo componente é de servidor por padrão.

Faça este teste agora — é o momento em que a ficha cai:

export default function Home() {
  console.log("onde eu apareço?");
  return <h1>Olá, mundo</h1>;
}

Salve e procure a mensagem. Ela está no terminal onde o pnpm dev roda — não no console do navegador.

Por que isso importa

  • Esse componente não virou JavaScript enviado pra quem acessa — zero bytes de bundle
  • O navegador recebeu HTML pronto, então a primeira tela aparece rápido
  • Como roda no servidor, ele pode falar com banco de dados e usar chave secreta sem expor nada
Guarde a surpresa. O mecanismo inteiro — a fronteira "use client", o que atravessa e o que não atravessa — é a aula 3. Hoje basta você ter visto acontecer.

Deploy na Vercel

Vamos publicar na aula 1, antes de escrever a segunda linha de código. Não é enfeite: é o que transforma "na minha máquina funciona" num link que a equipe inteira vê.

  1. Rode pnpm build local. Passou? Ótimo — é o mesmo comando que a Vercel roda
  2. git push pro GitHub, em repositório público
  3. Em vercel.com → Add New… → Project → importe o repositório
  4. Não mexa em nenhuma configuração. A Vercel reconhece o Next sozinha
  5. Deploy

A partir daí, todo git push na branch principal republica. E cada Pull Request ganha um preview deployment com URL própria — o que vai ser essencial pro code review do projeto em equipe.

Rode pnpm build antes de dar push. É literalmente o que a Vercel executa. Erro de tipo que o dev tolera, o build reprova — e é bem mais rápido descobrir isso local.

Erros comuns 🔧

404 numa página que acabei de criar

O arquivo precisa se chamar exatamente page.tsx, dentro de uma pasta. app/sobre.tsx não vira rota.

Port 3000 is already in use

Tem outra execução rodando. Pare a anterior, ou use pnpm dev -p 3001.

You're importing a component that needs useState…

Faltou "use client" na primeira linha do arquivo. Assunto da aula 3 — por hoje, saiba que a mensagem é literal.

Module not found: Can't resolve '@/components/…'

Confira a maiúscula no nome do arquivo. No Windows funciona botao quando o arquivo é Botao; no servidor da Vercel (Linux) não. É um erro que só aparece no deploy.

O build passa local e falha na Vercel

Quase sempre uma destas três: diferença de maiúscula em import, variável de ambiente que existe só na sua máquina, ou versão de Node diferente.

Disco cheio

node_modules de um projeto Next passa de 500 MB. Com vários projetos, o disco enche rápido — e o sintoma costuma ser um erro que não fala nada de disco. É outra razão pra usar pnpm, que compartilha os pacotes.
