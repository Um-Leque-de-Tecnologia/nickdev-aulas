README.md
# Meu primeiro Next Projeto da aula 01 de Frontend Avançado com Next.js. 🔗 No ar: https://meu-primeiro-next-nicoly.vercel.app ## Ambiente $ node -v v22.19.0 $ pnpm -v 10.4.1 Next.js 16.3.0 ## Onde o console.log apareceu — e por quê Apareceu no terminal onde eu rodei `pnpm dev`, e NÃO no console do navegador (F12). Isso acontece porque no App Router todo componente é Server Component por padrão. O `app/page.tsx` foi executado no servidor: lá o `console.log` rodou, o componente virou HTML, e só o HTML foi enviado pro meu navegador. O JavaScript desse componente nunca chegou no cliente — por isso o navegador não tem como mostrar o log. Confirmei abrindo "ver código-fonte da página": o texto do <h1> já está no HTML, antes de qualquer JS rodar. ## Rotas | Rota | Arquivo | |----------|-----------------------| | / | app/page.tsx | | /sobre | app/sobre/page.tsx | ## Saída do build Route (app) ┌ ○ / ├ ○ /_not-found └ ○ /sobre ○ (Static) prerendered as static content As duas rotas ficaram estáticas porque não dependem de nada que mude por requisição. Eu não configurei isso — o Next deduziu sozinho. ## O que foi mais difícil Entender que o log ia pro terminal. Passei uns 10 minutos procurando no console do navegador antes de ler o guia.
🎯

Por que esse README pontua

Ele não descreve o que foi feito — descreve o que foi observado, com as palavras de quem escreveu. A frase "o JavaScript desse componente nunca chegou no cliente" mostra que o conceito foi entendido, não copiado. E a última seção, sobre a dificuldade, é honesta: isso vale mais do que fingir que foi tudo tranquilo.

Por que essa entrega funciona

Está no ar

O link abre, as duas rotas funcionam e a navegação não recarrega a página. É o requisito de maior peso.

Explica, não descreve

O README conta onde o log apareceu, por que e como isso foi confirmado — com o teste do código-fonte.

Higiene

node_modules e .next fora do repo, pnpm-lock.yaml dentro, build limpo.
