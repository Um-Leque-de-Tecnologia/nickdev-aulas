Aula 02 · código do desafio

O esqueleto, parte por parte

O desafio resolvido. Cada uma das quatro partes tem a mesma forma: um record, um @Repository, um @Service e um @RestController. A parte 1 está comentada linha por linha; as outras repetem o padrão, então o comentário fica só no que muda.

🧭

Tente antes de abrir isto

Esta é a referência de quando travar, não o ponto de partida. Copiar os quatro arquivos resolve hoje e cobra caro na aula 05, quando o repository virar banco e você precisar entender o que está mudando.

VagaService

Onde mora a decisão. Hoje ela é pequena — buscar por id é uma decisão simples — mas o lugar já está certo.

VagaService.java
package br.edu.faculdade.vagas;

import org.springframework.stereotype.Service;
import java.util.List;

@Service
public class VagaService {

    // O formato que se repete nas quatro partes:
    private final VagaRepository repositorio;   // 1. campo final

    public VagaService(VagaRepository repositorio) {  // 2. recebe no construtor
        this.repositorio = repositorio;             // 3. guarda
    }

    public List<Vaga> listar() {
        return repositorio.todas();
    }

    public List<Vaga> buscarPorId(String id) {
        return repositorio.todas().stream()
                .filter(v -> v.id().equals(id))
                .toList();
    }
}

Por que devolver lista em vez de uma vaga só? Porque ainda não temos como dizer "não achei" — isso é 404, e é a aula 03. Lista vazia é a resposta honesta enquanto isso. Devolver null seria a desonesta.

VagaController

Recebe o pedido e devolve a resposta. Cada método tem uma linha.

VagaController.java
package br.edu.faculdade.vagas;

import org.springframework.web.bind.annotation.*;
import java.util.List;

@RestController
public class VagaController {

    private final VagaService servico;   // o mesmo formato, segunda vez

    public VagaController(VagaService servico) {
        this.servico = servico;
    }

    @GetMapping("/vagas")
    public List<Vaga> listar() {
        return servico.listar();
    }

    @GetMapping("/vagas/{id}")
    public List<Vaga> porId(@PathVariable String id) {
        return servico.buscarPorId(id);
    }
}

Leia o método em voz alta: "devolve as vagas". Nenhum if, nenhum for, nenhum número solto. Se aparecer algum, é regra — e regra é do service.

@Service
public class EmpresaService {
    private final EmpresaRepository repositorio;

    public EmpresaService(EmpresaRepository repositorio) {
        this.repositorio = repositorio;
    }

    public List<Empresa> listar() { return repositorio.todas(); }

Parte 4 · Números do catálogo
parte 4

A única parte sem recurso próprio. Ela consulta o que a parte 1 guarda — e é por isso que a equipe precisou combinar o contrato antes.

EstatisticasService.java
package br.edu.faculdade.vagas;

import org.springframework.stereotype.Service;
import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;

@Service
public class EstatisticasService {

    // Recebe o REPOSITORY da parte 1, não o service dela.
    private final VagaRepository vagas;

    public EstatisticasService(VagaRepository vagas) {
        this.vagas = vagas;
    }

    public Map<String, Object> resumo() {
        List<Vaga> todas = vagas.todas();

        return Map.of(
            "totalDeVagas", todas.size(),

            "aceitamIniciante", todas.stream()
                .filter(Vaga::aceitaIniciante)
                .count(),

            "porArea", todas.stream()
                .collect(Collectors.groupingBy(Vaga::area, Collectors.counting())),

            "porSenioridade", todas.stream()
                .collect(Collectors.groupingBy(Vaga::senioridade, Collectors.counting()))
        );
    }
}
EstatisticasController.java
@RestController
public class EstatisticasController {
    private final EstatisticasService servico;

    public EstatisticasController(EstatisticasService servico) {
        this.servico = servico;
    }

    @GetMapping("/estatisticas")
    public Map<String, Object> resumo() {
        return servico.resumo();
    }
}

Por que o repository e não o VagaService? Porque estatística é uma regra, e regra não chama regra por preguiça — ela busca o dado e decide. No dia em que o VagaService.listar() passar a esconder vagas expiradas, a contagem não deve mudar junto sem alguém decidir isso.

Map.of aceita no máximo 10 pares. São quatro aqui, então cabe. Se a sua equipe quiser mais números, troque por new LinkedHashMap<>() — e de quebra a ordem das chaves passa a ser a que você escreveu.

O que a correção procura
sinalo que indica
✅ Quatro pessoas no git logO trabalho foi dividido de verdade. É a primeira coisa que eu olho.
✅ Todo campo de dependência é finalA injeção é por construtor. Dá pra ver rolando o arquivo.
✅ Nenhum controller com if ou forAs regras ficaram no service.
✅ Os slugs batem entre vagas e empresasA equipe combinou antes de codar, em vez de descobrir na integração.
✅ /estatisticas confere com /vagasAlguém contou na mão para verificar. Testar não é o mesmo que rodar.
❌ Um record anotado@Component num record é sinal de que a diferença entre dado e serviço não ficou clara.
❌ A parte 4 injetando VagaServiceFunciona, mas acopla a estatística a uma regra que não é dela.
❌ Um new entre classes da equipeA dependência não passou pelo contêiner. Costuma vir com "mas funcionou".
❌ Uma pessoa com todos os commitsA nota individual das outras três cai — e é isso que o desafio de quatro partes existe para evitar.
Se der errado

required a bean of type 'VagaRepository'
Faltou o @Repository, ou a classe está fora do pacote da Application. As duas causas do lab 4.

Ambiguous mapping ao subir
Duas pessoas mapearam a mesma rota. Acontece quando alguém cria um /vagas "só para testar" na própria parte. Combine as rotas — elas estão na tabela do desafio.

Map.of reclamando de tipo
Map.of infere o tipo dos valores, e aqui eles são mistos — número, contagem e mapa. Declare o retorno como Map<String, Object>.

/vagas/1 devolve []
O id da URL chega como texto. Se você comparou com == em vez de .equals(), nunca vai bater.

Os números não fecham
Conte na mão: as contagens por área e por senioridade têm que somar o total de vagas. Se não somam, alguém tem vaga com área escrita de dois jeitos — "Front-end" e "front-end" são chaves diferentes.
