O garçom

Anota o pedido e leva o prato. Não cozinha. Se o garçom cozinhar, ninguém troca o cardápio sem treinar garçom de novo.

A cozinha

É onde ficam as receitas — as regras. "Rápida é até 30 minutos" é decisão de cozinha, não de garçom.

A despensa

Guarda e entrega os ingredientes. Não decide o prato. Hoje é uma lista fixa; na aula 05 vira banco — e só ela muda.

A gente vai montar de baixo para cima: primeiro a despensa, depois a cozinha, por último o garçom. Assim a aplicação continua rodando a cada passo.

PASSO 1 DE 3

Como se escreve um Repository

ReceitaRepository.java
@Repository
public class ReceitaRepository {

    public List<Receita> todas() {
        return List.of(
            new Receita("Bolo de fubá", 40),
            new Receita("Omelete", 8));
    }
}
1O nome termina em Repository e a classe leva @Repository em cima.
2Ela só sabe onde o dado está. Hoje é uma lista escrita à mão; na aula 05 vira banco.
3Devolve o dado cru, do jeito que está. Não filtra, não ordena, não decide nada.

Repare que ela não tem construtor. É a única das três que não precisa de nada de ninguém — por isso a gente começa por ela.

PASSO 2 DE 3

Como se escreve um Service

CatalogoService.java
@Service
public class CatalogoService {

    private final ReceitaRepository repositorio;

    public CatalogoService(ReceitaRepository repositorio) {
        this.repositorio = repositorio;
    }

    public List<Receita> rapidas() {
        return repositorio.todas().stream()
                .filter(r -> r.minutos() <= 30)
                .toList();
    }
}
1O nome termina em Service e a classe leva @Service.
2Ela recebe o repository no construtor. O campo é final. Nunca new.
3É aqui que mora a decisão: filtrar, calcular, validar, ordenar.
o formato que se repete

A classe não constrói o que ela usa — ela recebe pronto, pelo construtor. Quem constrói é o Spring. É sempre assim, em toda classe do projeto, e daqui a pouco você vai escrever de novo.

LAB 2

Crie o seu service

~15 min

Crie a classe com @Service

Import: org.springframework.stereotype.Service.

Copie o formato do construtor

Campo private final, construtor recebendo o repository, this.x = x. Três linhas, sempre iguais.

Escreva um método com a sua regra

Uma regra do seu tema: discos de antes de 2000, plantas que precisam de sol, jogos com menos de 10 horas.

quando terminar

O seu service tem um campo final e um construtor? E dentro do método tem uma regra de verdade — algo que decide o que entra e o que não entra?

Não lembra o formato do construtor? Volte um slide. Copiar o formato é o esperado nesta aula — ele vira automático depois de escrever umas cinco vezes.

PASSO 3 DE 3

Como se escreve um Controller

ReceitaController.java
@RestController
public class ReceitaController {

    private final CatalogoService servico;

    public ReceitaController(CatalogoService servico) {
        this.servico = servico;
    }

    @GetMapping("/receitas/rapidas")
    public List<Receita> rapidas() {
        return servico.rapidas();
    }
}
1O nome termina em Controller e a classe leva @RestController.
2Recebe o service no construtor, campo final — o mesmo formato do slide anterior.
3O método tem uma linha: chama o service e devolve. Sem if, sem for, sem conta.

Leia o método em voz alta: "devolve as rápidas". É esse o trabalho do controller — traduzir um endereço numa chamada de método. Se aparecer um if aí dentro, ele é da cozinha.

Quando o Spring não acha

Este erro vai aparecer muitas vezes no semestre. Ele parece assustador e é o contrário: diz exatamente o que fazer.

APPLICATION FAILED TO START

Description:

Parameter 0 of constructor in br.edu.faculdade.receitas.ReceitaController
required a bean of type 'br.edu.faculdade.receitas.CatalogoService'
that could not be found.

Action:

Consider defining a bean of type 'br.edu.faculdade.receitas.CatalogoService'
in your configuration.

Quem pediu

ReceitaController, no construtor.

O que faltou

Uma classe CatalogoService que o Spring conheça.

As duas causas

Faltou a anotação em cima da classe, ou ela está fora do pacote da Application.

LAB 4

Quebre de propósito

~10 min

Provocar a falha agora, com calma, é melhor do que encontrá-la na véspera da entrega.

Apague o @Service da sua classe

Só a anotação. Rode.

Leia o erro inteiro

Ache as três partes: quem pediu, o que faltou, o que fazer.

Recoloque e confirme que volta

Rode de novo e veja subir.

Agora a outra causa

Com a anotação no lugar, mova a classe para um pacote fora do da Application. Mesmo erro — motivo diferente.

a habilidade de hoje

Sair daqui sabendo ler esse erro economiza mais tempo no semestre do que decorar qualquer anotação.

// antes de ir

O que fica de hoje

  • Repository — sabe onde o dado está. Devolve cru, não decide nada.
  • Service — é onde mora a regra. Recebe o repository no construtor.
  • Controller — recebe o pedido e devolve a resposta. Uma linha por método.
  • Toda classe recebe no construtor o que precisa, com o campo final. Nunca new.
  • O erro de bean não encontrado tem duas causas: faltou a anotação ou a classe está fora do pacote.
