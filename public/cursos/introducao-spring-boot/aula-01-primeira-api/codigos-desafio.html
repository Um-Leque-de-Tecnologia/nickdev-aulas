Estrutura

Onde cada arquivo vai

Tudo dentro do pacote da classe principal. É o que o @ComponentScan (embutido no @SpringBootApplication) consegue enxergar.

receitas/
├── pom.xml
└── src/main/
    ├── java/br/edu/faculdade/receitas/
    │   ├── ReceitasApplication.java     ← veio pronta do Initializr
    │   ├── Receita.java                 ← você cria
    │   └── ReceitaController.java       ← você cria
    └── resources/
        └── application.properties       ← você edita
Na aula 01, tudo no mesmo pacote — e está certo assim. Separar em model/, service/ e controller/ é o assunto da aula 02, quando aparecerem camadas de verdade. Organizar pastas antes de ter o que separar só cria confusão.

Esqueceu de marcar uma dependência no Initializr? Não precisa recriar o projeto: cole o bloco <dependency> aqui e mande Maven → Reload project. O site mvnrepository.com tem o bloco pronto de qualquer biblioteca.

ReceitasApplication.java

Esta você não escreve — veio pronta. Está aqui pra você reconhecer cada pedaço.

package br.edu.faculdade.receitas;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

// Três anotações em uma:
//  @SpringBootConfiguration → esta classe é fonte de configuração
//  @EnableAutoConfiguration → liga as regras "se... então..." do Boot
//  @ComponentScan           → varre ESTE pacote e os subpacotes
@SpringBootApplication
public class ReceitasApplication {

  public static void main(String[] args) {
    // "Spring, assume daqui: monte o contêiner e suba o servidor."
    SpringApplication.run(ReceitasApplication.class, args);
  }
}

Receita.java

O record é uma classe só de dados: imutável, com construtor, getters, equals, hashCode e toString gerados automaticamente.

br/edu/faculdade/receitas/Receita.java
package br.edu.faculdade.receitas;

// Escrever isto...
public record Receita(
    String nome,
    String categoria,
    int minutos,
    boolean vegetariana) { }

// ...equivale a uma classe com 4 campos final, construtor de 4
// parâmetros, 4 métodos de acesso, equals, hashCode e toString.

Como se usa

Receita r = new Receita("Bolo de fubá", "Doce", 50, true);

r.nome();        // "Bolo de fubá"   — repare: nome(), não getNome()
r.minutos();     // 50
// r.nome = "outro";  <-- não compila. Record é imutável.
Por que record e não classe normal aqui? Porque isto é um pacote de dados: não tem comportamento e não muda depois de criado. Quando o objeto precisar de regra de negócio, aí sim vira classe normal. Na aula 04 os records voltam com força, como DTOs.

ReceitaController.java

O coração do desafio. Três rotas, cada uma devolvendo um tipo diferente.

br/edu/faculdade/receitas/ReceitaController.java
package br.edu.faculdade.receitas;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;
import java.util.List;

// @RestController faz DUAS coisas:
//  1. "Spring, crie um objeto desta classe e guarde no contêiner"
//  2. "O retorno dos métodos é o CORPO da resposta HTTP"
@RestController
public class ReceitaController {

  // A "base de dados" de hoje: uma lista fixa em memória.
  // List.of() devolve lista IMUTÁVEL — perfeito, ninguém vai alterar.
  // Banco de dados de verdade é a aula 05.
  private final List<Receita> receitas = List.of(
      new Receita("Bolo de fubá",    "Doce",   50, true),
      new Receita("Strogonoff",     "Salgado",35, false),
      new Receita("Sopa de abóbora","Salgado",40, true),
      new Receita("Pudim",          "Doce",   70, true));

  // ─── Rota 1 ────────────────────────────────────────────────
  // GET /boas-vindas  →  devolve TEXTO puro
  @GetMapping("/boas-vindas")
  public String boasVindas() {
    return "API de receitas da Ana — no ar!";
  }

  // ─── Rota 2 ────────────────────────────────────────────────
  // GET /destaque  →  devolve UM OBJETO, que o Jackson vira JSON
  @GetMapping("/destaque")
  public Receita destaque() {
    return receitas.get(0);
  }

  // ─── Rota 3 ────────────────────────────────────────────────
  // GET /receitas  →  devolve uma LISTA, que vira array JSON
  @GetMapping("/receitas")
  public List<Receita> todas() {
    return receitas;
  }
}

Peça por peça

PeçaO que significa
@RestControllera classe vira bean e o retorno dos métodos vira corpo da resposta
@GetMapping("/x")"quando chegar GET /x, execute este método"
o nome do métodonão importa pro Spring. Quem define a rota é a anotação — o nome é só pra você
return "texto"vira text/plain com status 200
return objetovira application/json com status 200
return List<...>vira um array JSON [ ... ]
Procure o new ReceitaController() no projeto. Não existe. Você só colou a etiqueta @RestController e o Spring criou o objeto no start, guardou no contêiner e chamou o método na hora da requisição. Isso é inversão de controle — o conceito do slide, acontecendo no seu código.

Rota extra (opcional): /resumo

Para quem quer ir além. É revisão de stream() do curso de OO — e o formato exato do que vem na aula 03.

// Um record novo, só pra transportar os números da resposta
public record Resumo(int total, double mediaMinutos, long vegetarianas) { }
@GetMapping("/resumo")
public Resumo resumo() {

  double media = receitas.stream()
      .mapToInt(Receita::minutos)   // vira um fluxo de int
      .average()                     // devolve OptionalDouble
      .orElse(0);                   // se a lista for vazia, 0

  long veg = receitas.stream()
      .filter(Receita::vegetariana) // só as que passam no teste
      .count();

  return new Resumo(receitas.size(), media, veg);
}
GET /resumo {"total":4,"mediaMinutos":48.75,"vegetarianas":3}
Repare no Receita::minutos. É referência de método: um atalho para r -> r.minutos(). Como o record gera o método com o mesmo nome do campo, fica bem curtinho.

README.md

Modelo mínimo do que o desafio pede:

README.md
# API de Receitas

Primeira API REST da disciplina de Introdução ao Spring Boot.
Cataloga receitas com nome, categoria, tempo de preparo e se é vegetariana.

## Como rodar

Requer JDK 21.

```
./mvnw spring-boot:run
```

A aplicação sobe em `http://localhost:8081`.

## Rotas

| Método | Rota | Devolve |
|--------|------|---------|
| GET | `/boas-vindas` | texto de apresentação |
| GET | `/destaque`    | uma receita em JSON |
| GET | `/receitas`    | a lista completa em JSON |

## Respondendo às perguntas da aula

**Quem criou o objeto do controller?** O Spring, no start da aplicação. A
anotação `@RestController` avisou o contêiner de que essa classe deveria
virar um bean; nenhum `new` foi escrito por mim.

**Como o JSON foi gerado?** A biblioteca Jackson veio dentro do
`spring-boot-starter-web` e a autoconfiguração do Spring Boot a registrou
sozinha. Como ela estava disponível, o Spring a usou pra converter o
`record` em JSON.
