Desafio · Aula 01

Sua primeira API REST 🌱

Criar um projeto Spring Boot do zero, configurá-lo e publicar três endpoints que respondem no navegador — um em texto, um com um objeto e um com uma lista em JSON. O tema é seu.

🎯

O que este desafio verifica

Que você consegue sair do zero até uma API respondendo. Não tem pegadinha nem lógica difícil: o que está sendo testado é o caminho — criar, configurar, rodar, mapear uma rota e ver responder.

É a base de tudo que vem depois. Da aula 03 em diante, toda aula começa com "abra seu projeto e crie um controller". Se esse passo estiver automático, você acompanha o semestre inteiro tranquilo.

Por isso vale refazer até sair sem travar. Não é sobre decorar — é sobre o caminho ficar familiar.

📖

Travou numa palavra?

API, terminal, porta, rota, record, contêiner, bean, anotação — se alguma dessas aparecer aqui e você não lembrar o que é, o guia da aula tem um glossário com todas elas em uma linha cada. Consultar não é trapaça: é o que todo mundo que programa faz o dia inteiro.

🎨

O tema é seu

Na aula usei livros. Escolha algo que você teria vontade de catalogar: receitas, plantas, discos, jogos, filmes, exercícios de treino, trilhas de estudo. A estrutura é idêntica — e um tema que te interessa é um projeto que você termina.

Guarde essa escolha: ela não precisa ser o tema do projeto da disciplina (esse a equipe define na aula 03), mas pode ser.

Passo a passo
01

Prepare a máquina

Se ainda não fez, faça agora — antes de tentar criar o projeto.

  • JDK 21 instalado. Confira no terminal com java -version: tem que aparecer 21, não 17 nem 11.
  • IntelliJ IDEA Community instalado e abrindo.
Deu erro no java -version? Feche todos os terminais abertos e abra um novo — o terminal só lê a configuração do sistema quando inicia. O guia tem a seção "Conferir a instalação" com a tabela de cada mensagem possível.
02

Crie o projeto no Spring Initializr

Em start.spring.io (ou por File → New → Project → Spring Boot no IntelliJ), com exatamente estas escolhas:

CampoValor
ProjectMaven
LanguageJava
Spring Boota versão estável mais alta (sem SNAPSHOT nem M1)
Groupbr.edu.faculdade
Artifacto nome do seu tema, minúsculo e sem acento — ex.: receitas
PackagingJar
Java21
DependenciesSpring Web e Spring Boot DevTools — só essas duas
Ao descompactar, coloque numa pasta com caminho simples, sem acento e sem espaço. C:\dev\receitas funciona; C:\Users\Ana Júlia\Downloads\Nova pasta (2) costuma dar dor de cabeça.
03

Rode e confirme que subiu

Abra a pasta do projeto no IntelliJ (File → Open, selecionando a pasta que contém o pom.xml), espere o Maven baixar tudo e rode a classe ...Application no ▶ verde.

Tomcat started on port 8080 (http) Started ReceitasApplication in 1.842 seconds

Achou a linha Started? Então está no ar. A aplicação não vai terminar — ela fica esperando requisições, e isso está certo.

Ainda sem nenhuma rota, localhost:8080 mostra a Whitelabel Error Page com 404. Isso é bom sinal: significa que o servidor respondeu.
04

Configure o application.properties

Abra src/main/resources/application.properties e coloque duas configurações:

# o nome da sua aplicação — troque pelo seu tema
spring.application.name=receitas

# mude a porta: você escolhe qualquer uma entre 8081 e 8099
server.port=8081

Reinicie a aplicação e confira no log que a porta mudou. A partir daqui, todas as suas URLs usam a sua porta.

Por que isso está no desafio: pra você provar que conseguiu discordar do padrão do Spring Boot. Esse arquivo vai ser usado o semestre inteiro — banco de dados, segurança e deploy passam todos por ele.
05

Crie o record do seu tema

No mesmo pacote da classe Application, crie um record com três a cinco campos. Exemplo com receitas:

package br.edu.faculdade.receitas;

public record Receita(
    String nome,
    String categoria,
    int minutos,
    boolean vegetariana) { }
⚠️ Mesmo pacote, sempre. Se você criar a classe fora do pacote da Application, o Spring não a enxerga e você vai passar meia hora tomando 404 sem entender por quê.
06

Crie o controller com três rotas

Ainda no mesmo pacote, crie uma classe terminada em Controller e escreva as três rotas:

#RotaDevolve
1GET /boas-vindasum texto apresentando sua API
2GET /destaqueum objeto do seu record → vira JSON
3GET /receitas (use o plural do seu tema)uma lista com pelo menos 4 itens → vira array JSON
@RestController
public class ReceitaController {

  @GetMapping("/boas-vindas")
  public String boasVindas() {
    return "API de receitas da Ana — no ar!";
  }

  // ...e as outras duas, seguindo o mesmo padrão
}
Não copie o código pronto do "Código do desafio". Escreva, erre, leia o erro, conserte. O objetivo aqui não é ter o arquivo certo na pasta — é você conseguir escrever de novo na aula que vem.
07

Teste as três rotas

No navegador ou pelo terminal, usando a sua porta:

$ curl http://localhost:8081/boas-vindas API de receitas da Ana — no ar! $ curl -i http://localhost:8081/receitas HTTP/1.1 200 Content-Type: application/json [{"nome":"Bolo de fubá","categoria":"Doce","minutos":50,"vegetariana":true}, ...]

Confira duas coisas na resposta das rotas 2 e 3: veio 200 e veio Content-Type: application/json.

08

Publique no GitHub

Crie um repositório público e suba o projeto. No README.md, escreva:

  1. o tema da sua API, em uma frase;
  2. como rodar (o comando e a porta que você escolheu);
  3. a lista das três rotas, com o que cada uma devolve;
  4. um print de cada rota respondendo no navegador.
O .gitignore já veio pronto no projeto do Initializr — ele impede que a pasta target/ vá pro repositório. Se aparecerem centenas de arquivos no commit, é sinal de que algo está errado: confira se o .gitignore está na raiz.
Antes de entregar
  • Java 21 e apenas Spring Web + DevTools como dependências
  • A aplicação sobe e o log mostra Started ... in X seconds
  • application.properties com nome e porta alterados
  • Um record com 3 a 5 campos, no mesmo pacote da Application
  • Rota 1 devolvendo texto
  • Rota 2 devolvendo um objeto em JSON
  • Rota 3 devolvendo uma lista com 4+ itens em JSON
  • Repositório público no GitHub com README e prints
Quer ir além (opcional)
  • Uma quarta rota /resumo que devolve um objeto com números calculados a partir da sua lista: total de itens, média de um campo numérico, quantidade que atende a alguma condição. Use stream() — é revisão de OO e cai na aula 03.
  • Um arquivo requisicoes.http na raiz do projeto com as requisições prontas, versionado junto com o código.
  • Configurar server.servlet.context-path=/api e ajustar as URLs do README de acordo.
O que ainda NÃO é pra fazer
  • Banco de dados — a lista fica fixa no código mesmo. Persistência é a aula 05.
  • POST, PUT ou DELETE — só GET hoje. Os outros verbos são a aula 03.
  • Camada de service e injeção de dependência no código — o conceito foi hoje, a prática é a aula 02.
  • Validação, tratamento de erro ou login — aulas 04, 10 e 11.
🧠

Duas perguntas pra responder no README

Valem tanto quanto o código, e caem em conversa de correção:

1. Em nenhum lugar do seu projeto existe new ReceitaController(). Então quem criou esse objeto, e quando?

2. Você não escreveu uma linha convertendo objeto em JSON. Como o Spring soube fazer isso sozinho?

Entrega
  1. Prazo: até a aula 02, em 18/08.
  2. Formato: link do repositório público no GitHub.
  3. Individual. As equipes só se formam na aula 02 — este desafio é seu.
  4. Travou? Mande o print do erro com a mensagem completa antes da aula. Erro de setup é rápido de resolver à distância; deixar pra resolver na aula custa metade do seu dia 02.
